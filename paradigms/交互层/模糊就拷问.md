# 维护者的表述能读出几种做法

**现行做法**:选错要返工的模糊,当场停下来分轮拷问,任务开头、做到一半、收到反馈时都一样。一轮问完前提已定、互不依赖的决策(前沿),每问附推荐;回「好」采纳本轮推荐,「按推荐收」则剩下的全取推荐。事实 agent 自己查或派子 agent 查,只问只有维护者能定的决策;纸上说不清的先做一次性原型再问。选错也不费事的小模糊取默认,在回复里写一句。前沿问空后把共识整理成意图卡、方案或任务书,确认一次再开工。

**原则**:模型再强也猜不出只有人知道的取舍;把决策按依赖顺序问在动手之前,比做到一半返工便宜,而事实永远不该拿来问人。

**Claude 与 Codex**:相同。两边都从用户级常驻指令读到「何时问」,从同一份 grilling skill 读到「怎么问」。Claude Code 的云端会话读不到用户级目录,但那里没有人可问。

**本仓库落实在**:`global/AGENTS.md`、`global/skills/grilling/`、`AGENTS.md` 意图卡的「待定」行

**待核**:下一次系统线或开源贡献选方向时核两件事:几轮问完(目标 3 轮以内),以及实施中还有没有冒出本该在拷问时问的决策。
