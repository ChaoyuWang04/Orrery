# 给 AI infra 开源项目做性能与正确性工作

**现行做法**:先读项目自带的 skill、守则与开发指南,它们优先;通用方法从工具包 `oss-*` 取。测量由轻到重(计时 → nsys → ncu),先测噪声底再做前后对比,前后交替跑;一次只改一处,并证明改动真的生效了;阈值事先声明,数字只来自工具输出,证据分级。数值正确性的阈值从高精度参照的误差推出来。交付前让全新上下文的子 agent 盲审完整 diff,查测试与容差没被放宽。上游资料缺 5090(sm_120)的,按实测补,测不了的写明。

**原则**:性能与正确性的结论只和测量纪律一样可信;把纪律写成两边共用的 skill,每次贡献都从同一个起点出发,项目自己的规矩永远压过通用做法。

**Claude 与 Codex**:相同。工具包经目录软链接接到实验仓的 `lab` 分支,两边读同一份;上游只放在一侧的 skill,接线脚本在另一侧补上链接。

**本仓库落实在**:`~/1Project/oss/_kit/skills/`(清单与写法见其 README,上游 skill 索引见 CATALOG)、`~/1Project/oss/_kit/wire-skills.sh`、`docs/14-开源贡献.md` 第一、三、七节

**待核**:第一个用上工具包的真实贡献里核两件事:结论被评审或实测推翻的次数,以及交付后因证据不足返工的次数。
