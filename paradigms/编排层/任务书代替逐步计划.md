# 交给 agent 一件多步的活

**现行做法**:写一页任务书,写给维护者看——目标、做到什么算完、证据怎么拿、边界、已知的未知。里面的决策先[拷问](../交互层/模糊就拷问.md)到共识,维护者看过一次就开工,执行步骤由 agent 自己规划、自己验证。不走 brainstorm → spec → plan → 逐步执行的仪式。拷问、任务书、实施尽量在同一个会话里,换一次上下文,原始问答就只剩摘要。只有要跨会话或跨 agent 交接时才拆开写:按纵切片拆,每片端到端能单独验证、一个新会话装得下,标明被哪几片挡着,而不是按层写步骤。

**原则**:对齐的是意图与验收,不是步骤;模型规划得动的东西写成文档,只多花 token、多一次打断。

**Claude 与 Codex**:相同。用户级不再装流程仪式类 skill(如 superpowers),以免它们在仓库守则之外强插步骤。
