# Kimi Linear：线性注意力想赢全注意力，先学会按通道遗忘

<!-- release-date: 2025-10-30 -->

> 本文依据 Kimi Team 的 **Kimi Linear: An Expressive, Efficient Attention Architecture**（Technical Report of Kimi Linear），arXiv:2510.26692v2，2025-11-01，共 28 页：正文与参考文献到 p. 23，附录 A–D 在 p. 24–28。页码均指这份 PDF 自身的页码。文中区分三件事：**报告明确写了什么**、**我们怎么解释它**、**哪些是外部资料或本文推算**。

## 读前先把几个词说成人话

这篇报告的难点不在公式多，而在它同时改了三处：记忆怎么擦、kernel 怎么算、层怎么混。先把反复出现的词说清楚。

- **Token（词元）**：模型读写文本的最小单位。
- **Softmax 注意力 / 全注意力（full attention）**：每个新 Token 都和之前所有 Token 逐个比一遍。长度翻倍，计算量约翻四倍。
- **KV cache（键值缓存）**：解码时把每个历史 Token 的 key 和 value 存下来，下一步直接读。它随上下文线性变大，长上下文解码的瓶颈往往是「读这块缓存」而不是算。
- **Prefill / 解码（decode）**：prefill 是一次性读完整段输入；解码是一个 Token 一个 Token 往外吐。**TPOT（Time Per Output Token）** 是解码时每吐一个 Token 的耗时。
- **线性注意力（linear attention）**：不存全部历史，而是把历史压进一个固定大小的矩阵「记忆状态」$S_t$。每来一个 Token 更新一次，代价不随长度增长。
- **Delta rule（增量规则）**：写入新联想前，先把记忆里同一个 key 下的旧值修正掉，而不是简单叠加。
- **遗忘门 / 衰减（gate / decay）**：每一步让旧记忆按一定比例褪色。
- **GDN（Gated DeltaNet，门控增量网络）**：delta rule 加一个「每个头一个数」的遗忘门，是本文的直接前作。
- **KDA（Kimi Delta Attention）**：本文的新模块。把 GDN 的遗忘门细到「每个 key 通道一个数」。
- **MLA（Multi-Head Latent Attention，多头潜在注意力）**：DeepSeek 提出的全注意力变体，把 KV 压进低维潜向量再存，见站内 DeepSeek-V2 一篇。本文用它当全注意力层和对照基线。
- **混合架构（hybrid）**：大部分层用便宜的线性注意力，少数层保留全注意力。
- **NoPE（No Position Encoding）**：不加任何显式位置编码，比如不用 RoPE（旋转位置编码）。
- **Chunkwise（分块并行）**：训练时把序列切成长度 $C$ 的块，块内用矩阵乘并行，块间传递状态。
- **DPLR（Diagonal-Plus-Low-Rank，对角加低秩）**：一类状态转移矩阵的写法 $D - a b^{\top}$，表达力强但算得慢。

## 一句话先说清

全注意力贵在两处：prefill 的计算随长度平方涨，解码的 KV cache 随长度线性涨。线性注意力把历史压成固定大小的状态，两处都便宜，但一直有个老毛病：**状态有限，擦得太粗**。旧联想要么不擦，要么整块一起褪色，长了就记混、找不回来（PDF p. 2）。

Kimi Linear 的回答分三层（PDF p. 2）：

1. **KDA**：在 GDN 的 delta rule 上，把「一个头一个遗忘率」换成「每个 key 通道一个遗忘率」，让有限记忆可以分工；
2. **受限 DPLR 的 chunkwise 算法**：把这种细粒度衰减写成一个特殊的 DPLR，并让它的两个低秩向量都绑到 $k$ 上，kernel 因此比通用 DPLR 快约一倍；
3. **3:1 层间混合**：每 3 层 KDA 配 1 层 MLA，MLA 层不加位置编码，位置信息全交给 KDA。

报告的主张写得很满：在同一套 1.4T Token 配方下，这个 48B 总参、3B 激活的混合模型在短上下文、长上下文和 RL 三种场景都超过全 MLA，KV cache 最多省 75%，1M 上下文下解码吞吐最高约 6 倍（PDF p. 1）。

读完全文，这句话需要三处收窄：「全面超过」有例外格；「6 倍」是放大 batch 之后的解码吞吐，单请求延迟只有约 2.2 倍；公开的 5.7T 发布版和 Moonlight 比，不是同一场公平赛。下面逐一讲。

## 主要矛盾：固定大小的记忆，擦得太粗

### 线性注意力把历史写成一块「快权重」

先看一个注意力头。线性注意力维护一个 $d_k \times d_v$ 的矩阵 $S_t$，每来一个 Token 就把「key → value」的联想加进去，读的时候用 query 去查（PDF p. 3）：

$$
S_t = S_{t-1} + k_t v_t^{\top}, \qquad o_t = S_t^{\top} q_t
$$

$S_t$ 大小固定，所以不管上下文多长，每步只做一次固定大小的矩阵运算，也不需要 KV cache。报告借「快权重」的视角解读它：$S_t$ 是一块在推理时被在线改写的联想记忆，这条更新等于对目标 $-\langle S^{\top} k_t, v_t \rangle$ 做梯度下降，只会不断强化最近的联想，**没有任何「该擦哪条」的判据**，状态无界增长，长了就相互干扰（PDF p. 3）。

### DeltaNet：写之前先修正

DeltaNet 把目标换成重建误差 $\frac{1}{2}\lVert S^{\top} k_t - v_t \rVert^2$，走一步梯度下降（学习率 $\beta_t$）得到（PDF p. 3）：

$$
S_t = (I - \beta_t k_t k_t^{\top})\, S_{t-1} + \beta_t k_t v_t^{\top}
$$

人话版：先用 $k_t$ 去查记忆，看它现在记成了什么；把这个方向上的旧值擦掉 $\beta_t$ 份，再写入新的 $v_t$。这就是经典 delta rule。它的更新是秩 1 的，等价于广义 Householder 变换，有现成的分块并行算法（PDF p. 3）。

### GDN：再加一个标量遗忘门

DeltaNet 仍然会无限期留着过时的联想。GDN 乘上一个标量遗忘门 $\alpha_t \in [0, 1]$（PDF p. 3）：

$$
S_t = \alpha_t (I - \beta_t k_t k_t^{\top})\, S_{t-1} + \beta_t k_t v_t^{\top}
$$

报告把 $\alpha_t$ 读成对快权重的权重衰减，相当于数据相关的 L2 正则；还把它读成一种可学习、数据相关的乘性位置编码，放宽了 RoPE 的正交约束（PDF p. 3）。

问题在于这个 $\alpha_t$ **一个头只有一个数**。整块记忆只能按同一速度褪色：想留住长程信息就得整头慢忘，想及时清掉近邻噪声就得整头快忘。GDN 和 Mamba2 都是这种粗粒度的头级门（PDF p. 2）。

于是矛盾变成：

> 状态大小是写死的。要在有限容量里同时记住长程事实和近处细节，遗忘必须能分工；而分工一细，现有的高效 kernel 又算不动。KDA 要同时解开这两头。

## 先看全景：一层怎么搭，整机怎么混

![Kimi Linear 的整机由 3 层 KDA 加 1 层不加位置编码的 MLA 组成一组反复堆叠，每层后接 MoE；右侧标出 KDA 内部 q、k、v、α、β 五路输入与输出门。](/reports/Kimi-Linear/figure3-kimi-linear.svg)

骨架沿用 Moonlight（PDF p. 5，见站内 Muon-is-Scalable-for-LLM-Training 一篇）。图里有三件事是后文的主角：KDA 内部的五路输入，3:1 的层间排布，以及 MLA 层的 NoPE。

KDA 每个头的输入这样算（PDF p. 5）：

- $q, k$：线性投影 → 短卷积（ShortConv）→ Swish → L2 归一化。L2 归一化是为了让转移矩阵的特征值稳定；
- $v$：线性投影 → 短卷积 → Swish；
- $\alpha_t \in [0, 1]^{d_k}$：先过一对低秩投影（秩等于头维），再过一个类似 GDN / Mamba 的衰减函数 $f(\cdot)$；
- $\beta_t \in [0, 1]$：线性投影后接 Sigmoid。

$d_k$ 和 $d_v$ 在全部实验里都是 128（PDF p. 5）。输出端先做按头的 RMSNorm，再乘一个数据相关的 Sigmoid 输出门，最后过 $W_o$（PDF p. 6，式 10）：

$$
o_t = W_o \Bigl( \mathrm{Sigmoid}\bigl(W_g^{\uparrow} W_g^{\downarrow} x_t\bigr) \odot \mathrm{RMSNorm}\bigl(\mathrm{KDA}(q_t, k_t, v_t, \alpha_t, \beta_t)\bigr) \Bigr)
$$

输出门也用低秩参数化，报告给的理由是参数对照公平，效果与全秩门相当，还能缓解 Attention Sink（PDF p. 6）。

整机层面，1.4T 对照用的配置是：MoE 稀疏度提到 32，每 Token 从 256 个专家里激活 8 个（含 1 个共享专家），总参 48B、激活 3B；第一层是不带 MoE 的 dense 层，理由是训练稳定（PDF p. 9）。层数、隐藏维和 MLA 的维度，正文没有给。

## 核心设计一：KDA 把遗忘从「一头一个数」细到「一通道一个数」

![三格对比：线性注意力的记忆状态全部保留，GDN 的整块状态按同一比例褪色，KDA 的每一行即每个 key 通道各有自己的保留比例；下方按顺序画出一步更新的衰减、delta 修正和写入。](/reports/Kimi-Linear/figure-kda-gates.svg)

### 新设计：把标量 $\alpha_t$ 换成对角矩阵

KDA 的一步更新是（PDF p. 4，式 1）：

$$
S_t = \bigl(I - \beta_t k_t k_t^{\top}\bigr)\, \mathrm{Diag}(\alpha_t)\, S_{t-1} + \beta_t k_t v_t^{\top}, \qquad o_t = S_t^{\top} q_t
$$

和 GDN 只差一处：标量 $\alpha_t$ 变成了对角矩阵 $\mathrm{Diag}(\alpha_t)$，$\alpha_t$ 是长 $d_k$ 的向量。它左乘 $S_{t-1}$，等于给状态的每一行、也就是每个 key 通道，各乘一个自己的保留比例。上图下排就是这条式子的执行顺序：先按通道衰减，再沿 $k_t$ 方向做 delta 修正，最后写入新联想。

这种通道级遗忘不是新发明。GLA（Gated Linear Attention）早就用对角门控，只是没有 delta rule（PDF p. 2、16）。KDA 的位置是把 GLA 的细门控和 GDN 的 delta rule 合到一起。报告在 Table 7（PDF p. 16）用「测试时训练」的视角把一串方法排成表：从线性注意力、RetNet、Mamba2、GLA，到 DeltaNet、GDN、KDA，差别都落在状态怎么衰减、目标函数是什么。

### 为什么要细到通道：报告自己的两条理由

第一条是记忆管理。细粒度衰减让模型能有选择地忘掉无关信息、更精确地留住关键记忆（PDF p. 8）。

第二条来自位置编码的类比（PDF p. 13–14，§6.1）。RoPE 可以写成 $q_t^{\top} \bigl(\prod_{j=i+1}^{t} R_j\bigr) k_i$ 的累乘形式，它的强项是给每一对维度分配不同的旋转频率，沿特征维做了类似非均匀傅里叶变换的分工。GDN 的累乘转移矩阵 $\prod \alpha_j (I - \beta_j k_j k_j^{\top})$ 形式相同，但每头只有一个标量衰减，缺了这种「逐维不同」的多样性。报告说，这正是提出通道级门控的动机（PDF p. 14）。

**我们怎么解释它**：可以把每个 key 通道想成一条带宽不同的时间滤波器。$\alpha$ 接近 1 的通道是长程记忆，接近 0 的通道只看最近几步。同一个头里同时有快有慢，有限的 $128 \times 128$ 状态就不必在「记长」和「记准」之间二选一。这是解释，报告没有做通道级的可视化或统计。

### 收益与代价

收益在后面的合成任务和 1.4T 对照里兑现。代价有两层：

- **算力**：细粒度衰减让 chunkwise 计算里出现逐通道的累计衰减相除，半精度下数值不稳，通用解法很慢。这是下一节要解决的；
- **边界**：KDA 仍是固定大小状态。它改善的是有限记忆怎么用，不改变「压缩就会丢」这个上限。所以整机仍要保留全注意力层做精确检索（PDF p. 6）。

### 可迁移启发

有限容量的记忆，遗忘粒度要和冲突粒度对齐。一个头里的信息寿命长短不一，就不该共用一个衰减率。这条不只适用于线性注意力：KV 压缩、缓存淘汰、带衰减的在线统计，都可以先问一句「我的遗忘是整块的，还是分通道的」。

## 核心设计二：受限 DPLR，让细门控跑得动

![左侧通用 DPLR 在块内要算 4 个含累计衰减倒数的矩阵，右侧 KDA 把 a、b 都绑到 k 上后只剩 2 个，另外两份省掉；底部说明 Figure 2 中 KDA kernel 耗时约为 DPLR 的一半。](/reports/Kimi-Linear/figure-kda-dplr.svg)

### 旧问题：细粒度衰减 + 分块并行 = 数值麻烦

GPU 喜欢大矩阵乘，不喜欢逐 Token 串行递推。所以训练和 prefill 都用分块算法：块内并行，块间传状态。标量衰减可以提到矩阵乘外面；逐通道衰减做不到，块内计算里会出现逐通道的累计衰减相除（式 9 里的 $1/\Gamma$）。半精度下这种除法会失真。GLA 的做法是转到对数域、再加一层全精度的二级分块，代价是用不满半精度矩阵乘，算子明显变慢（PDF p. 5）。

更一般的写法是 DPLR：$S_t = (D - a_t b_t^{\top}) S_{t-1} + k_t v_t^{\top}$。它表达力强，但计算量大、难并行（PDF p. 14）。

### 新设计：DPLR 的一个特例

把式 (1) 展开，KDA 恰好是一个受限的 DPLR（PDF p. 14）：

$$
D = \mathrm{Diag}(\alpha_t), \qquad a_t = \beta_t k_t, \qquad b_t = k_t \odot \alpha_t
$$

$a$ 和 $b$ 不再是两组独立向量，都由 $k$ 决定；$\alpha_t$ 又是共享的，可以像式 (1) 那样提出来。于是块内要特殊处理的 $C \times C$ 矩阵从 4 个减到 2 个，块间与输出阶段再省约 3 次矩阵乘（PDF p. 5、15）。

### 工作机制：块间递推，块内打包

分块算法的骨架是这样（PDF p. 4–5，式 2–9）：

- 一个块内连乘的秩 1 更新，用 **WY 表示** 打包成紧凑形式，写法跟随 Comba，省掉一次额外的矩阵求逆；
- 用 **UT 变换** 把剩下的逐行递推收成一次下三角矩阵求逆，减少非矩阵乘的运算，下三角求逆用前代法逐行完成；
- 块与块之间只传一个状态 $S_{[t]}$，块内用矩阵乘并行：输出 = 块间项 + 块内项，块内项作用在一个「伪 value」$U_{[t]} - W_{[t]} S_{[t]}$ 上。

附录 B 给了 WY 表示的归纳证明（PDF p. 25–26），附录 C 给了完整的 PyTorch 风格伪代码，块长默认 64，块内仍保留一处二级分块以求数值稳定（PDF p. 27）。

### 收益

Figure 2（PDF p. 5）在 batch 1、16 头下比较两种 kernel：输入 2K–64K 时，KDA 的耗时约为通用 DPLR 的一半。报告文字写作「算子效率约提升 100%」「64K 以内接近 2 倍」（PDF p. 5、15）。

### 复杂度：KDA 的每 Token 成本不随长度涨

报告给了单头、块长 $C = 64$ 时的理论 FLOPs（PDF p. 15，式 13–14）：

$$
\mathrm{FLOPs}_{\mathrm{KDA}}(T; C, d_h) = 6 T d_h^2 + 3 T C d_h + T C^2, \qquad \mathrm{FLOPs}_{\mathrm{Attn}}(T; d_h) = 2 T^2 d_h
$$

**本文推算**：取 $d_h = 128$，KDA 每 Token 约 $1.27 \times 10^5$ 次运算，是常数；全注意力每 Token 平均约 $256\,T$。两者在 $T \approx 500$ 时持平，到 128K 时全注意力约是 KDA 的 260 倍。这只比两条式子的主项，不含投影层与 MoE。它解释了一件事：混合模型里剩下的 1/4 MLA 层仍是平方项，整机 prefill 的加速会被这 1/4 层卡住，不会像单层对比那样悬殊。

### 可迁移启发

想用更强的表达形式，先找它的一个「受限特例」：约束要和旧规则一致（这里是经典 delta rule 的形状），同时恰好砍掉硬件上的慢路径。KDA 没有追求通用 DPLR 的全部表达力，换来的是半精度矩阵乘跑得满。

## 核心设计三：3:1 层间混合，MLA 层不要位置编码

### 旧问题：纯线性过不了检索，纯全注意力太贵

固定大小的状态做不到精确检索和整段复制，这是线性注意力的理论天花板（PDF p. 2、18）。混合架构是公认的折中，但此前的混合模型要么规模有限，要么评测不全（PDF p. 2）。

### 新设计：整层交替，不在层内混头

混合有两种做法：层内混（同一层里一部分头是线性、一部分是全注意力），或层间混（整层交替）。Kimi Linear 选层间，理由是基础设施简单、训练稳定（PDF p. 6）。层内混合的异构计算路径会让分布式并行这类优化变复杂（PDF p. 18）。比例由消融定为 3:1。

Table 1（PDF p. 8）的消融规模是缩放实验里最小那一档（16 头、16 层），同 FLOPs 预算、同超参。验证集取自一个和预训练分布差别很大的高质量数据集，所以验证困惑度更看泛化（PDF p. 8）。

| 设置 | 训练 PPL（↓） | 验证 PPL（↓） |
|---|---:|---:|
| **3:1（最终采用）** | 9.23 | 5.65 |
| 0:1（纯全注意力） | 9.45 | 5.77 |
| 1:1 | 9.29 | 5.66 |
| 7:1 | 9.23 | 5.70 |
| 15:1 | 9.34 | 5.82 |
| 去掉输出门 | 9.25 | 5.67 |
| Swish 输出门 | 9.43 | 5.81 |
| 去掉短卷积 | 9.29 | 5.70 |

读表要知道三件事（PDF p. 8）：

- **比例**：7:1 训练困惑度和 3:1 一样，验证明显变差；1:1 验证差不多，但推理开销更高；纯全注意力 0:1 两项都差。3:1 是在验证集和推理成本之间选出来的，不是「线性层越多越好」；
- **输出门**：去掉会变差；换成 GDN 原文用的 Swish 门明显更差，所以包括 GDN-H 对照在内全部用 Sigmoid 门；
- **短卷积**：在混合模型里仍有不可忽略的作用。

### NoPE：让 KDA 独自管位置

Kimi Linear 的全部 MLA 层都不加位置编码，位置信息和「越近越重要」的偏置全交给 KDA（PDF p. 6）。依据是上一节的类比：GDN 类的转移矩阵本身就是一种数据相关的乘性位置编码。

报告给了两条工程好处（PDF p. 7）：NoPE 的 MLA 在推理时可以化成高效的纯 MQA；长上下文训练不必调 RoPE 的基频，也不用 YaRN 这类外推方法。

为了验证，作者另训了一个 MLA 层带 RoPE 的版本 Kimi Linear (RoPE)。它在短上下文上分数接近，长上下文明显落后（PDF p. 8、12）。报告的解释是：带 RoPE 时，全局层携带强而显式的相对位置信号，线性层只有弱而隐式的位置偏置，两者失衡，模型过分偏向短程顺序，到中训扩展上下文时就不够灵活；NoPE 让位置偏置在各层间分布得更均衡（PDF p. 8–9）。这是作者的推测，报告没有专门做实验拆开它。

### 可迁移启发

- 混合比例是用「验证集 + 推理成本」两把尺子一起选的，别只盯训练 loss；
- 位置信息不要两套系统各写各的。已经有一个天然带位置感的算子时，让全局层专心按内容检索，长上下文扩展会省掉一整套 RoPE 调参。

## 1.4T 公平对照：短上下文、长上下文、RL

### 对照口径

三个主角是全 MLA、混合 GDN（GDN-H）和 Kimi Linear，外加 Kimi Linear (RoPE)。四者同架构、同参数量、同训练配置（PDF p. 9）。

预训练配方（PDF p. 10）：上下文 4096，MuonClip 优化器，WSD 学习率调度，从 Kimi K2 预训练语料里采 1.4T Token，学习率 $1.1 \times 10^{-3}$，全局 batch 固定 32M Token；退火和长上下文激活阶段照搬 K2。数据配比与长上下文阶段的具体长度，正文没有展开，只指回 K2（见站内 Kimi-K2 一篇）。

评测口径（PDF p. 10）：温度一律 1.0；高方差项报 Avg@k；base 模型的 MMLU、MMLU-Redux、GPQA-Diamond、C-Eval 用困惑度打分，其余用生成打分；GPQA-Diamond 取 8 次独立运行的均值；框架是基于 LM-Harness 的内部版本。

后训练配方（PDF p. 10–11）：SFT 数据在 K2 的 SFT 数据上加了更多推理任务，先做通用指令，再有计划地加推理密集数据。RL 的 prompt 来自数学、代码、STEM，事先按起始 checkpoint 筛出中等难度；为防通用能力退化，RL 期间同时加 PTX 损失（在高质量数据上并行做 SFT）。算法沿用 K1.5，外加三招：截断重要性采样，缓解训练引擎和推理引擎精度不一致导致的策略失配；动态调 KL 惩罚；动态调 mini batch 大小，防熵塌缩。

## 效率：75%、6 倍和 2.2 倍，不是同一件事

![三组倍数柱：prefill 在 512K 和 1M 时约 2.3 倍与 2.9 倍；batch 1 解码在 512K 和 1M 时约 1.8 倍与 2.2 倍；放大 batch 的解码在 256K、512K、1M 时约 4.8、5.7、6.3 倍。](/reports/Kimi-Linear/figure7-speedup.svg)

先说 KV cache。**本文推算**：3:1 意味着每 4 层只有 1 层存随长度增长的 KV，其余 3 层只存每头 $128 \times 128$ 的固定状态，所以长上下文下 KV cache 约为全 MLA 的 1/4，这就是「最多省 75%」（PDF p. 1–2）。

再说速度。三组测试都用 48B 设置，层数与头数相同（PDF p. 12）：

- **Prefill**（Figure 7a）：4K–16K 时和 MLA 相当，128K 起明显更快，512K 时约 2.3 倍，1M 时约 2.9 倍；Kimi Linear 与 GDN-H 的曲线几乎重合，说明细门控没有带来可见的 prefill 开销（PDF p. 12–13）；
- **解码，batch 1**（Figure 7b）：512K 约 1.8 倍，1M 约 2.2 倍（图上标注）；
- **解码，放大 batch**（Figure 1b）：因为 KV 省下的显存可以放更大 batch，1M 时 TPOT 是 1.84 ms 对 11.48 ms，约 6.3 倍（PDF p. 1）。

摘要与结论里的「最多 6 倍解码吞吐」「6.3 倍」都是第三组，报告在 §6.3 也称它为理论上的解码加速（PDF p. 16）。第三组放大到多大 batch，报告没写。

报告自己的数字有一处对不上：§6.3 说 Figure 7b 在 1M 时是 2.3 倍（PDF p. 16），图上标的是 2.2 倍，2.3 倍其实是 Figure 7a 在 512K 的 prefill 标注；§7.1 又写作「1M 时解码超过 2 倍」（PDF p. 17）。以图为准，本文取 2.2 倍。

推理策略本身很简单（PDF p. 15–16）：prefill 用计算密集的 chunk kernel，自回归生成切到更省的递推 kernel。随着长度增长、解码受 I/O 限制，混合模型相对全注意力的解码时间会逼近一个由 3:1 比例决定的上限（PDF p. 16）。KDA kernel 与 vLLM 集成已开源，接口与现有全注意力流水线兼容，不需要改缓存与调度接口（PDF p. 1–2）。

## 和稀疏注意力是什么关系

报告在相关工作里把高效注意力分成两条路（PDF p. 16–17）：线性注意力压缩历史，稀疏注意力只挑一部分历史去看。NSA 和 MoBA 从 Token 级走到块级选择，DeepSeek-V3.2-Exp 的 DSA 又回到 Token 级，用低精度的索引器挑 Token（相关内容见站内 NSA、MoBA、DeepSeek-V3.2 三篇）。

作者的判断是：稀疏注意力取回细节更准，但要保留完整 KV cache 来做挑选，表达力上限就是全注意力；线性注意力状态固定、更省，配上 delta rule 理论上表达力可以更强，检索弱的问题可以用状态扩展等办法缓解（PDF p. 17）。两者不互斥，作者把「线性加稀疏的混合」列为未来方向。这段是立场，不是实验结论。

## 论文之后：KDA 成了 Kimi K3 的序列骨干

以下是外部补充，不是本 PDF 的内容。Kimi K3 技术报告（见站内 Kimi-K3 一篇，依据其 PDF p. 4–5）写明：K3 采用 KDA 与 Gated MLA 的层间混合，每 3 层 KDA 接 1 层 Gated MLA，比例 3:1；KDA 的参数化和分块算法沿用 Kimi Linear；全部 MLA 层照搬 Kimi Linear 的 NoPE 设计。K3 同时改了两处：给 Kimi Linear 原本无下界的对数衰减加了下界，以及把 KDA 的低秩输出门改成全秩门。

所以「Kimi Linear 是 K3 的骨干」这句话成立的范围是：KDA 模块、3:1 层间混合和 NoPE 全局层这三件事被 K3 继承了。K3 的规模、衰减下界和全秩门都是后来的改动，不能读回本篇的 48B 实验。

## 限制与没有公开的部分

报告写了、但证据有边界的：

- **「全面超过」有例外**。SFT 的 LiveBench、EvalPlus，长上下文的 LongBench V2、Frames、Commit，最好的都是 MLA；Stack 合成任务上 KDA 与 GDN 平手；
- **6.3 倍是放大 batch 后的吞吐**，batch 大小没写；单请求解码约 2.2 倍，而且正文对这个数前后说法不一；
- **1.16 倍缩放优势只覆盖到 1.7B 激活**，且基线调过参、Kimi Linear 没调；
- **RL 对照只有数学、单次运行**，没有误差带；
- **NoPE 为什么更好**，是作者的推测，没有单独的机制实验。

正文没有公开的：

- 48B 模型的层数、隐藏维、MLA 维度与头数；
- 预训练数据配比，长上下文激活阶段的具体长度与步数（都只指回 K2）；
- SFT 与 RL 的数据规模、步数、奖励设计与超参数值；
- 放大 batch 解码实验的 batch 大小与硬件；
- 衰减函数 $f(\cdot)$ 的具体形式，正文只说「类似 GDN 与 Mamba」。

## 可迁移启发

1. **公平对照先锁三样：规模、配方、骨架。** 1.4T 对照里 MLA、GDN-H、Kimi Linear 同骨架、同参数、同数据，差别只剩注意力。发布版和 Moonlight 的对比变量太多，只能当产品数据看。
2. **遗忘粒度要跟信息寿命的差异对齐。** 一个头里有长有短，就给每个通道自己的衰减率。
3. **想要更强的表达式，找一个硬件友好的受限特例。** 把 DPLR 的 $a$、$b$ 绑到 $k$ 上，保住了 delta rule 的形状，也砍掉了一半的特殊矩阵。
4. **混合比例用验证集和推理开销一起定。** 7:1 训练 loss 不差，验证就露馅；1:1 验证不差，推理更贵。
5. **位置只让一套系统负责。** 已有带位置感的线性层时，全局层用 NoPE，既能化成 MQA，又免掉长上下文的 RoPE 调参。
6. **报加速时把三件事拆开：结构省量、batch 1 延迟、放大 batch 的吞吐。** 同一个 3:1 结构，对应的是「KV 省 75%」「1M 解码约 2.2 倍」「1M 放大 batch 约 6.3 倍」三个不同的数。
7. **固定状态省的是 3/4，剩下的 1/4 决定上限。** 混合模型的 prefill 与解码加速，最终都会被保留下来的全注意力层卡住。

## 关键词回看

- **KDA**：GDN + 通道级对角遗忘门，式 (1)，$d_k = d_v = 128$。
- **GDN / GDN-H**：头级标量遗忘门的前作，以及用它做线性层的混合对照模型。
- **Delta rule**：写入前先沿 $k$ 方向擦掉旧值，等价于对重建误差做一步在线梯度下降。
- **受限 DPLR**：$D = \mathrm{Diag}(\alpha_t)$，$a_t = \beta_t k_t$，$b_t = k_t \odot \alpha_t$；块内特殊矩阵 4 → 2，kernel 约快 1 倍。
- **WY 表示 / UT 变换**：把块内连乘的秩 1 更新打包成矩阵运算的两个工具。
- **3:1 层间混合**：3 层 KDA 配 1 层 MLA，消融在验证 PPL 与推理开销之间选出。
- **NoPE MLA**：全局层不加位置编码，位置交给 KDA，推理可化 MQA。
- **1.16 倍**：缩放曲线上的算力效率，基线调参而 Kimi Linear 没调。
- **75% / 6.3 倍 / 2.2 倍 / 2.9 倍**：KV 省量，1M 放大 batch 解码，1M batch 1 解码，1M prefill。
- **5.7T 发布版**：48B-A3B，支持 1M 上下文，RULER@1M 94.8。
