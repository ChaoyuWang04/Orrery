# 每个 Token 只进一个专家，参数就能涨到万亿

<!-- release-date: 2021-01-11 -->

> 本文依据 Google 的 **Switch Transformers: Scaling to Trillion Parameter Models with Simple and Efficient Sparsity**，arXiv:2101.03961v3（2022-06-16），即 JMLR 23 (2022) 的刊出版，共 40 页。作者 William Fedus、Barret Zoph（共同一作）与 Noam Shazeer。页码均指这份 PDF 自身的页码。文中区分三件事：**报告明确写了什么**、**我们如何解释或验算它**、**哪些是外部资料补充**。

## 读前先把几个词说成人话

这篇论文难读的地方不是公式，而是它故意把「模型里存了多少权重」和「每个 Token 这一步要算多少」拆成两件事。后面所有表，都踩在这道缝上。

- **Token（词元）**：模型读写文本的最小单位。
- **Dense（稠密模型）**：每一层的全部参数对每个 Token 都算一遍。参数翻倍，单次计算量大致也翻倍。
- **FFN（Feed-Forward Network，前馈网络）**：Transformer 块里注意力之后那两层全连接。本文只动它。
- **MoE（Mixture-of-Experts，混合专家）**：把 FFN 换成一排小网络（专家），每个 Token 只让其中少数几个干活。总参数可以很大，每个 Token 的计算量却不必跟着涨。
- **路由器（router）**：一个小线性层，按 Token 的隐状态给每个专家打分，决定这个 Token 去哪。得分最高的 $k$ 个叫 top-$k$。
- **FLOPs（浮点运算次数）**：一次前向实际做了多少加减乘。本文拿「每个 Token 或每个序列的 FLOPs」当计算账单，不拿总参数当账单。
- **专家容量（expert capacity）与容量因子（capacity factor）**：每个专家在一个 batch 里最多接多少 Token，以及在均匀份额之上垫多少余量。
- **bfloat16 / float32**：两种浮点精度。bfloat16 更快、通信更省，但路由里的 softmax 在它下面更容易出数值问题。

论文自己的几个专有设定：

- **Switch 层（Switch layer）**：每个 Token 只激活得分最高的 **一个** 专家，即 $k = 1$（PDF p. 6）。
- **隔层专家**：Switch-Base、Large、XXL 都是每隔一层才把 FFN 换成 Switch 层；只有 Switch-C 每层都换（PDF p. 9、p. 23 表 9 的 Expert Freq. 列）。
- **负对数困惑度（Neg. Log Perp.）**：全文的预训练质量指标，以 e 为底，越接近 0 越好（PDF p. 8 脚注 4）。

这篇论文的对照对象是 T5：同一个编码器–解码器骨架、同一份 C4 语料、掩码语言模型目标（随机遮掉 15% 的 Token，用一个哨兵 Token 替换每段被遮的内容）（PDF p. 8）。它不是自回归解码器，这一点读实验数字时要记住。

## 一句话先说清

2021 年初，想把语言模型做强，通行做法是把 dense Transformer 加宽加深。Kaplan 等人的规模定律已经说明：模型、数据、算力一起涨，效果按幂律变好（PDF p. 4）。dense 的麻烦是这几件事焊在一起——参数翻一倍，每个 Token 的矩阵乘也大致翻一倍。

Switch Transformer 要加的是第四根轴（PDF p. 4）：

> **参数可以单独涨，每个 Token 的 FLOPs 几乎不涨。办法是每个 Token 只进一个专家。**

摘要和贡献列表把结论写成五条（PDF p. 1、p. 4）：

- 把 MoE 路由简化成 top-1，降低通信与计算；
- 用选择性精度、更小的初始化、专家 dropout 三招，第一次让大规模稀疏模型能用 bfloat16 稳定训练；
- 以 T5-Base、T5-Large 为骨架，同样计算资源下预训练最多快 7 倍以上；
- 多语言上相对 mT5-Base，101 种语言全都有收益，91% 的语言快 4 倍以上；
- 把语言模型推到万亿参数，相对 T5-XXL 大约快 4 倍。

这五条要分开定价。7 倍是预训练墙钟，4 倍是到达固定困惑度的速度，下游微调、蒸馏、服务又是另外几本账。下文逐本拆开。

## 主要矛盾：参数和计算被绑在同一张账单上

论文开头先承认，简单架构加上大预算、大数据、大参数，能压过更复杂的算法；GPT、T5、GPT-3 走的都是把 dense Transformer 做大这条路，而它极其耗算力（PDF p. 3）。

稀疏计算是自然的出路，但当时的库和加速器都按稠密矩阵乘优化。作者因此不从任意稀疏入手，而是从 MoE 往回收：Shazeer 等人 2017 年、Mesh-TensorFlow、GShard 已经在机器翻译上证明「参数可以变多、计算不必等比例变多」，可普及被三件事挡住——复杂、通信贵、训练不稳（PDF p. 3）。

于是矛盾变成：

> dense 把「能记住多少」和「每次要算多少」焊在一起。旧 MoE 声称能拆开，但 top-2 路由、两套辅助损失、整网 float32，把省下来的算力又花回了通信和稳定性上。Switch 要回答的是：每个 Token 只进一个专家，这根轴还站不站得住。

## 核心设计：把 top-2 收成 top-1

### 旧问题：都以为至少要看两个专家，路由器才学得动

Shazeer 等人 2017 年的 MoE 层对每个 Token 表示 $x$，从 $N$ 个专家里挑 top-$k$（PDF p. 5）。路由器先做一次线性投影 $h(x) = W_r \cdot x$，再 softmax 成门控值：

$$
p_i(x) = \frac{e^{h(x)_i}}{\sum_{j=1}^{N} e^{h(x)_j}}
$$

$p_i(x)$ 是 Token $x$ 分给专家 $i$ 的概率。若 $\mathcal{T}$ 是选中的 top-$k$ 下标，层输出是这几个专家输出的门控加权和：

$$
y = \sum_{i \in \mathcal{T}} p_i(x)\, E_i(x)
$$

$E_i(x)$ 是专家 $i$（一个 FFN）对 $x$ 的输出。当时的直觉是：$k > 1$ 路由器才有「比较两个专家」的非平凡梯度；Ramachandran 与 Le 2018 年还发现，路由层多时，下面几层需要更大的 $k$（PDF p. 5–6）。

代价是三笔同时发生的账：每个 Token 跑两份 FFN，每个专家的槽位按「每个 Token 占两格」预留，跨设备的派发也按两份走。

### 新设计：只留得分最高的那一个

Switch 的改动小到不像主贡献：$k = 1$。层仍按上面第二个式子算，只是 $\mathcal{T}$ 里只剩一个下标（PDF p. 6）。

作者强调，**无论 top-$k$ 还是 top-1，门控值 $p_i(x)$ 本身就让路由器可微**（PDF p. 6）。选中的专家输出要乘上 $p_i(x)$ 才进残差流，梯度沿这个乘法回到 $W_r$；softmax 又把各专家的分数绑在一起，一个升高别的必须降低。所以不需要第二个专家来「对比」。

论文列的好处有三条（PDF p. 6）：路由计算减少；每个专家的容量至少可以减半，因为每个 Token 只占一个槽；实现更简单，通信更少。

### 容量：静态形状碰上动态路由

实现栈是 Mesh-TensorFlow，面向 TPU（PDF p. 6）。TPU 要求张量形状在编译期定下来，路由却是训练和推理时才决定的，所以「每个专家算多少 Token」必须提前写死（PDF p. 7，式 3）：

$$
\text{expert capacity} = \frac{\text{tokens per batch}}{\text{number of experts}} \times \text{capacity factor}
$$

括号里是完全均匀时每个专家该分到的份额，容量因子是在这个份额之上垫的余量。

![两栏对照：6 个 Token 派给 3 个专家，实际是 3 比 2 比 1。容量因子 1.0 时每个专家 2 个槽，第一个专家多出的 1 个 Token 溢出、只走残差，第三个专家空 1 个槽；容量因子 1.5 时每个专家 3 个槽，没有溢出，但 9 个槽空了 3 个。](/reports/Switch-Transformers/figure3-capacity.svg)

图上的两栏就是这个式子的两种失败方向。容量因子小，热门专家溢出，溢出的 Token 这一层跳过专家、沿残差直接进下一层；容量因子大，空槽照样占计算、内存和通信（PDF p. 6–7）。论文的经验是：保持低丢弃率对稀疏模型的规模化很重要；他们的实验里丢弃率通常低于 1%，而且没观察到它和专家数有关——只要负载均衡损失的系数够大（PDF p. 7）。

附录 F 的伪代码把整层写成一串形状变换（PDF p. 33–35）。人话顺序是：

1. 把 `[batch, seq, d_model]` 收成 `[核数, 每核 Token 数, d_model]`；
2. 路由器算出 **dispatch 张量**（布尔，Token 去哪个专家的第几个槽）和 **combine 张量**（同形状，再乘上门控值）；超出容量的槽位在这一步被掩掉，同一专家内按 Token 顺序先到先得；
3. 用 einsum 把 Token 收成 `[专家数, 核数, 容量, d_model]`；
4. 一次 all-to-all，让「按核切分」变成「按专家切分」；
5. 每个专家跑自己的 FFN；
6. 再一次 all-to-all 送回，用 combine 张量乘门控值，拼回原形状。

**我们如何解释它。** 这六步比「MoE」这个词更接近真实的账单：静态容量要为空槽付费，两次 all-to-all 要付延迟，溢出要付「这一层等于没算」。论文没有测服务延迟，但这套形状在推理时同样生效（PDF p. 7 说路由决定在训练和推理时都是动态的）。

### 负载均衡：只留一项辅助损失，系数 $10^{-2}$

Shazeer 2017 年的原始设计有负载均衡与重要性加权两套损失；Switch 跟随 Mesh-TensorFlow 与 GShard，收成一项（PDF p. 7）。对 $N$ 个专家、一个含 $T$ 个 Token 的 batch $\mathcal{B}$，每个 Switch 层加一项（PDF p. 7，式 4–6）：

$$
\text{loss} = \alpha \cdot N \cdot \sum_{i=1}^{N} f_i \cdot P_i
$$

$f_i$ 是这一批里真正被派到专家 $i$ 的 Token 比例（按 argmax 计数，不可导）；$P_i$ 是路由器在这批 Token 上分给专家 $i$ 的平均概率（可导）。两者都想靠近 $1/N$。乘上 $N$ 是为了让损失尺度不随专家数变：完全均匀时 $\sum_i \tfrac{1}{N}\cdot\tfrac{1}{N} = \tfrac{1}{N}$，乘 $N$ 后是 1（PDF p. 8）。

$\alpha$ 从 $10^{-1}$ 扫到 $10^{-5}$，全文用 $10^{-2}$：够快把负载拉平，又不干扰主交叉熵（PDF p. 8）。

**我们如何解释它。** 梯度只从 $P_i$ 走，意思是路由器看不见「你把这个 Token 派错了」，只看得见「你给这个专家的概率偏高」。辅助损失推的是概率质量，真正切掉多余 Token 的是容量。两者是配套的两件事，不是同一个旋钮。

### 表 1：同样 128 个专家，top-1 在低容量上赢 top-2

表 1 是全文最重要的头对头（PDF p. 9）。所有 MoE 与 Switch 都是 128 个专家、隔层替换，32 核 TPUv3，训同样步数；质量看 100k 步的负对数困惑度，时间看到达 $-1.50$ 的小时数。

| 模型 | 容量因子 | 100k 步质量 | 到 $-1.50$ 的小时 | 样本 / 秒 |
|---|---:|---:|---:|---:|
| T5-Base | — | $-1.731$ | 100k 步内没到 | 1600 |
| T5-Large | — | $-1.550$ | 131.1 | 470 |
| MoE-Base（top-2） | 2.0 | $-1.547$ | 68.7 | 840 |
| Switch-Base | 2.0 | $-1.554$ | 72.8 | 860 |
| MoE-Base（top-2） | 1.25 | $-1.559$ | 80.7 | 790 |
| Switch-Base | 1.25 | $-1.553$ | 65.0 | 910 |
| MoE-Base（top-2） | 1.0 | $-1.572$ | 80.1 | 860 |
| Switch-Base | 1.0 | $-1.561$ | 62.8 | 1000 |
| Switch-Base+ | 1.0 | $-1.534$ | 67.6 | 780 |

MoE 用 top-2，每个 Token 跑两份 FFN，所以它的 FLOPs 比 Switch 大（PDF p. 8）。论文读出三条（PDF p. 8）：

1. 固定计算量与墙钟，Switch 在速度–质量上优于调好的 dense 与 MoE；
2. Switch 计算脚印更小；把它加大到与 MoE 同速（Switch-Base+），逐步质量也最好；
3. Switch 在容量因子 1.0 与 1.25 上更强，而大模型显存紧张时，容量因子正会被压到尽量小。

**我们如何解释它。** 容量因子 2.0 时，Switch 反而略差于 MoE（100k 步 $-1.554$ 对 $-1.547$，到阈值慢 4.1 小时）。真正拉开的是把容量往 1.0 收：Switch 从 72.8 小时降到 62.8，MoE 反而升到 80.1。**top-1 的价值不是「永远比 top-2 准」，而是「在给不起每个专家两倍槽位时，掉得更少、跑得更快」**——这正是万亿规模会碰到的约束。

表 1 有两处按原文照录、但要带着读：

- 脚注 5 承认速度既取决于算法也取决于实现；MoE 从容量因子 2.0 收到 1.25 反而变慢（840 到 790），作者自己也说意外（PDF p. 8）。样本 / 秒不要读成渐近复杂度。
- 表注说 Switch-Base+ 把隐层从 768 加到 896、头数「从 14 加到 16」（PDF p. 9），而表 9 里 T5-Base 与 Switch-Base 都是 12 个头（PDF p. 23）。两处对不上，原文没有解释。

**可迁移启发。** 在 top-1 与 top-2 之间选，先问能不能给每个专家留两倍的槽。留得起，表 1 并不禁止 top-2；留不起，$k = 1$ 就是按这个约束设计的。「专家数」和「每个 Token 激活几个专家」是两个旋钮，不要混着调。

## 训练怎么稳住：三招各治一种病

稀疏模型每层都有一次硬切换，bfloat16 又会放大路由器 softmax 的数值问题（PDF p. 8–9）。GShard 的做法是整网 float32（PDF p. 9）。Switch 拆成三招，分别对付三件不同的事。

### 选择性精度：只把路由器局部升到 float32

表 2 用 32 个专家的 Switch-Base，在训练早期固定步数比三种精度（PDF p. 10）：

| 精度 | 负对数困惑度 | 样本 / 秒 |
|---|---:|---:|
| 全程 float32 | $-1.718$ | 1160 |
| 全程 bfloat16 | $-3.780$（发散） | 1390 |
| 选择性精度 | $-1.716$ | 1390 |

做法是把路由器的输入转成 float32，在**本设备内部**算完 dispatch 与 combine 张量，函数末尾再转回 bfloat16（PDF p. 9–10）。跨设备的 all-to-all 仍传 bfloat16，所以速度和纯 bfloat16 一样，质量却贴着 float32。附录 F 图 15 把 `to_float32` 与 `to_bfloat16` 写在同一段路由器函数里（PDF p. 34）。

**我们如何解释它。** 不稳发生在 softmax 的指数上，不在专家的矩阵乘上。所以不必把万亿参数都升精度，只让「谁去哪」这道分类在 32 位里做。它和混合精度训练把某些局部留在高精度是同一类思路（论文也这么类比，PDF p. 9），只是局部化的对象换成了路由器。

### 初始化：默认尺度除以 10

权重从截断正态分布抽样，均值 0，标准差 $\sigma = \sqrt{s/n}$，$n$ 是输入维度（fan-in），$s$ 是尺度超参；超过两倍标准差的值重采（PDF p. 10）。默认 $s = 1.0$，论文建议除以 10。表 3 是 32 个专家、3.5k 步、3 个随机种子（PDF p. 10）：

| 初始化尺度 | 平均质量 | 标准差 |
|---|---:|---:|
| $0.1\times$ | $-2.72$ | 0.01 |
| $1.0\times$ | $-3.60$ | 0.68 |

质量更好，跨种子方差几乎消失。作者说同一套初始化从 223M 的基线一直用到超过万亿参数的模型（PDF p. 10）。

### 专家 dropout：微调时只对专家加码

Switch 的参数远多于 FLOP 对齐的 dense，下游小数据集上更容易过拟合（PDF p. 11）。表 4 在只预训练了 34B Token 的模型上扫 dropout（PDF p. 11）：

| 设置 | GLUE | CNNDM | SQuAD | SuperGLUE |
|---|---:|---:|---:|---:|
| T5-Base（0.1） | 82.9 | 19.6 | 83.5 | 72.4 |
| Switch-Base（0.1） | 84.7 | 19.1 | 83.7 | 73.0 |
| Switch-Base（0.2） | 84.4 | 19.2 | 83.9 | 73.2 |
| Switch-Base（0.3） | 83.9 | 19.6 | 83.4 | 70.7 |
| Switch-Base（0.1，专家 0.4） | 85.2 | 19.6 | 83.7 | 73.0 |

所有层一起加大 dropout 会变差（0.3 时 SuperGLUE 掉到 70.7）；**非专家层保持 0.1、只把专家内部 FFN 的 dropout 加到 0.4**，四个任务都不输（PDF p. 11）。后面的正式微调协议就用这一档（PDF p. 15）。

**可迁移启发。** 三招打的是三种不同的病：softmax 数值、训练起步的方差、小数据过拟合。不要把「MoE 不稳」当成一种病开一剂药；路由精度、初始化尺度、专家正则可以分开扫。

## 缩放：专家数是最便宜的那根轴

第 3 节先把数据瓶颈拿掉：C4 有超过 180B 个目标 Token，训到收益递减为止（PDF p. 11）。论文认为加专家是最划算的放大方式：每个 Token 仍只选一个专家，每 Token FLOPs 近似不变；路由器要对更多专家做 softmax，代价 $O(d_{\text{model}} \times N)$，是轻量计算（PDF p. 11）。

**我们验算「轻量」。** Switch-Base 上 $d_{\text{model}} = 768$、$N = 128$，路由约 $9.8 \times 10^{4}$ 次乘加，单个专家 FFN 约 $768 \times 2048 \times 2 \approx 3.1 \times 10^{6}$，路由约为一个专家的 3%。换到 Switch-C（$d_{\text{model}} = 2080$、$N = 2048$、$d_{\text{ff}} = 6144$），路由约 $4.3 \times 10^{6}$，单个专家约 $2.6 \times 10^{7}$，升到约 17%。仍远小于把专家都算一遍，但到 2048 个专家这一档，已经不是可以随口忽略的项。

### 逐步：同样 FLOPs，专家越多越样本高效

![左图：从 1 个专家的 T5-Base（223M）到 256 个专家（14.7B），每 Token 计算量不变，测试损失从 6.00 一路降到约 4.84；右图：专家数每翻一倍，损失的降幅从 0.13 升到 8 到 16 专家时的 0.21，之后收窄到 0.08。](/reports/Switch-Transformers/figure4-expert-scaling.svg)

左图是论文 Figure 4 左图的读数：每 Token FLOPs 固定，专家数从 1 翻倍到 256，测试损失单调下降（PDF p. 12）。右图是我们把相邻两点相减：降幅在 8 到 16 个专家时最大，之后一路收窄。第 5 节开头那句「一味增加专家数会收益递减（Figure 4）」（PDF p. 18），在这张图上就是右半边越来越矮的柱子。

Figure 4 右图换成对训练步：Switch-Base 64 个专家在第 60k 步达到的质量，T5-Base 要到第 450k 步，逐步加速 **7.5 倍**（PDF p. 12）。

### 墙钟：逐步的优势能不能换成时间

逐步快不等于墙钟快：Switch 多了跨设备通信和路由计算（PDF p. 13）。Figure 5 把横轴换成训练时间，32 核 TPUv3、每样本 FLOPs 对齐：64 个专家的 Switch-Base 用 **七分之一** 的时间走到 T5-Base 的质量，而且还在继续变好（PDF p. 13）。这就是摘要里「最多 7 倍」的出处。

Figure 6 换一个更硬的对照：和每个 Token 多算 3.5 倍 FLOPs 的 T5-Large 比。Switch-Base 逐步仍更样本高效，墙钟上相对 T5-Large 仍快 **2.5 倍**（PDF p. 13–14）。

附录 D 把同一句话收到小规模：只有 2、4、8 个专家也稳定好过 FLOP 对齐的 T5-Base，作者的经验是一个专家放一个核（PDF p. 29–31，Figure 12）。

**可迁移启发。** 加宽 $d_{\text{ff}}$ 同时加参数和每 Token FLOPs，很快撞上单卡显存，被迫上模型并行、付 all-reduce；加专家主要加参数，付的是 all-to-all 与显存。表 9 后来把这两条路做成了两个万亿候选。选型时先问硬件更怕显存还是更怕 all-to-all。

## 下游：预训练的优势搬不搬得过去

微调前的预训练协议为了和 T5 公平：两边都用去掉样本内重复文本的新版 C4，每步 $2^{20}$ 个 Token，550k 步，共 576B Token（PDF p. 14–15）。微调用 1M Token 的 batch、16k 步，每 200 步验一次、报验证集峰值；dropout 非 Switch 层 0.1、Switch 层 0.4（PDF p. 15）。

表 5 是 FLOP 对齐的主结果（PDF p. 16）：

| 任务 | T5-Base | Switch-Base | T5-Large | Switch-Large |
|---|---:|---:|---:|---:|
| GLUE | 84.3 | 86.7 | 87.8 | 88.5 |
| SQuAD | 85.5 | 87.2 | 88.1 | 88.6 |
| SuperGLUE | 75.1 | 79.5 | 82.7 | 84.7 |
| Winogrande（XL） | 66.6 | 73.3 | 79.1 | 83.0 |
| XSum | 18.7 | 20.3 | 20.9 | 22.3 |
| ANLI（R3） | 51.8 | 54.0 | 56.6 | 58.6 |
| ARC Easy | 56.7 | 61.3 | 68.8 | 66.0 |
| ARC Challenge | 35.5 | 32.8 | 35.5 | 35.5 |
| 闭卷 Web QA | 26.6 | 27.4 | 27.7 | 31.3 |
| 闭卷 Natural QA | 25.8 | 26.8 | 27.6 | 29.5 |
| 闭卷 Trivia QA | 24.5 | 30.7 | 29.5 | 36.9 |

SuperGLUE 上 Switch 相对 T5-Base、T5-Large 分别高 4.4 和 2 个点，Winogrande、闭卷 Trivia QA、XSum 的提升也大（PDF p. 15）。唯一没赚到的是 ARC：Challenge 上 T5-Base 高于 Switch-Base，Easy 上 T5-Large 高于 Switch-Large（PDF p. 15）。

**我们如何解释它。** 闭卷问答考的是参数里装了多少事实，多出来的专家容量正好用得上；ARC 这类科学推理更依赖每个 Token 实际算了多少。附录 E 的上下游对照指向同一个方向（见后文）。表 5 的 ARC 是这条缝最早的信号，但论文本身只报告了结果，没有给这个解释。

## 蒸馏：训练用稀疏，部署用小 dense

论文直接问：「我部署不了万亿参数的模型，能不能把它缩小？」回答是质量不能全保住，但能压缩 10 到 100 倍、留下稀疏老师约 30% 的增益（PDF p. 25）。

表 6 拆开技术（PDF p. 17）。学生都是 223M 的 T5-Base，老师是 3.8B 的 Switch-Base：

| 做法 | 参数 | 负对数困惑度（留下的增益） |
|---|---:|---|
| T5-Base 从头训 | 223M | $-1.636$ |
| Switch-Base 老师 | 3,800M | $-1.444$ |
| 蒸馏 | 223M | $-1.631$（3%） |
| 再用老师的非专家权重初始化 | 223M | $-1.598$（20%） |
| 再用 0.75 真实标签 + 0.25 老师概率的混合损失 | 223M | $-1.580$（29%） |
| 只用老师的非专家权重初始化、不蒸馏 | 223M | $-1.639$ |

因为老师与学生 FLOP 对齐，非专家层形状相同，学生可以直接拷老师的注意力、嵌入等权重再蒸（PDF p. 16）。只拷不蒸没有用；两项合起来，大约用 1/20 的参数留下约 30% 的增益。

「增益」的口径要读准（PDF p. 16–17）：它是老师比学生基线多出来的那一截里，学生拿回了多少。表 6 上老师比基线好 $0.192$，学生好 $0.056$，$0.056 / 0.192 \approx 29\%$（我们验算）。

表 7 把老师从 1.1B 加到 14.7B，学生不变（PDF p. 18）：

| 老师参数 | 1.1B | 2.0B | 3.8B | 7.4B | 14.7B |
|---|---:|---:|---:|---:|---:|
| 老师困惑度 | $-1.505$ | $-1.474$ | $-1.444$ | $-1.432$ | $-1.427$ |
| 学生困惑度 | $-1.587$ | $-1.585$ | $-1.579$ | $-1.582$ | $-1.578$ |
| 留下的老师增益 | 37% | 32% | 30% | 27% | 28% |
| 压缩比例 | 82% | 90% | 95% | 97% | 99% |

表 8 把同一套办法用到在 SuperGLUE 上微调过的 7.4B Switch-Base：老师 81.3，T5-Base 74.6，学生 76.6，又是约 30%（PDF p. 18）。

**我们如何解释它。** 老师从 1.1B 涨到 14.7B，学生困惑度几乎不动（$-1.587$ 到 $-1.578$）。加专家加出来的容量，很大一块蒸不进固定尺寸的 dense——作者也提醒，更强更大的老师可能需要更大的学生（PDF p. 18）。对服务侧，这篇论文给的路径是「训练用 Switch，部署用学生」，而不是「服务也上 1.6T」。

## 多语言：101 种语言都更好

数据是 mT5 的 mC4，101 种语言；因为一些语言有多种文字写法，混合物里实际是 107 个任务（PDF p. 17）。FLOP 对齐的 mSwitch-Base 对 mT5-Base，都训 1M 步。

Figure 7 按语言排开负对数困惑度：101 种语言上 Switch 全部更好（PDF p. 19）。Figure 8 是逐步加速比的直方图：平均 5 倍，91% 的语言至少 4 倍（PDF p. 19）。加速比的定义是「基线达到某质量的步数 ÷ Switch 达到同一质量的步数」（PDF p. 18 脚注 9）。

论文没有把专家可视化成「某种语言专用的专家」。证据只到「每种语言都更好、大多数更快」，不要补写成语言专家已经特化。

## 三种并行叠到万亿

第 5 节先承认只加专家会收益递减，于是要把 $d_{\text{model}}$、$d_{\text{ff}}$ 也加上去，每 Token FLOPs 跟着涨；单核放不下，就要切（PDF p. 18–19）。Figure 9 用两行 $4 \times 4$ 的核格子画了五种切法（PDF p. 21），改写成表：

| 策略 | 权重怎么切 | Token 怎么切 | 通信 |
|---|---|---|---|
| 数据并行 | 每核一份完整权重 | 按核切 | 整次前向反向结束才聚合梯度 |
| 模型并行 | 每核一块 $d_{\text{ff}}$ | 每核都拿全部 Token | 前向、反向各一次 all-reduce，张量 $[B, d_{\text{model}}]$ |
| 模型 + 数据 | 按 $d_{\text{ff}}/m$ 切 | 每核 $B/n$ 个 | all-reduce，张量 $[B/n, d_{\text{model}}]$ |
| 专家 + 数据 | 每核一个专家 | 按核切，再按路由重排 | all-to-all，张量 $[E, C, d_{\text{model}}]$ |
| 三者一起 | 专家之间切，专家内部再切 $d_{\text{ff}}$ | 两种都切 | all-to-all 加 all-reduce |

表中 $B$ 是 batch 的 Token 数，$n$、$m$ 是数据并行与模型并行的路数，总核数 $N = n \times m$；$E$ 是专家数，$C$ 是专家容量（PDF p. 20）。

三者一起时的矛盾论文写得很清楚（PDF p. 22）：加 $d_{\text{ff}}$ 会先撑爆每核显存，于是加大 $m$；$N$ 固定，$n$ 就得变小，为了每核 Token 数不变，batch 只能跟着缩。FLOPs、通信、每核显存的最佳切法是经验定的。

### 两个万亿候选：对齐 FLOPs，还是把专家加到 2048

- **Switch-XXL（395B）**：与 T5-XXL FLOP 对齐，64 个专家，维度大，但要付模型并行的通信（PDF p. 23）。
- **Switch-C（1.6T）**：只用专家并行、不用模型并行，2048 个专家，宽度、深度、头数都比 T5-XXL 小（PDF p. 22–23）。

表 9 下半给出 C4 上 250k 与 500k 步的负对数困惑度（PDF p. 23）：

| 模型 | 250k 步 | 500k 步 |
|---|---:|---:|
| T5-Base | $-1.599$ | $-1.556$ |
| T5-Large | $-1.402$ | $-1.350$ |
| T5-XXL | $-1.147$ | $-1.095$ |
| Switch-Base | $-1.370$ | $-1.306$ |
| Switch-Large | $-1.248$ | $-1.177$ |
| Switch-XXL | $-1.086$ | $-1.008$ |
| Switch-C | $-1.096$ | $-1.043$ |

正文说：250k 步时两个 Switch 变体都比 T5-XXL 好「超过 0.061」，而 T5-XXL 自己再训 250k 步只提升了 0.052；500k 步时 Switch-XXL 领先 0.087（PDF p. 23）。**按表验算，Switch-XXL 的差是 0.061，Switch-C 只有 0.051**，「两个都超过 0.061」和表对不上，更像以 Switch-XXL 为主的概括。脚注 10 另说这个差距是下界：T5-XXL 训在含样本内重复、更容易的旧版 C4 上（PDF p. 23）。

稳定性在这里分叉：1.6T、2048 个专家的 Switch-C **完全没有不稳**；每序列 FLOPs 约大 10 倍的 Switch-XXL 反而偶尔不稳，所以没有按 T5 惯例训满 1M 步（PDF p. 23）。未来工作第一条就是这件事：三招对 Base、Large、C 够用，对 XXL 不够；试过正则与改过的梯度裁剪，仍未解决（PDF p. 26）。

### 半程 checkpoint 的下游：知识任务先兑现，推理任务还没有

Switch-XXL 只预训练了 503B Token，约为 T5-XXL 所用文本的一半，而且是多任务联合训练、不是逐任务微调（PDF p. 24）：

- SQuAD 验证集 89.7，当时最好 91.3；
- SuperGLUE 测试集平均 87.5，T5 是 89.3，当时最好 90.0；
- ANLI 65.7，此前最好 49.4；
- 闭卷问答（没用 Salient Span Masking）：Natural Questions 34.4 对 32.8，WebQuestions 41.0 对 37.2，TriviaQA 47.5 对 42.9，都超过此前的 T5-XXL。

作者的判断是：上游已经是最好的困惑度，下游还没有全面最好；目前更会把上游优势翻译到知识型任务，而不是推理型任务（PDF p. 24）。

未来工作第二条给了更刺眼的一组对照（PDF p. 26）：C4 困惑度相近，1.6T 的 Switch-C 在 SQuAD 上只有 87.7，更小的 Switch-XXL 是 89.6。XXL 每 Token FLOPs 约为 C 的 10 倍，独立参数约为 C 的 1/4。作者明说，微调质量与「每 Token FLOPs」「参数量」之间的依赖还没被理解。

附录 E 的 Figure 13 从另一个角度印证（PDF p. 32）：同样的上游困惑度下，小中规模时 Switch 与 dense 的下游差不多；最大档上，SuperGLUE 往往是 dense 更好，而知识型的 TriviaQA 上 Switch 可能遵循更好的缩放关系。作者说还需要更多统计才能确认。

**可迁移启发。** 万亿有两种买法。买 Switch-XXL，是买「和 11B dense 同样的每 Token 计算，外加 64 个专家的容量」；买 Switch-C，是买「更少的每 Token 计算、2048 个专家、更稳的训练」。下游若像闭卷问答，纯容量路线有证据；若像 SQuAD、SuperGLUE，每 Token 算得更多的那条更像能兑现的。

## 附录里几件没进主模型的事

**注意力里的 Switch。** 附录 A 把 Switch 层放进自注意力：一组权重产生 query，另一组独立权重产生共享的 key 与 value（PDF p. 27–28，Figure 10）。表 10 在 32 个专家、float32 下，专家注意力 100k 步 $-1.524$，好于只换 FFN 的 $-1.548$；两者都换是 $-1.513$。但 bfloat16 下凡是带专家注意力的都发散，所以主模型只换 FFN（PDF p. 28）。

**不让 Token 掉队。** 附录 B 的 No-Token-Left-Behind：第一轮按最高概率派，溢出的 Token 第二轮改派到概率第二高的专家，可迭代到几乎不丢（PDF p. 29–30，Figure 11）。作者本以为能涨点、更稳，**实验没有看到任何好处**。他们的猜测是：网络一旦学会 Token 与专家的对应，把 Token 改送到第二名，反而破坏这种对应（PDF p. 29）。

**路由探索。** 路由器每次只看到自己选中那个专家的结果，没有「选别的会怎样」的反事实，是一个探索–利用问题（PDF p. 29）。表 11 比了四种做法：argmax $-1.471$，从 softmax 抽样 $-1.570$，输入 dropout $-1.480$，输入乘性抖动 $-1.468$（PDF p. 30）。全文用输入抖动；伪代码里是训练时给路由 logits 乘上 $[1-\varepsilon, 1+\varepsilon]$ 的均匀噪声（PDF p. 34）。

## 论文怎么看自己

讨论一节用问答收紧主张（PDF p. 25–26）：

- 是不是只因为参数多？是，而且是故意的——参数本身就是一根值得加的轴；并且在同样计算资源下它更样本高效、也更快。
- 没有超算有没有用？2 个专家就有收益，放得进常见的 GPU、TPU 显存。
- 部署不了万亿怎么办？蒸馏，压缩 10 到 100 倍，留下约 30% 增益。
- 为什么不用模型并行的大 dense？墙钟上 Switch 可以更快；而且两者不互斥，Switch-XXL 就同时用了模型并行。
- 为什么稀疏还没普及？dense 缩放太成功，稀疏又有复杂、难训、通信贵三个问题；作者认为 Switch 缓解了这三件。

未来工作还列了：给定硬件的计算、显存、通信规格，怎么设计数据、模型、专家并行的配比；专家目前完全同构，以后可以把难的样本路由到更大的专家；把 Switch 用到注意力层与其他模态（PDF p. 26–27）。

## 读完该留下的判断

| 你真正想买的东西 | 这篇论文支不支持 | 证据 |
|---|---|---|
| 同样每 Token FLOPs 下更快的 T5 式预训练 | 支持：逐步约 7.5 倍，墙钟约 7 倍 | Figure 4、Figure 5、表 1 |
| 比自己每 Token 多算 3.5 倍的 dense 仍然更快 | 支持：相对 T5-Large 约 2.5 倍 | Figure 6 |
| 只加专家就能一直涨 | 部分支持：一直在涨，但每翻一倍的收益在变小 | Figure 4、p. 18 |
| 万亿参数、相对 T5-XXL 更快 | 支持：约 4 倍；Switch-C 稳、Switch-XXL 逐步更好但不稳 | 表 9、p. 23 |
| 多数下游微调 | 支持：SuperGLUE +4.4 / +2 点；ARC 是例外 | 表 5 |
| 最大档上推理型下游全面领先 | **不支持**：SuperGLUE、SQuAD 仍落后当时最好结果，Switch-C 还不如更小的 XXL | p. 24、p. 26、附录 E |
| 把稀疏老师压成可部署的 dense | 支持：留下约 30% 增益，最多压缩 99% | 表 6–8 |
| 同样显存下的服务吞吐与解码延迟 | **原文没测** | 只有训练期样本 / 秒 |

这篇论文真正改写的，不是「MoE 能不能做语言模型」——翻译上已经做过——而是把路由收到 $k = 1$，配上三招稳定性补丁，让「只加参数不加计算」这根轴第一次在 T5 骨架上训到了万亿。

> **top-1 换来的是「每个 Token 一份 FFN、容量因子可以贴近 1」的训练与通信预算，不是「万亿参数可以直接上线」。** 线上必须是 dense，就走蒸馏；能上专家并行，就先按容量因子与 all-to-all 的体积定价，再决定专家数。每 Token FLOPs 与总参数哪根轴对下游更有用，这篇论文证明了两者不是一回事，但没有给出最终配比。

## 关键词回看

- **第四根缩放轴**：参数独立于每 Token FLOPs 增长。本文用 Switch 层实现。
- **Switch 层 / $k = 1$**：每个 Token 只进一个专家；路由器靠门控值 $p_i(x)$ 拿梯度，不靠第二个专家。
- **专家容量与容量因子**：槽数 =（本批 Token 数 ÷ 专家数）× 容量因子；小了溢出，大了空转。
- **溢出 Token**：专家满员后这一层只走残差；全文丢弃率通常低于 1%。
- **负载均衡损失**：$\alpha N \sum_i f_i P_i$，$\alpha = 10^{-2}$；只推概率质量，真正切槽靠容量。
- **选择性精度**：路由器局部 float32，all-to-all 仍传 bfloat16；纯 bfloat16 会发散。
- **$0.1\times$ 初始化**：默认尺度除以 10，从 223M 用到万亿。
- **专家 dropout**：微调时非专家层 0.1、专家层 0.4。
- **Switch-XXL 与 Switch-C**：395B、64 个专家、FLOP 对齐 T5-XXL、逐步更强但不稳；1.6T、2048 个专家、无模型并行、训练更稳，推理型下游更弱。
- **蒸馏 30%**：非专家权重初始化加 0.75 / 0.25 混合损失，把稀疏增益的三成装进 223M 的 dense。
