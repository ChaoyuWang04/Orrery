# NSA：稀疏注意力要从预训练就长在模型里，也要在硬件上真的变快

<!-- release-date: 2025-02-16 -->

> 本文依据 DeepSeek-AI、北京大学与华盛顿大学的 **Native Sparse Attention: Hardware-Aligned and Natively Trainable Sparse Attention**，arXiv:2502.11089v2，2025-02-27，共 25 页：正文到 p. 17，参考文献在 p. 17–20，附录 A（AIME 解题样例）在 p. 21–25。页码均指这份 PDF 自身的页码。文中区分三件事：**报告明确写了什么**、**我们怎么解释它**、**哪些是外部资料或本文推算**。

## 读前先把几个词说成人话

这篇论文一半讲算法，一半讲 GPU。先把两边的词都翻成人话。

- **Token（词元）**：模型读写文本的最小单位。
- **注意力（attention）**：当前 Token 回头看前文、按相关程度加权取信息的机制。当前 Token 的提问叫 **Query**，历史 Token 的索引标签叫 **Key**，携带的内容叫 **Value**。
- **全注意力（full attention）**：每个 Query 都和前面全部 Key 比一次，成本随长度平方增长。
- **稀疏注意力（sparse attention）**：每个 Query 只看一部分历史。挑哪部分、怎么挑，是这一整类方法的全部分歧。
- **KV Cache（键值缓存）**：生成时把算过的 Key 与 Value 存在显存里，每生成一个新 Token 都要把它读一遍。
- **GQA（Grouped-Query Attention，分组查询注意力）/ MQA（Multi-Query Attention，多查询注意力）**：让一组 Query 头共用一份 Key 与 Value，KV Cache 因此变小、解码时读得少。MQA 是全部头共用一份的极端情况。
- **预填充（prefill）与解码（decode）**：一次请求先一口气读完输入（prefill），再逐个吐新 Token（decode）。
- **算术强度（arithmetic intensity）**：每读 1 字节数据做多少次运算。高于硬件的临界值，瓶颈在算力（compute-bound）；低于它，瓶颈在显存带宽（memory-bound）。
- **SRAM / HBM**：GPU 片上的小而快的缓存 / 片外的大而慢的显存。
- **Tensor Core**：GPU 上专做矩阵乘的单元，要喂成块的连续数据才跑得满。
- **FlashAttention**：把注意力分块搬进 SRAM 计算、精确且省显存读写的实现。本文对照的是它的第二代 FlashAttention-2。
- **Triton**：一种用 Python 写 GPU 算子的语言与编译器。

这篇论文自己的名字：

- **NSA（Natively trainable Sparse Attention，原生可训练稀疏注意力）**：从预训练第一步就用的稀疏注意力。每个 Query 同时走三条路读历史：压缩（看全局摘要）、选择（精读挑中的块）、滑窗（盯住最近一段），再用门控把三路加起来（PDF p. 2–3、p. 6）。

## 一句话先说清

2025 年初，稀疏注意力的论文已经很多，但落地的很少。论文把原因归成两句话（PDF p. 2）：

1. **纸面上省了，墙钟上没快**。很多方法理论计算量降了，实际延迟没跟着降。
2. **只在推理期稀疏，训练时照旧稠密**。模型从没在稀疏下被训练过，训练成本也一分没省。

NSA 同时回答这两件事：

- **硬件对齐**：稀疏的单位是连续的块，同一 GQA 组的头共用一套块，这样稀疏才能喂满 Tensor Core、真正少读显存（PDF p. 3、p. 7–9）。
- **原生可训练**：挑块用的分数，直接复用一个可学习的压缩分支的注意力分数，整条链路端到端训练，不需要辅助损失（PDF p. 3、p. 7）。

论文的实验是从头预训练一个 27B 总参、3B 激活的 MoE 模型（PDF p. 9–10）。结论是：NSA 在通用基准、LongBench 与 AIME 上都不输甚至略超全注意力；在 64K 长度上，注意力算子前向快 9.0 倍、反向快 6.0 倍，解码按访存量估算快 11.6 倍（PDF p. 2、p. 13–14）。

读结论前要知道三条边界：

- 对照组只有一个全注意力模型和几种推理期稀疏方法，**没有其他可训练稀疏方法**的同条件对比。
- 9.0 倍与 6.0 倍是 **注意力算子** 的实测，不是整模型训练吞吐；11.6 倍是 **按读取 Token 数估算** 的解码加速，不是实测（PDF p. 13–14）。
- 整篇只有一个规模、一套超参，没有消融三条分支各自的贡献。

## 主要矛盾：稀疏在论文里省了，在 GPU 上没省

### 卡点一：解码的大头是注意力

论文开篇给了一个估算：解码 64K 上下文时，softmax 注意力占总延迟的 70%–80%（PDF p. 2）。长上下文越来越常见：长链推理、仓库级代码、多轮 Agent。注意力不变快，别处再省也没用。

### 卡点二：推理期加速是幻觉

第 2.1 节把「理论省了、实际没快」拆成两个原因（PDF p. 3–4）。

**只稀疏一个阶段**。H2O 在解码时稀疏，但 prefill 要先算注意力图、建索引；MInference 反过来，只稀疏 prefill。总有一个阶段的成本和全注意力差不多。于是读长文档做摘要（prefill 为主）或长链推理（decode 为主）这类负载，总有一类吃不到加速（PDF p. 4）。

**和 GQA / MQA 对不上**。现代模型为了省解码带宽，让一组 Query 头共用一份 KV。Quest 这类方法让每个头各选各的 KV 子集。在多头注意力（MHA）里，这确实同时省了计算和访存；但在 GQA 里，一组头要从同一份 KV Cache 里读，要读的量是组内所有头选择的 **并集**。计算省了，读取量没怎么省（PDF p. 4）。

### 卡点三：可训练稀疏是迷思

第 2.2 节给出为什么必须在训练时就稀疏（PDF p. 4–5）：

- **事后稀疏会掉点**。预训练出来的模型没按稀疏优化过。论文引用的数据是：取注意力分数最高的 20%，只能覆盖总注意力分数的 70%；检索头这类结构在推理期剪枝时很容易被剪坏（PDF p. 4）。
- **训练本身也要省**。长文档预训练、长上下文微调、强化学习都在拉长训练序列，只盯推理的方法对此无能为力（PDF p. 4）。

想把已有方法搬进训练，又会碰到两堵墙（PDF p. 4–5）：

- **挑选步骤不可导**。ClusterKV 的 k-means 聚类、MagicPIG 的 SimHash 都是离散操作，梯度流不过挑选这一步，模型学不会更好的挑法。
- **反向传播跑不快**。HashAttention 这类按单个 Token 挑选的方法，要从 KV Cache 里零散地读大量 Token，FlashAttention 依赖的连续读取与分块计算用不上，只能退回低利用率的实现。

于是矛盾变成：

> 挑选必须足够细，才能不漏掉关键信息；又必须足够粗、足够整齐，GPU 才跑得快；还必须能被训练，模型才能学会挑。NSA 要同时满足这三条。

## 先看全景：三条路读同一段历史

![NSA 让一个 Query 同时走压缩、选择、滑窗三条分支：压缩分支看全部历史的粗摘要，选择分支精读 16 个 64 Token 的块，滑窗分支看最近 512 个 Token，三路结果由门控加权相加。](/reports/NSA/figure2-three-branches.svg)

这张图按 PDF p. 3 Figure 2、p. 6–8 的式 (5)–(12) 与 p. 10 的超参重画，是机制示意。右侧的 Token 数按 64K 上下文算，三路合计与 PDF p. 14 Table 4 的 5632 一致。

总框架只有一个式子（PDF p. 6，式 3–5）：对每个 Query $\mathbf{q}_t$，不用原始的全部 Key 与 Value，而是按三种策略各构造一份更紧凑的 $\tilde{K}_t^c, \tilde{V}_t^c$，各算一次注意力，再加权相加：

$$
\mathbf{o}_t^{*} = \sum_{c \in \{\mathrm{cmp},\ \mathrm{slc},\ \mathrm{win}\}} g_t^c \cdot \mathrm{Attn}\bigl(\mathbf{q}_t,\ \tilde{K}_t^c,\ \tilde{V}_t^c\bigr)
$$

$c$ 取压缩（cmp）、选择（slc）、滑窗（win）三种；门值 $g_t^c \in [0, 1]$ 由输入特征过一个 MLP 再过 sigmoid 得到（PDF p. 6）。三路一共读 $N_t$ 个 Key，论文要求 $N_t$ 远小于 $t$，稀疏度就来自这里（PDF p. 6，式 6）。

注意这和把所有选中位置放进同一个 softmax 不一样：三条分支 **各自归一化**，再由门控按比例混合。

## 核心设计一：压缩分支，把全部历史折成摘要

### 旧问题：只挑块会漏掉没被挑中的地方

只要是挑选，就一定有没被挑中的历史。那部分信息要么全丢，要么得有一条通路以低成本「扫一眼」。

### 新设计：滑动窗口压缩，窗口互相重叠

把连续的 Key 按窗口切开，每个窗口用一个可学习的函数压成一个 Key（PDF p. 6，式 7）：

$$
\tilde{K}_t^{\mathrm{cmp}} = \Bigl\{\ \varphi\bigl(\mathbf{k}_{id+1\,:\,id+l}\bigr)\ \Bigm|\ 0 \le i \le \Bigl\lfloor \tfrac{t-l}{d} \Bigr\rfloor \Bigr\}
$$

- $l$ 是窗口长度，实验取 32；
- $d$ 是相邻窗口的步长，实验取 16（PDF p. 10）；
- $\varphi$ 是一个带块内位置编码的可学习 MLP，把窗口里的 $l$ 个 Key 映射成 1 个压缩 Key。Value 同理。

步长小于窗口长度，窗口就互相重叠。论文的理由是减少信息被切碎（PDF p. 6）。64K 上下文时，压缩分支大约要看 $65536/16 \approx 4096$ 个压缩 Token，仍然随长度线性增长，但系数只有全注意力的十六分之一。

### 收益与代价

收益是 Query 始终能看到全部历史的粗粒度语义，这是后面选择分支的打分来源。代价是引入了新参数 $\varphi$，NSA 因此不再是全注意力的「零参数替身」：同一套权重不能直接切回全注意力跑。

## 核心设计二：选择分支，分数是白捡的

### 为什么按块选，而不是按 Token 选

论文给了两个理由（PDF p. 7）：

- **硬件**：GPU 读连续内存比按下标零散读快得多；分块计算才能用满 Tensor Core。这也是 FlashAttention 分块设计的出发点。
- **注意力本身就成块**：已有工作发现注意力分数有空间连续性，相邻 Key 的重要程度往往相近。论文用自己 27B 全注意力模型的注意力图验证了这一点（PDF p. 15–16，Figure 8），并说正是这个观察促成了按块选择。

### 最关键的一步：块的重要性直接取自压缩分支

给每个块单独打分会带来额外开销。NSA 的办法是：压缩分支本来就要算 Query 对每个压缩 Key 的注意力分数，这些分数可以直接拿来当块的重要性（PDF p. 7，式 8）：

$$
\mathbf{p}_t^{\mathrm{cmp}} = \mathrm{Softmax}\bigl(\mathbf{q}_t^{\top} \tilde{K}_t^{\mathrm{cmp}}\bigr)
$$

![选择块的分数由与它重叠的压缩 Token 的注意力分数求和得到，同一 GQA 组内各头的块分数再相加，排名取前 16 块，全组共用一套块下标。](/reports/NSA/figure-score-reuse.svg)

这张图按 PDF p. 7 式 (8)–(10) 与 p. 8 式 (11)–(12) 重画，是机制示意。分三步：

1. **对齐切法**。选择块的长度记作 $l'$。压缩块与选择块切法相同（$l' = l = d$）时，分数一一对应，直接用；切法不同时，按空间重叠关系把压缩分数加到选择块上（式 9）。实验配置是 $l = 32$、$d = 16$、$l' = 64$，走的是后一种。
2. **组内求和**。对 GQA 或 MQA，同一组的头共用 KV Cache。为了让解码时只读一份，组内 $H$ 个头的块分数相加，得到一个共享分数（式 10）。
3. **取前 $n$ 块**。按共享分数排名，保留前 $n$ 块内的原始 Token，拼成选择分支的 Key 与 Value（式 11–12）。实验取 $n = 16$，其中写死了 1 个开头块和 2 个本地块（PDF p. 10）。

**我们如何解释它。** 选块这一步本身仍是不可导的排序，NSA 没有去硬造它的梯度。它做的是让挑选 **寄生在一个被主损失监督的量上**：压缩分支的输出直接进入最终结果，它的注意力分数就会被语言模型损失推着变准；分数变准，选块自然变准。这绕开了第 2.2 节说的两堵墙：不需要 k-means 那样的离散模块，也不需要额外的辅助损失。第 6.1 节的对照实验（后文）正好说明，另两种做法确实更差。

还要注意 $n = 16$ 里写死了开头块和本地块。**我们如何解释它。** 这相当于 attention sink 加局部窗口的结构先验。NSA 没有把「少结构」当原则，它的原则是：结构先验可以写死，只要写在块的粒度上、不妨碍训练和硬件效率。

### 可迁移启发

要在训练里做离散选择，先看系统里有没有一个 **已经被主损失监督、又便宜** 的中间量可以当打分。能复用，就同时省掉了打分开销和辅助损失。

## 核心设计三：滑窗分支，不让局部模式抄近路

### 旧问题：局部模式学得太快，会抢走学习信号

论文的观察是：局部模式适应得更快，会主导学习过程，让模型不去认真学压缩和选择两条路（PDF p. 8）。换句话说，如果局部信息也能从选择分支里拿到，模型会偷懒，只靠最近的几块把 loss 降下去。

### 新设计：单独一条滑窗分支，三路各用各的 K 与 V

- 滑窗分支只看最近 $w$ 个 Token，实验取 512（PDF p. 8、p. 10）；
- 三条分支的 **Key 与 Value 相互独立**，各自算注意力，最后由门控合并。论文说这样可以阻断局部与长程模式之间的梯度干扰，额外开销很小（PDF p. 8）。

**我们如何解释它。** 这是一个「给捷径单独修一条路」的思路：与其指望正则项压住局部模式，不如让它有专属通路，其余通路就只剩长程信息可学。代价是每条分支都要自己的 K、V 投影，参数和 KV Cache 都比单分支大；论文没有给出这部分开销的具体数字，也没有做「不独立 K、V」的消融。

## 硬件对齐：算子为什么按 GQA 组装 Query

### 训练、prefill 与解码的优化目标不同

论文先分清了两类瓶颈（PDF p. 5–6）：训练与 prefill 做的是批量矩阵乘，算术强度高，瓶颈在算力，目标是少算；解码每步只产出 1 个 Token 却要读完整个 KV Cache，算术强度低，瓶颈在带宽，目标是少读。NSA 的块选择加组内共享，同时照顾这两件事。

### 算子设计

压缩分支和滑窗分支本来就是规整的稠密注意力，直接用 FlashAttention-2 的算子。难的是选择分支（PDF p. 8）。

![照搬 FlashAttention 按连续位置装 Query 时，几个位置选的块互不相同，要读的是并集；NSA 按同一位置、同一 GQA 组的全部头装 Query，组内共用一套块，只读选中的那几块。](/reports/NSA/figure3-kernel.svg)

这张图按 PDF p. 8–9 的三条要点与 Figure 3 重画，是示意，不是实测。FlashAttention 的惯例是把时间上连续的一块 Query 装进 SRAM；可是在 NSA 里，相邻位置选的块各不相同，这一块 Query 要读的 KV 是并集，访存很低效（PDF p. 8）。NSA 换了分组方式（PDF p. 8–9）：

1. **按组装 Query**：每次装同一位置 $t$、同一 GQA 组的全部 $h$ 个头，它们共用块下标 $I_t$；
2. **共享取 KV**：内层循环按 $I_t$ 依次把连续的 KV 块装进 SRAM，算子块大小 $B_k$ 整除 $l'$；
3. **外层交给网格调度**：每个位置的内循环长度都约等于 $n$，几乎一样长，于是把 Query / 输出循环放进 Triton 的网格调度器。

论文的说法是，这样做既消除了冗余的 KV 读取，又让各个流多处理器的负载均衡，算术强度接近最优（PDF p. 9）。

**我们如何解释它。** 第 2.1 节批评 Quest「每头各选、GQA 下读并集」，式 (10) 的组内求和与这里的「按组装 Query」是同一件事的两面：算法层面规定组内选同样的块，算子层面才能把一次读取给 16 个头共用。选择的共享粒度与 KV 的共享粒度对齐，是 NSA 硬件对齐最核心的一条。

## 实验：从头预训练一个 27B MoE

### 设置

论文用的骨干是 GQA 加 MoE（PDF p. 9–10）：

| 项 | 取值 |
|---|---|
| 总参 / 激活 | 27B / 3B |
| 层数 / 隐藏维 | 30 / 2560 |
| 注意力 | GQA，4 组，共 64 个头；$d_q = d_k = 192$，$d_v = 128$ |
| MoE | DeepSeekMoE 结构，72 个路由专家 + 2 个共享专家，每 Token 激活 6 个；第一层换成 SwiGLU MLP |
| NSA 超参 | $l = 32$，$d = 16$，$l' = 64$，$n = 16$（含 1 个开头块、2 个本地块），$w = 512$ |
| 训练 | 8K 长度预训练 270B Token，再用 YaRN 在 32K 上继续训练与 SFT；两边都训到完全收敛 |

预训练 Token 数有一处不一致：引言写 260B（PDF p. 3），实验设置写 270B（PDF p. 10）。本文按实验设置取 270B。

Figure 4 的预训练 loss 曲线里，NSA 全程略低于全注意力，两者都平稳收敛（PDF p. 10）。

对照组分两类（PDF p. 10–11）：全注意力，以及四种推理期稀疏方法（H2O、InfLLM、Quest，以及先算完整注意力再取 top-n 的 Exact-Top）。通用评测的样本大多短于稀疏基线的本地窗口，基线此时等价于全注意力，所以只比 NSA 与全注意力；推理评测需要长文本 SFT，而稀疏基线不支持训练，也只比全注意力（PDF p. 11）。

| GSM8K（8-shot） | 0.486 | 0.520 |
| MATH（4-shot） | 0.263 | 0.264 |
| DROP（1-shot，F1） | 0.503 | 0.545 |

NSA 在 9 项里赢 7 项，DROP 高 0.042、GSM8K 高 0.034（PDF p. 11）。论文的解释是：稀疏预训练逼模型只看最重要的信息，可能滤掉了无关注意力路径带来的噪声（PDF p. 11）。

**我们如何解释它。** 这个解释是作者的推测，论文没有设计实验去验证「滤噪」。更稳妥的读法是：在这个规模和这组基准上，NSA 至少没有因为稀疏而掉点。差距最大的几项也只有几个百分点，只有一次训练，没有误差范围。

### 长上下文：唯一和同类稀疏方法正面比的地方

64K 的大海捞针（Needle in a Haystack）测试里，NSA 在所有长度与深度上都检索正确（PDF p. 11–12，Figure 5）。

LongBench 上，所有稀疏基线的每 Query 预算设成 2560 个 Token，对应 NSA 处理 32K 序列时的平均激活量；预算里包含开头 128 个与本地 512 个 Token；部分所有模型得分都很低的子集被剔除（PDF p. 12）。Table 2（PDF p. 11）：

| 方法 | MFQA-en | MFQA-zh | Qasper | HPQ | 2Wiki | GovRpt | Dur | PassR-en | PassR-zh | LCC | 平均 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| H2O | 0.428 | 0.429 | 0.308 | 0.112 | 0.101 | 0.231 | 0.208 | 0.704 | 0.421 | 0.092 | 0.303 |
| InfLLM | 0.474 | 0.517 | 0.356 | 0.306 | 0.250 | 0.277 | 0.257 | 0.766 | 0.486 | 0.143 | 0.383 |
| Quest | 0.495 | 0.561 | 0.365 | 0.295 | 0.245 | 0.293 | 0.257 | 0.792 | 0.478 | 0.135 | 0.392 |
| Exact-Top | 0.502 | 0.605 | 0.397 | 0.321 | 0.288 | 0.316 | 0.291 | 0.810 | 0.548 | 0.156 | 0.423 |
| 全注意力 | 0.512 | 0.623 | 0.409 | 0.350 | 0.305 | 0.324 | 0.294 | 0.830 | 0.560 | 0.163 | 0.437 |
| NSA | 0.503 | 0.624 | 0.432 | 0.437 | 0.356 | 0.307 | 0.341 | 0.905 | 0.550 | 0.232 | 0.469 |

NSA 平均 0.469，比全注意力高 0.032、比 Exact-Top 高 0.046；多跳问答 HPQ 与 2Wiki 分别高 0.087 与 0.051，代码 LCC 高 0.069，段落检索 PassR-en 高 0.075（PDF p. 12）。

**我们如何解释它。** 两件事值得分开看。第一，四种推理期稀疏方法都 **低于** 全注意力，其中连「先算完整注意力再取 top-n」的 Exact-Top 也低，这正好印证第 2.2 节的论点：拿一个没按稀疏训练过的模型事后稀疏，挑得再准也会掉点。第二，NSA **高于** 全注意力，这不是稀疏本身带来的，而是原生训练出来的模型在这组任务上更好。NSA 也不是全面领先：MFQA-en、GovRpt、PassR-zh 三项低于全注意力。

2560 这个预算怎么来的，论文没有展开。**本文推算**：32K 序列里，位置 $t$ 的 Query 读约 $t/16$ 个压缩 Token、1024 个选中 Token 与 512 个窗口 Token；对所有位置求平均，压缩部分约 $32768/2/16 = 1024$，合计 $1024 + 1024 + 512 = 2560$，与论文数字对得上。

### 长链推理：唯一一次后训练

为了看 NSA 能不能接住长链推理的后训练，论文从 DeepSeek-R1 蒸馏，用 10B Token、32K 长度的数学推理轨迹做 SFT，得到 Full Attention-R 与 NSA-R 两个模型（PDF p. 12）。论文说小模型上强化学习效果有限，所以这里只用蒸馏。评测是 AIME 24，温度 0.7、top-p 0.95、每题采样 16 次取平均，分 8K 与 16K 两个生成上限（PDF p. 12）。Table 3（PDF p. 13）：

| 生成上限 | 8192 | 16384 |
|---|---:|---:|
| Full Attention-R | 0.046 | 0.092 |
| NSA-R | 0.121 | 0.146 |

8K 时高 0.075，16K 时高 0.054（PDF p. 13）。附录 A 给了两道题的完整输出：第一题 NSA-R 用 2275 个思考 Token 答对 33，基线用了 9392 个、答成 131；第二题 NSA-R 用 15147 个答对 25，基线用了 16223 个、答成 45/2（PDF p. 21–25）。

**我们如何解释它。** 两个模型的绝对分都很低（3B 激活的模型做 AIME），差距来自每题 16 次采样的平均，而 AIME 24 一共只有 30 道题（题数是外部常识，论文没写）。方向是清楚的，幅度要谨慎读。附录的两个样例是挑出来的展示，不是统计证据。

## 效率：分清实测与估算

![在 8K 到 64K 上，NSA 注意力算子的前向与反向实测加速随长度增大，64K 时分别为 9.0 倍与 6.0 倍；解码的 11.6 倍是按读取 Token 数估算的。](/reports/NSA/figure6-speed.svg)

测试环境是 8 卡 A100，配置沿用实验设置：GQA 组数 4、每组 16 个头、$d_k = 192$、$d_v = 128$，NSA 超参同上（PDF p. 13）。

### 训练：前向与反向是实测

对照是 **Triton 版的 FlashAttention-2**，与 NSA 的 Triton 实现同一后端，避免编译器差异混进来（PDF p. 13）。加速比随长度增大，64K 时前向 9.0 倍、反向 6.0 倍（PDF p. 13，Figure 6）。论文把原因归到两点：块状访存让 Tensor Core 满载，循环调度消除了冗余的 KV 读取（PDF p. 14）。

**我们如何解释它。** 这是注意力算子的时间，不是整模型每步训练时间。在一个 3B 激活的 MoE 里，MoE 层与其他层的耗时不变，端到端训练能快多少，论文没有给。短序列上优势很小：8K 时反向只快 1.1 倍。

### 解码：11.6 倍是按访存量算出来的

解码受带宽限制，每步耗时约与读取的 KV 量成正比。NSA 每步最多读 $\lfloor (s-l)/d \rfloor$ 个压缩 Token、$n l'$ 个选中 Token 与 $w$ 个窗口 Token，$s$ 是已缓存的长度（PDF p. 14）。Table 4（PDF p. 14）：

| 上下文长度 | 8192 | 16384 | 32768 | 65536 |
|---|---:|---:|---:|---:|
| 全注意力读取量 | 8192 | 16384 | 32768 | 65536 |
| NSA 读取量 | 2048 | 2560 | 3584 | 5632 |
| 预期加速 | 4× | 6.4× | 9.1× | 11.6× |

表题写的是「预期加速」（expected speedup），并说明加速约与访存量成线性关系（PDF p. 14）。**我们如何解释它。** 这是估算，不是在真实服务里量出来的延迟；Figure 1 右图把 11.6 倍和两个实测倍数画在一起（PDF p. 2），读图时容易当成同一类证据。还要注意：长度越长，压缩分支的 $s/16$ 占比越大，NSA 的读取量仍随长度线性增长，只是斜率是全注意力的十六分之一，加上一个 1536 的常数。

## 作者试过又放弃的路

第 6.1 节交代了设计 NSA 之前的尝试（PDF p. 14–15），这是理解「为什么是现在这个样子」的最好材料。

**基于 Key 聚类**（如 ClusterKV）：把同一簇的 Key 与 Value 放进连续内存。理论上训练和推理都可行，但有三个问题：动态聚类本身开销不小；簇之间大小不均，给算子优化添乱，在 MoE 系统里还会让专家并行各组的执行时间失衡；还必须周期性重新聚类、按块顺序训练（PDF p. 14）。

**其他按块选择的办法**：两类在 3B 模型上与 NSA、全注意力比了训练 loss（PDF p. 15，Figure 7）。

- **带辅助损失的可学习选择**：给每个 Token 加额外的 Query、给每个块加代表 Key 来估计块重要性；监督信号是块内注意力分数的均值，用 KL 散度去拟合。思路与 SeerAttention 相近。
- **无参数的启发式选择**：照 Quest 的办法，用 Query 与块内 Key 逐坐标 min、max 的乘积打分；另试了前 1000 步先用全注意力「冷启动」再切到启发式选择。

两种方法的 loss 都比 NSA 差（PDF p. 15）。论文给的原因是：前者的辅助损失增加算子开销、常常伤效果；后者召回率低（PDF p. 15）。

**我们如何解释它。** 这三条弯路正好对应 NSA 的三个设计：不要离散聚类（改成按固定位置分块），不要辅助损失（改成复用压缩分数），不要无参数的粗糙打分（改成可学习的压缩分支）。Figure 7 只有 3B 规模的 loss 曲线，没有下游评测，也没有给出几条曲线的最终数值。

## 与同期方案的关系

### MoBA：同一周公开的另一条块稀疏路线

Moonshot 的 MoBA 在 2025-02-18 公开，比 NSA 的 arXiv v1 晚两天，与 DeepSeek 官方发文介绍 NSA 是同一天（出处见文末）。两份原件互相没有引用。下面的对照是本文按两份原件整理的，细节见 MoBA 一篇。

| | NSA | MoBA |
|---|---|---|
| 挑块的分数 | 复用可学习压缩分支的注意力分数 | Query 与块内 Key 均值的内积，零参数 |
| 写死的通路 | 开头块、本地块、512 滑窗 | 只有当前块 |
| 全局摘要 | 有，压缩分支 | 没有 |
| 合并方式 | 三路各自注意力，门控加权 | 选中块同进一个 softmax |
| 能否切回全注意力 | 不能直接切，多了参数 | 能，参数完全相同 |
| 选择在头之间 | GQA 组内共享 | 每头各选 |
| 实验 | 从头预训练 27B MoE | 从头训小模型，续训 Llama 3.1 8B |

**我们如何解释它。** 两边都是「先粗挑块，再精读原文」。NSA 押注在「挑选要被训练、要和 KV 共享对齐」，因此付出新参数与不可逆的代价；MoBA 押注在「零参数、随时可退」，因此挑选信号更粗、也没有针对 GQA 解码的设计。

### 论文之后

以下是外部资料与站内其他篇的记述，不是这份 PDF 的内容。

- DeepSeek-V3.2 的 DSA（见 DeepSeek-V3.2 一篇）没有沿用 NSA 的三分支，改成一个轻量的闪电索引器逐 Token 打分、主注意力只读前 2048 个位置，并建在 MLA 的 MQA 模式上。V3.2 报告在说明「每个 KV 条目必须被多个 Query 共享」时引用了 NSA；这正是本文所说「选择的共享粒度与 KV 的共享粒度对齐」那一条。
- MiniMax 的 MSA（见 MiniMax-Sparse-Attention 一篇）回到块级选择，在 GQA 上按组共享 top-k，并用 KL 训练一个纯选择器。
- 块级还是 Token 级、选择在多少个头之间共享、选择器靠什么信号学，这三个旋钮在 NSA 之后被反复重新定价。

## 限制、边界，以及不要补进去的实现

- **只有一个规模、一套超参**。没有消融三条分支各自的贡献，没有扫 $l$、$d$、$l'$、$n$、$w$，也没有扫门控设计。
- **没有其他可训练稀疏方法的同条件对比**。LongBench 的对手全是推理期稀疏；第 6.1 节的两种可训练选择只有 3B 的 loss 曲线。
- **速度是算子级的**。前向、反向是实测的注意力算子时间；解码 11.6 倍是按读取量估算；整模型训练吞吐与真实服务延迟都没有给。
- **三分支的额外开销没有量化**。独立的 K、V 投影、压缩 MLP、门控 MLP 带来多少参数和多大 KV Cache，论文没有写。
- **长链推理只做了蒸馏 SFT**。没有强化学习，AIME 只有两个生成长度、30 道题。
- **官方没有开源实现**。论文说用 Triton 实现了算子，但 DeepSeek 没有放出 NSA 的代码或权重。
- **一处数字不一致**：预训练 Token 数 260B（p. 3）与 270B（p. 10）。

## 可迁移启发

1. **让离散决策寄生在被主损失监督的中间量上**。NSA 不去造选块的梯度，而是复用压缩分支的注意力分数。压缩分支学得越好，选块就越准。自己设计路由、检索、剪枝时，先找系统里现成的、被监督的打分。
2. **选择的共享粒度要与存储的共享粒度对齐**。KV 按 GQA 组共享，选择就按组共享；否则计算省了、访存没省。
3. **稀疏的单位要让硬件满意**。按连续块选，才能喂满 Tensor Core、做到合并读取；按单 Token 选，理论再省也可能跑不快。
4. **给容易抄近路的信号一条专属通路**。局部模式学得快，就单独给它一条滑窗分支、单独的 K 与 V，别的分支才学得到长程信息。
5. **分清训练、prefill、解码三种瓶颈**。前两者算力受限，要少算；解码带宽受限，要少读。一个稀疏方案只照顾其中一种，在另一种负载下就吃不到加速。
6. **报加速比时写清口径**。算子实测、整模型实测、按访存量估算是三类不同的证据，放在同一张柱状图里会被读成同一类。

## 关键词回看

- **原生可训练**：从预训练第一步就用稀疏注意力，挑选链路与模型一起训练。
- **压缩 / 选择 / 滑窗**：三条分支，分别看全局摘要、精读挑中的块、盯住最近一段；各用各的 K、V，由 sigmoid 门加权。
- **$l = 32$，$d = 16$**：压缩窗口长 32、步长 16，窗口互相重叠。
- **$l' = 64$，$n = 16$**：选择块长 64，取 16 块，含开头 1 块与本地 2 块。
- **$w = 512$**：滑窗长度。
- **分数复用**：选择块的重要性由压缩分支的注意力分数按重叠关系求和而来（式 9）。
- **组内共享**：同一 GQA 组的头把块分数相加，共用一套块下标（式 10）。
- **按组装 Query 的算子**：外层网格按位置排，内层按选中块顺序读连续 KV。
- **9.0× / 6.0× / 11.6×**：64K 时注意力算子前向、反向的实测加速，以及按访存量估算的解码加速。
- **2560**：LongBench 上给稀疏基线的每 Query 预算，等于 NSA 在 32K 序列上的平均读取量。
