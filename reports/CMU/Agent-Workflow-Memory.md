# AWM：把做对的轨迹收成带槽位的工作流写进记忆，网页 agent 越做越会

<!-- release-date: 2024-09-11 -->

> 本文依据 **Agent Workflow Memory** 的 ICML 2025 正式版（Proceedings of the 42nd International Conference on Machine Learning，PMLR 267），共 15 页，作者 Zora Zhiruo Wang、Jiayuan Mao、Daniel Fried、Graham Neubig；Wang、Fried、Neubig 署 Carnegie Mellon University，Mao 署 Massachusetts Institute of Technology（PDF p. 1）。页码均指这份 PDF 自身的页码。文中区分三件事：**论文明确写了什么**（带页码）、**我们怎么解释或验算它**（会写明）、**外部资料补充**（给出处并标注）。

## 读前先把几个词说成人话

这篇论文只回答一个问题：网页 agent 做长程任务时，过去做过的题该以什么形式留在记忆里。

先把后面反复出现的词说清楚：

- **网页导航 agent**：给一句自然语言指令，让语言模型在网站上逐步点击、填写、滚动，直到发出停止动作。每走一步，页面变一次（PDF p. 2）。
- **经验（experience）**：做完一道题留下的东西，包括指令和一条轨迹；轨迹的每一步是「当时看到的页面 + 当时发出的动作」（PDF p. 2）。
- **工作流（workflow）**：从经验里抽出的可复用小套路。它不是「在 Amazon 买干猫粮送到我家」这种整道题，而是「在 Amazon 搜一个商品」这种会在很多题里反复出现的子任务；具体值被换成 `{product-name}` 这样的槽位（PDF p. 3）。
- **记忆（memory）**：论文里就是系统提示或主提示里的一段辅助文本，默认只写着 `CLICK`、`TYPE` 这类内置动作的说明（PDF p. 2，脚注 2）。AWM 往里加的，就是工作流。
- **离线 / 在线**：有标注好的训练示范时，先从训练集一次性归纳出工作流、测试时不再变，叫离线；没有示范时，一边做测试题、一边从自己做对的题里归纳，叫在线（PDF p. 3）。
- **WebArena / Mind2Web**：两个网页导航基准。WebArena 有 812 道题、5 个网站，按执行结果判对错（PDF p. 4）；Mind2Web 每道题的步数固定，逐步判「选的元素对不对、动作对不对」，强调跨任务、跨网站、跨领域（PDF p. 5）。
- **逐步成功率（step SR）/ 任务成功率（SR）**：Mind2Web 上前者看「这一步元素和动作都对」，后者看「这道题每一步都对」（PDF p. 5）。摘要里的 24.6% 是前者的相对提升。

这篇论文里模型权重从头到尾没有动：没有 SFT，没有 RL。变的只是提示里的那份记忆。

## 一句话先说清

2024 年的网页 agent 大多靠两种方式吸收过去的经验：拿示范去训练，或者把整条示范原样塞进上下文。论文认为两者都在记「那一次点了哪里」，没有记「这类事一般怎么做」，所以任务一变、网站一变就不灵，而且每道题都是从零开始，做过的题不会让下一道变容易（PDF p. 1）。

AWM 的做法是：**把做成功的轨迹交给同一个语言模型，让它抽出跨题复用的子程序、把具体值换成槽位，存进记忆；下一道题带着这份记忆做**（PDF p. 3）。在线模式下，这个循环在测试流上一直转，记忆越滚越大：

![Figure 1 是 WebArena 地图站上的在线运行：横轴是已做的题数，纵轴是累计成功率；AWM 这条线在前几十道题里依次学会「按名字找地点」「找附近咖啡馆」「取地点坐标」「查邮编」「查驾车时间」等工作流，迅速升到 40% 上下，基线始终在 20% 以下徘徊，40 道题后两者差距拉到 22.5 个百分点。](/reports/Agent-Workflow-Memory/fig1-snowball.png)

图引自原文 Figure 1（PDF p. 1）。图上的节点就是被学会的工作流，后学的常常把先学的当作前几步（后文 Figure 5 专门讲这件事）。论文把这叫「滚雪球」（PDF p. 2）。

主结果有两组，口径要先对齐：

- **WebArena**（只做在线）：总成功率 35.5%，比当时最强的公开自主方法 BrowserGym（23.5%）高 12.0 个百分点、相对 +51.1%；还略高于用 14 条人写工作流的 SteP（33.0%）（PDF p. 4–5，Table 1）。
- **Mind2Web 跨任务**（离线，gpt-4）：逐步成功率 45.1%，比 MindAct 的 36.2% 高 8.9 个百分点、相对 +24.6%；任务成功率只有 4.8%（PDF p. 6，Table 3）。

论文还宣称在跨网站、跨领域上「比基线高 8.9 到 14.0 个百分点，分布差越大优势越大」（PDF p. 1–2）。正式版的表格对不上这句话，后文「跨网站与跨领域」一节单独对账。

## 主要矛盾：示范记住的是那一次点击

论文开场给的矛盾很具体（PDF p. 1）：

- 现有 agent 把一组固定示范拿去训练或放进上下文。**遇到和示范很像的动作序列时表现不错，任务上下文或环境一变就不稳**。原因是示范里的具体值、具体元素和这道题绑死了，agent 没学会把复杂任务拆成跨题共享的小套路。
- agent 一道一道地独立解题，**做成功的、做失败的都不会留下来**，所以没法随时间变好。

人话版：新员工拿到一本「上周三张三处理 0130 号订单的完整录屏」，下次遇到 0131 号订单，他只能在录屏里找相似的画面照做；老员工记住的是「查订单：先点 Orders，再按编号找到那一行」。前者换个订单号就容易点错，后者可以用在所有订单上。

所以要回答的是：

> 不改权重，只改记忆，能不能让 agent 从自己的经验里攒出「这类事一般怎么做」，并且越做越多、越做越准？

## 先看全景：一条轨迹怎么变成记忆

![Figure 2 画出 AWM 的一圈：环境给出页面状态，agent 以语言模型为骨干、带着记忆输出动作；第一步得到一条动作轨迹（可以是人标的，也可以是模型自己生成的），第二步判断这道题是否做对，做对的轨迹进入第三步归纳成工作流——由描述和逐步的环境描述、推理、动作组成——再写回记忆，做错的直接丢掉。](/reports/Agent-Workflow-Memory/fig2-pipeline.png)

图引自原文 Figure 2（PDF p. 3）。它和正文的形式化是一一对应的（PDF p. 2–3）：

- agent 由语言模型 $L$ 和文本记忆 $M$ 组成，每一步按 $L(q, M, o_i) \to a_i$ 出动作，$q$ 是指令，$o_i$ 是当前观察；
- 归纳模块 $I$ 吃进一组经验 $\mathcal{E}$，吐出一组工作流：$I(\mathcal{E}) \to \mathcal{W}$；
- 工作流并进记忆：$M + \mathcal{W} \to M_w$，之后按 $L(q, M_w, o) \to a$ 出动作。

离线和在线只差在「经验从哪来、记忆何时更新」（PDF p. 3，Figure 3）：

| | 离线 AWM | 在线 AWM |
|---|---|---|
| 经验来源 | 额外的训练示范（人标或模型合成） | 只有测试题，经验是 agent 自己做出来的轨迹 |
| 归纳时机 | 测试前一次性：把一个网站的全部训练示范拼进一个提示，归纳出 $\mathcal{W}_{\text{offline}}$ | 每做完一道测试题，判为成功就立刻归纳并写入 |
| 测试时记忆 | 固定不变，每道题用同一份 | 第 $t$ 道题用 $M^t$，做完变成 $M^{t+1}$ |
| 谁判「做对了」 | 示范默认是对的 | Pan 等人 2024 的语言模型评判器，输出 0 或 1 |

两个基准都**按网站分组**各跑一份 AWM：每个网站维护一份小的工作流集合，只放和本站相关的套路（PDF p. 4）。

## 核心设计一：工作流的格式，决定它能不能被复用

### 旧问题：整条示范太具体

整条示范里有两类「只属于这道题」的东西：一是具体值（「dry cat food」、订单号 0130），二是整道题的粒度（「买猫粮并寄到我家」这种组合几乎不会原样再出现）（PDF p. 3）。把它们原样放进上下文，agent 会被带着去选和示范里相似的元素，而不是当前页面上正确的那个（PDF p. 6）。

### 新设计：子任务粒度、槽位抽象、三段式步骤

一个工作流由两部分组成（PDF p. 2–3）：

1. **描述 $d$**：一句话说清这个工作流的功能，比如「找到指定编号的客户订单」；
2. **轨迹**：若干步，每步三段——当前页面状态的自然语言描述（「Order {id} is shown」）、据此做决定的推理（「订单已找到，结束任务」）、一条可执行的动作程序（`stop()`）。

归纳由同一个语言模型完成。附录 A 给出的提示词只有五句，要点是（PDF p. 11）：

- 找出多道题之间**重复出现的动作子集**，每个抽成一个工作流；
- 每个工作流是常用子程序，**不要生成相似或重叠的工作流**；
- **每个工作流至少两步**；
- 输入文本、按钮文字这类不固定的成分，用描述性变量名代替。

模型输出按空行切开，每段存成一条工作流（PDF p. 3）。附录 A.2 给了实例：WebArena 地图站的「计算两地行程时间与距离」是填起点、填终点、选交通方式、点查询、把结果回报给用户五步；Mind2Web 购物域的「搜索并排序」是在 Amazon 搜索框输入 `{search-term}`、点 Go、点排序、选 `{sort-option}`（PDF p. 12）。

### 工作机制：为什么抽象之后反而选得更准

论文拿 Mind2Web 离线结果对比 Synapse 来说明（PDF p. 6，Table 3）。Synapse 检索最相似的完整训练示范放进上下文；AWM 放的是工作流。同为 gpt-3.5-turbo，AWM 的元素准确率高 5.0 个百分点（39.0 对 34.0），逐步成功率高 4.0 个百分点（34.6 对 30.6）。作者给的解释有两层：

- 完整示范会让 agent **偏向选和示范里相似的元素**；工作流把具体值抽掉了，这种偏差小；
- 子程序会在很多测试题里反复用上，完整轨迹则很少原样重现。

提升主要落在元素选择上：两档模型的元素准确率分别高 5.0 和 9.0 个百分点（PDF p. 6）。

### 代价：agent 不太会离开工作流

元素选得更准，**动作 $F_1$ 反而略低于 MindAct**（gpt-4 下 57.3 对 60.6）（PDF p. 6，Table 3）。论文的解释是：工作流会引导 agent 做符合套路的动作，但套路不总适用于当前页面，agent 还没学会在哪一步该偏离指南（PDF p. 6）。任务成功率依然很低（最高 4.8%），说明「每一步都对」这件事远没解决。

### 可迁移启发

把 agent 日志当 few-shot 之前，先做两件事：把订单号、商品名、元素 id 这类值换成槽位；把整题切成跨题复用的子任务。记忆的单位选子程序，不选整段录屏。

## 核心设计二：在线雪球，只让做对的轨迹进门

### 旧问题：没有示范时，经验从哪来

高质量、和测试同分布的示范往往拿不到（PDF p. 3）。WebArena 只有测试题，没有额外的领域示范，所以在 WebArena 上只能跑在线（PDF p. 4）。

### 新设计：评判器当门卫

在线模式里，agent 从只有内置动作说明的默认记忆出发，按顺序做测试题；每做完一道，用 Pan 等人 2024 的语言模型评判器给轨迹判 0 或 1，**只有判为成功的轨迹才被归纳成工作流**并加进记忆，供下一道题使用（PDF p. 3）。

### 工作机制：新工作流踩在旧工作流上

![Figure 5 左边是早期学到的「按名字找地点」：任务目标是在地图上显示某地，轨迹是在 OpenStreetMap 搜索框填入地名再点搜索；右边是后来学到的「查某地邮编」：前两步直接沿用左边的填写与点击，再加上读取搜索结果、把邮编回报给用户的步骤。](/reports/Agent-Workflow-Memory/fig5-compose.png)

图引自原文 Figure 5（PDF p. 5）。在线过程早期，agent 从几道题里总结出「按名字找地点」；后来遇到「查某地邮编」，它先照已有工作流走完前几步，再多做几步拿到邮编，于是长出一条更复杂的新工作流（PDF p. 5）。这就是 Figure 1 里那串节点的来历：简单套路先进门，复杂套路建在简单套路之上。

### 收益：几十道题就够

在线运行时，论文按「前 $k$ 道已完成题的平均成功率」画累计曲线（PDF p. 4，Figure 4）。地图站上，前约 40 道题是快速学习段，agent 攒下最基本的工作流，成功率迅速上升；之后进入稳定段，继续学更复杂的工作流，成功率稳定在早期达到的最高点附近（PDF p. 4）。和基线的差距在 40 道题之后拉到 22.5 个百分点（PDF p. 1–2，Figure 1）。

### 代价与边界

- **门卫错判会写进记忆**。论文自己指出，在线归纳用的是模型预测的轨迹，并不总是对的，可能产出错误的工作流、拉低表现（PDF p. 6）。论文没有报告评判器在这些基准上的准确率。
- **雪球要先滚起来**。在线只收成功轨迹，基座前几十道题如果都做不对，就没有工作流可收。论文展示的是地图站上滚得起来的曲线，没有讨论冷启动失败的情形。
- **题目顺序影响不大，但样本很少**。附录 E 在 Mind2Web 跨任务上比较原顺序、随机打乱、按步数由易到难、由难到易四种顺序，逐步成功率在 45.1–45.9 之间（PDF p. 14，Table 12）。作者认为子任务粒度让工作流不依赖题目先后，但也承认每个网站不到 20 道题，这个结论未必能推广到更大的数据集（PDF p. 14）。

### 可迁移启发

让 agent 从自己的经验里长记忆，门卫的质量就是记忆的质量。规则能验证的地方用规则；必须用模型评判时，要预期错判会以工作流的形式留下来。

## WebArena：35.5%，差距集中在按网站拆开看

### Table 1：主结果

WebArena 的基线是 BrowserGym（当时不用人工网站知识的最好方法）。BrowserGym 同时输入网页 HTML 和可访问性树，AWM 只用可访问性树，所以论文另跑了一版只看可访问性树的 BrowserGym 作为同口径对照；SteP 用了 14 条专家为 WebArena 写的工作流，是「有人工监督」的参照（PDF p. 4）。

|---|---:|---:|---:|---:|---:|---:|---:|
| SteP（人写工作流） | 33.0 | 37.0 | 24.0 | 59.0 | 32.0 | 30.0 | — |
| WebArena 原始 agent | 14.9 | 14.0 | 11.0 | 6.0 | 15.0 | 16.0 | — |
| AutoEval | 20.2 | 25.5 | 18.1 | 25.4 | 28.6 | 31.9 | 46.7 |
| BrowserGym | 23.5 | — | — | — | — | — | — |
| BrowserGym（只用可访问性树） | 15.0 | 17.2 | 14.8 | 20.2 | 19.0 | 25.5 | 7.9 |
| **AWM** | **35.5** | 30.8 | 29.1 | 50.9 | 31.8 | **43.3** | **5.9** |

数据引自原文 Table 1（PDF p. 5）。读表要知道三件事：

1. **相对提升的基准是 BrowserGym 的 23.5**：35.5 − 23.5 = 12.0，35.5 / 23.5 ≈ 1.511，即 +51.1%（PDF p. 4）。同口径的「只用可访问性树」版本只有 15.0，AWM 相对它高 20.5 个百分点。
2. **赢 SteP 是总分上的小幅领先**：35.5 对 33.0，相对 +7.6%（PDF p. 4）。按网站拆开，SteP 在 Shopping（37.0 对 30.8）和 Reddit（59.0 对 50.9）上更高；AWM 的优势主要来自 Maps（43.3 对 30.0）和 CMS（29.1 对 24.0）。
3. **步数更少**：平均 5.9 步，比只用可访问性树的 BrowserGym 少 2.0 步；AutoEval 需要额外的评估与修正步骤，平均 46.7 步，AWM 比它少 40.8 步（PDF p. 4）。

WebArena 用的模型与温度：正文写 GPT-4o（`gpt-4o-2024-05-13`）、温度 0（PDF p. 4）；Table 1 与 Table 5 的表注写的是 `gpt-4`（PDF p. 5、p. 7）。正式版内部没有统一，这组数出自哪个模型，只能按正文理解为 GPT-4o。

### Table 2：跨模板子集，不是在同一道题的复制上刷分

WebArena 的很多题是从同一个任务模板实例化出来的，同模板题的标准轨迹高度重叠。学会一条工作流，同模板的其余题自然更容易（PDF p. 4）。为排除这种「模板内红利」，作者按模板分组、每组随机留一道，得到跨模板子集（PDF p. 5）：

| 方法 | 总成功率 | Shopping（51） | CMS（45） | Reddit（24） | GitLab（45） | Maps（32） |
|---|---:|---:|---:|---:|---:|---:|
| SteP（人写工作流） | 32.1 | 26.5 | 29.3 | 52.2 | 27.3 | 36.4 |
| AutoEval | 23.2 | 12.2 | 17.1 | 21.7 | 31.8 | 36.4 |
| BrowserGym（只用可访问性树） | 20.5 | 10.4 | 17.8 | 23.1 | 27.3 | 28.6 |
| **AWM** | **33.2** | 24.5 | 29.3 | 52.2 | 31.8 | 39.4 |

数据引自原文 Table 2（PDF p. 6），括号里是各站题数。总分上 AWM 仍然最高，在自主方法里全面领先或持平。论文写的是「在总分和每个网站上都最高」（PDF p. 5），但表上 Shopping 一列 SteP 更高（26.5 对 24.5），CMS 和 Reddit 与 SteP 打平，GitLab 与 AutoEval 打平。

**我们如何解释它**。 跨模板子集把「模板内复用」这条最便宜的收益去掉之后，AWM 的领先幅度基本保住了，这比主表更能说明学到的是跨题套路。但子集每站只有 24–51 道题，单站差一两道就是几个百分点，逐站排名不宜细读。

## Mind2Web：24.6% 是逐步成功率

### Table 3：离线跨任务

Mind2Web 提供覆盖部分测试网站的训练集，所以跨任务那一档可以跑离线（PDF p. 5）。对照是 MindAct（网页元素过滤 + 多选题格式）和 Synapse（轨迹格式 + 检索相似示范）；AWM 沿用两者都用的元素过滤，把 Synapse 的检索示范换成工作流。两档模型都是温度 0，归纳和解题用同一个模型（PDF p. 5）。

| 方法 | 元素准确率 | 动作 $F_1$ | 逐步成功率 | 任务成功率 |
|---|---:|---:|---:|---:|
| MindAct（gpt-3.5） | 20.3 | 56.6 | 17.4 | 0.8 |
| CogAgent（gpt-3.5） | — | — | 18.6 | — |
| Synapse（gpt-3.5） | 34.0 | — | 30.6 | 2.4 |
| **AWM（gpt-3.5）** | **39.0** | 52.8 | **34.6** | **2.8** |
| MindAct（gpt-4） | 41.6 | **60.6** | 36.2 | 2.0 |
| **AWM（gpt-4）** | **50.6** | 57.3 | **45.1** | **4.8** |

数据引自原文 Table 3（PDF p. 6）。逐步成功率的提升是 4.0 和 8.9 个百分点，任务成功率的提升是 0.4 和 2.8 个百分点。45.1 / 36.2 ≈ 1.246，就是摘要里的 24.6%，引言也写明它指逐步成功率（PDF p. 2）。正文在这里把 4.0–8.9 写成「相对百分比」（PDF p. 5–6），按表算它们是绝对百分点。

### 跨网站与跨领域：正式版改了表，没改结论句

在线模式只需要测试题，天然可以测跨网站、跨领域。离线在这两档没有同站示范，就从训练集随机挑工作流：跨网站挑同领域的，跨领域从全部领域里挑（PDF p. 6）。

| 方法 | 跨任务 逐步 / 任务 | 跨网站 逐步 / 任务 | 跨领域 逐步 / 任务 |
|---|---:|---:|---:|
| MindAct（Table 4） | 36.2 / 2.0 | 30.1 / 2.0 | 26.4 / 2.0 |
| MindAct（Table 10） | 36.2 / 2.0 | 30.1 / 2.0 | 18.6 / 1.0 |
| 离线 AWM | 45.1 / 4.8 | 33.7 / 2.3 | 32.6 / 0.7 |
| 在线 AWM | 43.6 / 4.0 | 33.9 / 1.6 | 35.5 / 1.7 |

数据引自原文 Table 4（PDF p. 7）与 Table 10（PDF p. 13），均为 gpt-4；两表的 AWM 行完全相同，只有 MindAct 跨领域一格不同。

问题就出在这一格。正文说两种 AWM 在三档上分别提升「7.4–8.9、3.6–3.8、14.0–16.9 个百分点」（PDF p. 6），摘要说「8.9 到 14.0 个百分点」（PDF p. 1）。跨领域的 14.0 与 16.9 正好是 32.6 − 18.6 与 35.5 − 18.6，也就是按 Table 10 的基线算的；按正文主表 Table 4 的 26.4 算，跨领域提升只有 6.2 与 9.1 个百分点，比跨任务那一档还小。正式版没有说明哪一格是对的。

**我们如何解释它**。 不论取哪个基线，下面几条都成立：

1. **跨网站那一档提升最小**（3.6–3.8），摘要的「8.9 到 14.0」跳过了它，「分布差越大优势越大」并不是单调的。
2. **分布差越大，在线越占优**：跨任务上离线略好（45.1 对 43.6），跨网站两者持平，跨领域在线明显更好（35.5 对 32.6）。论文的解释是在线只用测试题和测试环境，归纳出的工作流天然贴近测试分布；离线在同分布、高质量示范存在时才更有利（PDF p. 6–7）。
3. **任务成功率几乎没有提升**：跨领域离线只有 0.7%，低于 MindAct；三档里任务成功率都在 5% 以下。逐步准确率的提升还没有传导到整题做成。

## 表示消融：功劳在「抽象子程序」，不在代码格式

第 4 节把工作流的表示方式拆开做了三组对照（PDF p. 7–8）。

**规则归纳对 LM 归纳**。规则版不做抽象，只做两件事：按动作序列（如 CLICK → CLICK → TYPE）给经验去重，每组随机留一条；再删掉参数不合法、无法执行的 CLICK 与 TYPE 步骤，剩下的整条经验就当工作流（PDF p. 7、p. 13）。

| 基准 | 方法 | 元素准确率 | 动作 $F_1$ | 逐步成功率 | 任务成功率 / 总成功率 | 平均步数 |
|---|---|---:|---:|---:|---:|---:|
| WebArena | 规则归纳 | — | — | — | 35.6 | 6.3 |
| WebArena | LM 归纳 | — | — | — | 35.5 | 5.9 |
| Mind2Web | MindAct | 41.6 | 60.6 | 36.2 | 2.0 | — |
| Mind2Web | 规则归纳 | 49.5 | 57.0 | 43.4 | 2.0 | — |
| Mind2Web | LM 归纳 | 50.6 | 57.3 | 45.1 | 4.8 | — |

数据引自原文 Table 5、Table 6（PDF p. 7）。WebArena 上两者总分只差 0.1，LM 版少走 0.4 步；人工检查发现 LM 归纳的工作流更细，能避开规则版里偶尔带着的多余步骤（PDF p. 7）。Mind2Web 上规则版已经把逐步成功率抬到 43.4，但任务成功率与 MindAct 持平，LM 版才把它提到 4.8。

**我们如何解释它**。 规则版本质是「去重后的完整示范」，已经能拿到大部分逐步收益；抽象成子程序的价值主要体现在整题做成上。WebArena 上两者几乎一样，说明在执行式评测里，「只收做成功的轨迹、按网站分组」这两个设计本身就贡献了大头。

**代码格式对文本格式**。把工作流里的动作程序用 gpt-3.5-turbo 改写成自然语言（`CLICK({submit-id})` 改成「点击提交按钮」），元素准确率和逐步成功率略升 0.6 和 0.3，任务成功率降 1.2（PDF p. 8，Table 7）。论文的结论是两种格式都有效，没有实质差别。

**要不要在工作流里贴网页 HTML**。用 gpt-3.5-turbo 比较三种状态表示（PDF p. 8，Table 8）：

| 状态描述 | 过滤后的 HTML | 元素准确率 | 动作 $F_1$ | 逐步成功率 | 任务成功率 |
|---|---|---:|---:|---:|---:|
| 有 | 无 | 39.0 | 52.8 | 34.6 | 2.8 |
| 无 | 有 | 38.1 | 54.0 | 33.8 | 2.8 |
| 有 | 有 | 37.1 | 51.3 | 32.9 | 2.0 |

两样都给反而最差。作者的两个推测：上下文变长，模型更难处理；过滤后的 HTML 里无关元素很多，47% 的情况下连一个正确元素都没留下，和自然语言描述互相矛盾（PDF p. 8）。

**可迁移启发**。记忆里写「现在页面是什么状态」用一句人话就够，别贴一段不可靠的原始结构；贴错比不贴更糟。

## 附录里要记的几件事

### 工作流质量：每站七条左右，几乎都用得上

附录 A.3 用四个指标检查归纳出的工作流（PDF p. 12–13，Table 9）：

| 基准 | 工作流数 | 覆盖率 | 功能重叠 | 使用率 |
|---|---:|---:|---:|---:|
| WebArena | 7.4 | — | 0.08 | 0.94 |
| Mind2Web | 7.3 | 0.40 | 0.20 | 0.91 |

论文报告的工作流数是 7.3–7.4 条（原文口径写作「每个样例」，没有说明分母），九成以上的测试题用到了它们。WebArena 没有标准轨迹，所以不算覆盖率；Mind2Web 的覆盖率只有 0.40，作者归因于训练示范与跨任务测试题的任务分布差得远（PDF p. 12–13）。

### 离线加在线不是加法

把训练集归纳的工作流当热启动、再叠加在线归纳，三档的逐步成功率都落在离线与在线之间（跨领域 34.1），任务成功率在跨任务和跨网站两档还低于两者（1.6 与 1.1）（PDF p. 13，Table 10）。作者的判断是两种来源的工作流不完全兼容，离线工作流似乎损害了在线工作流的生成质量和使用效果（PDF p. 13）。

### 算力开销：多出约一成

附录 D 统计了每道题三个步骤的 token 消耗（PDF p. 14，Table 11）：

| 步骤 | 每次输入 token | 每次输出 token | 每题次数 | 每题总 token |
|---|---:|---:|---:|---:|
| 动作生成 | 5,663 | 52.0 | 5.9 | 33,718.5 |
| 轨迹评判 | 306.8 | 82.8 | 5.9 | 2,298.6 |
| 工作流归纳 | 306.8 | 328.7 | 2.1 | 1,344.6 |

按表算，评判和归纳分别是动作生成的 6.8% 与 4.0%，合计 10.8%。正文把前两个比例写反了（评判 4.0%、归纳 6.8%），合计没错（PDF p. 14）。换来的是 WebArena 上约五成的相对提升。

### 把工作流做成动作：调用率只有 18.5%

附录 F 试了另一种用法 AWM_AS：把每条工作流包成一个高层函数，加进 agent 的动作空间，调用一次就按顺序执行预定的一串原子动作，比如 `login(username, password)` 依次点击、输入、点击、输入、提交（PDF p. 14–15）。

| 方法 | 元素准确率 | 动作 $F_1$ | 逐步成功率 | 任务成功率 |
|---|---:|---:|---:|---:|
| MindAct | 41.6 | 60.6 | 36.2 | 2.0 |
| AWM | 50.6 | 57.3 | 45.1 | 4.8 |
| AWM_AS | 51.8 | 56.7 | 46.4 | 3.6 |

数据引自原文 Table 13（PDF p. 15）。逐步成功率多 1.3 个百分点，任务成功率从 4.8 降到 3.6；正文写成「总体成功率同为 3.2」（PDF p. 15），与表不符。agent 只在 18.5% 的任务里调用了工作流动作，作者认为这说明当前 agent 不太愿意用新加的动作（PDF p. 15）。

![Figure 6 左图是订机票页面：agent 点击目的地输入框、输入「New York」；右图是输入后弹出的建议列表，里面有纽瓦克、所有机场、拉瓜迪亚、肯尼迪等多个选项，下一步要选哪一个取决于弹出的内容。](/reports/Agent-Workflow-Memory/fig6-popup.png)

图引自原文 Figure 6（PDF p. 15）。失败的典型：用户输入城市名后，网站会弹出附近机场让人挑。一个预先写死的「订机票」工作流动作可以把所有字段一口气填完，但「从弹出列表里选机场」这一步执行时看不到弹出的选项，没法灵活应对（PDF p. 15）。作者建议给工作流动作实时的状态访问或动态执行循环，留作后续工作。

**我们如何解释它**。 这条附录反过来说明了主方法为什么成立：工作流放在记忆里，是「下一步可以参考的说明书」，每一步仍由模型看着当前页面决定；冻成宏之后，中间状态被跳过，动态页面就会打断它。

## 限制、边界，以及不要补进去的实现

正式版没有单独的限制一节。能从正文收上来的边界如下：

- **只测了网页导航**。引言提到手机应用，结论写「各种数字任务」，实验只有 WebArena 和 Mind2Web（PDF p. 1、p. 8）。
- **不改权重，记忆就是提示**。论文把记忆实现为系统提示或主提示里的辅助文本（PDF p. 2，脚注 2），没有讨论跨会话持久化、检索索引或记忆变大之后怎么淘汰。按网站分组、工作流只有七条左右（PDF p. 12–13），是它能一直整份放进提示的前提。
- **在线的门卫是别人的评判器**。评判器错判会变成错误的工作流，论文承认这一点（PDF p. 6），但没有报告评判器准确率。
- **agent 不会离开工作流**。动作 $F_1$ 下降、AWM_AS 调用率 18.5%、弹出列表打断预定动作，指向同一个问题（PDF p. 6、p. 15）。
- **任务级成功率仍然很低**。Mind2Web 各档都在 5% 以下（PDF p. 6–7）。
- **没有方差**。所有结果都是温度 0 下的单次运行，没有报告重复或标准差。Mind2Web 任务成功率只有几个百分点，一两道题的差异就会改变排名。
- **Mind2Web 的顺序实验样本小**。每个网站不到 20 道题（PDF p. 14）。

## 可迁移启发

1. **记忆的单位选子程序，不选整段示范**。Synapse 对照说明，完整示范会把元素选择拉向示范里的样子（PDF p. 6）。自己的 agent 日志进上下文之前，先换槽位、切子任务。
2. **粒度要细、条目要少**。归纳提示要求「至少两步、不重叠」（PDF p. 11），七条左右的工作流就被九成题目用上（PDF p. 12–13）。记忆越大不等于越好。
3. **只收做成功的，并且门卫要可靠**。在线雪球的质量等于评判器的质量。能用规则验证的地方用规则。
4. **记忆按环境切片**。按网站分组，只放本站相关的套路（PDF p. 4）；不同来源的套路合并之前先验证会不会互相干扰（PDF p. 13）。
5. **状态用一句人话描述，别贴不可靠的原始结构**。贴过滤后的 HTML 反而更差（PDF p. 8）。
6. **指南不要冻成宏**。动态页面需要每步看见当前状态；工作流适合当说明书，不适合当一键执行的脚本，除非脚本内部还能观察（PDF p. 15）。
7. **分布差大时，现场学比搬运旧经验更稳**。跨领域上在线优于离线（PDF p. 7）：测试环境本身就是最贴近的经验来源。

## 关键词回看

- **Agent Workflow Memory（AWM）**：从经验里归纳可复用的工作流，写进 agent 的文本记忆，指导之后的动作生成；权重不动。
- **工作流**：一句功能描述加若干步；每步是状态描述、推理、可执行动作，不固定的值写成槽位。
- **归纳模块 $I$**：吃进经验、吐出工作流。LM 版做子任务切分和槽位抽象；规则版只做去重和非法动作过滤。
- **离线 / 在线 AWM**：前者从训练示范一次性归纳、测试时记忆固定；后者在测试流上边做边收，只收评判器判为成功的轨迹。
- **按网站分组**：每个网站一份小记忆，只放相关套路。
- **滚雪球**：新工作流把旧工作流当前几步，逐渐长出更复杂的套路（Figure 1、Figure 5）。
- **逐步成功率 / 任务成功率**：Mind2Web 上「这一步对」对「整题每一步都对」；24.6% 指前者。
- **AWM_AS**：把工作流包成高层动作加进动作空间；逐步略升、整题下降，动态页面会打断它。
