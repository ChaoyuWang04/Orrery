# gpt-oss 模型卡：权重交出去之后，写满用法与风险，留白怎么造

<!-- release-date: 2025-08-05 -->

> 本文依据本地 `papers/OpenAI/gpt-oss.pdf`，即 OpenAI **gpt-oss-120b & gpt-oss-20b Model Card**，arXiv:2508.10925v1，封面日期 2025-08-05，共 35 页。页码均指 PDF 物理页（封面为第 1 页），比页脚印的页码大 1。文中区分三件事：**卡里明确写了什么**、**我们怎么解释它**、**哪些是外部资料或本文推算**。

## 阅读前先认识几个词

- **MoE（Mixture-of-Experts，混合专家）**：把一层前馈网络拆成很多个并列的小网络（专家），每个 Token 只让其中几个干活。总参数可以很大，单次计算量却只跟被选中的那几个有关。
- **激活参数（active parameters）**：处理一个 Token 真正参与计算的参数量，近似代表每 Token 的计算量。
- **MXFP4（Microscaling FP4，块级缩放的 4 位浮点）**：一种低精度存储格式。一小块数值共用一个缩放因子，摊下来每个参数约 4.25 位（PDF p. 5）。
- **chat template（对话模板）**：把「谁在说话、说给谁听」这些结构信息拼成模型实际读入的那串 Token 的规则。
- **CoT（Chain-of-Thought，思维链）**：模型给出答案之前写下的中间推理文本。
- **Preparedness Framework（准备度框架）**：OpenAI 跟踪高危能力的内部框架，这份卡里追踪三类：生物与化学、网络安全、AI 自我改进（PDF p. 4）。

这份卡里最重要的两个新名字是：

- **harmony chat format**：OpenAI 为 gpt-oss 训练时使用的消息格式，用专用 Token 标出消息边界、作者、收件人和「通道」（PDF p. 7）。
- **launch candidate / helpful-only**：Preparedness 图表里的两类版本。launch candidate 是准备发布的默认模型；helpful-only、bio max、cyber max 是 OpenAI 自己做的对抗微调版本，**不发布**（PDF p. 12）。

## 一句话先说清

gpt-oss 是 OpenAI 放出的两个开放权重推理模型：120b 总参 116.8B、每 Token 激活 5.1B，20b 总参 20.9B、激活 3.6B，Apache 2.0 许可（PDF p. 4–5）。这份文件自称 model card 而不是 system card，理由是权重交出去之后，它会被许多不同的人装进许多不同的系统，护栏不再只由 OpenAI 一家实现（PDF p. 4）。

这个定位决定了它写什么、不写什么：

1. **写满「怎么正确使用」**：架构规格到位，harmony 格式与推理档位讲清，并直说格式用错会伤能力（PDF p. 7）；
2. **写满「会在哪里出事」**：默认模型的安全评测，连同比 o4-mini 弱的项一起公开；再自己扮演攻击者，把模型往生物和网安方向微调，测上限（PDF p. 11–29）；
3. **「怎么造出来」基本留白**：数据一段话、算力一句话、后训练一段话，没有超参、没有消融、没有 MoE 负载均衡（PDF p. 5–7）。

如果只记一句话：

> **开放权重的深浅，不看权重放没放，看训练链条上的配方环节公开了几格。这份卡公开的是接口与后果，不是配方。**

| Embed + Unembed（输入嵌入 + 输出投影） | 1.16B | 1.16B |

![同一比例尺下，120b 的 116.83B 参数里专家占 114.71B，注意力与嵌入不到 2%；每 Token 只激活 5.13B；20b 的非专家部分约占 9%。](/reports/gpt-oss/figure-param-budget.svg)

### 反推一遍：专家多宽、有没有共享专家

卡里没给专家的中间维度，也没说有没有共享专家。但上面这些数足够把它反推出来。以下是**本文的算术**，不是卡内陈述。

每个专家是门控 SwiGLU（PDF p. 5），有三个 $2880 \times H$ 的投影矩阵。用 120b 的 MLP 总量倒推：

$$
H \approx \frac{114.71 \times 10^{9}}{36 \times 128 \times 3 \times 2880} \approx 2881
$$

也就是说，**每个专家的中间维度约等于残差宽度 2880**。单个专家约 $3 \times 2880^2 \approx 24.9\text{M}$ 参数，乘满 36 层 × 128 个专家得 114.66B，比卡里的 114.71B 少 0.04%；20b 用同一尺寸，24 层 × 32 个专家得 19.11B，比卡里少 0.05%。差额可以由路由器和偏置之类的小张量填上。**两个规模用的是同一种专家，120b 只是层数乘 1.5、每层专家数乘 4。**

其余几行也对得上：

| 反推项 | 算法 | 反推值 | 卡里的值 |
|---|---|---:|---:|
| 嵌入 + 输出投影 | $201{,}088 \times 2880 \times 2$ | 1.158B | 1.16B |
| 注意力（120b） | $(2880 \cdot 4096 + 2 \cdot 2880 \cdot 512 + 4096 \cdot 2880) \times 36$ | 0.956B | 0.96B |
| 注意力（20b） | 同上 × 24 层 | 0.637B | 0.64B |
| 激活（120b） | $4 \times 24.9\text{M} \times 36 + 0.956 + 0.579$ | 约 5.12B | 5.13B |
| 激活（20b） | $4 \times 24.9\text{M} \times 24 + 0.637 + 0.579$ | 约 3.61B | 3.61B |

4096 与 512 来自「64 个查询头 × 头维 64」与「8 个 KV 头 × 64」（PDF p. 5）。嵌入那一行乘 2 才对得上，说明**输入嵌入与输出投影不共享权重**。MLP 总量几乎被 36 × 128 个标准尺寸的专家填满，没给共享专家或稠密前馈层留出位置，所以 gpt-oss 的 MoE 大概率**没有常驻共享专家**。官方权重的 `config.json` 印证了这几条推断：`intermediate_size` 为 2880、`tie_word_embeddings` 为 false（外部补充，见文末）。

### checkpoint 大小也对得上

卡里说 MoE 权重量化到 MXFP4、约 4.25 位/参数（PDF p. 5）。假设其余部分按 BF16（16 位）存：

$$
\text{平均位数} = \frac{\text{MLP 参数} \times 4.25 + \text{其余参数} \times 16}{\text{总参数}}
$$

120b 得约 4.46 位，20b 得约 5.26 位；60.8 GiB 与 12.8 GiB 反算回去分别是 4.47 位与 5.26 位（本文算术）。**20b 平均位数更高，不是量化得差，而是它的专家只占总参数的 91%，120b 占 98%。** 同一套量化，砸在非专家占比更高的模型上，省下的比例就小。

卡里给的量化动机很直接：MoE 权重占总参数九成以上，把它们压到 MXFP4，120b 就能放进单张 80GB GPU，20b 能跑在 16GB 内存的系统上（PDF p. 5）。它用的动词是 post-trained with quantization，但**没有说清是量化感知训练还是训练后量化，也没给量化前后的精度差**。

## 核心设计一：粗粒度 MoE，top-4 内 softmax

### 卡里写了什么

§2.2 的 MoE 段落只有几句（PDF p. 5）：

- 每个 MoE 块有固定数目的专家：120b 每层 128 个，20b 每层 32 个；
- 路由器是一个**标准线性投影**，把残差激活映射成每个专家的分数；
- 每个 Token 选 **top-4**；
- 专家输出的权重是**只在选中的 4 个专家上**做的 softmax；
- 专家用门控 SwiGLU，脚注补一句「我们的 SwiGLU 实现不太常规，带 clamp 和一条残差连接」。

前面还有一句全局设定：两个模型都在每个注意力块和 MoE 块之前做 RMSNorm，沿用 GPT-2 的 Pre-LN 位置（PDF p. 5）。

### 「只在选中专家上 softmax」是一个真实的选择

路由权重有两种常见写法：先对全部专家做 softmax 再取 top-K，被选中的权重之和小于 1；或者先取 top-K 再只在它们之间 softmax，权重之和恒为 1。gpt-oss 是后者。

**我们的解释**：权重和恒为 1，意味着「这 4 个专家合起来就是这一层的全部前馈」，输出尺度不随路由器的绝对置信度漂移，数值上更接近一个稠密 FFN。卡里没解释为什么这样选。

### 和 DeepSeek 路线差在哪

把 gpt-oss 和 DeepSeek-V3 放在一起（DeepSeek-V3 的数字来自 DeepSeek-V3 一篇，属外部对照）：

| 指标 | gpt-oss-120b | gpt-oss-20b | DeepSeek-V3 |
|---|---:|---:|---:|
| 总参数 / 激活参数 | 116.83B / 5.13B | 20.91B / 3.61B | 671B / 37B |
| 激活比 | 4.4% | 17.3% | 5.5% |
| 每层专家 | 128 | 32 | 256 路由 + 1 共享 |
| 每 Token 选中 | 4 | 4 | 8 路由 + 1 共享 |
| 路由专家被选比例 | 3.1% | 12.5% | 3.1% |
| 专家中间维 / 隐藏维 | 约 1.0（本文反推） | 约 1.0（本文反推） | 约 0.29 |

120b 与 DeepSeek-V3 的**路由稀疏度几乎一样**（4/128 与 8/256），差在专家粒度：DeepSeek 把前馈切成约 0.29 倍宽的小块、一次叫醒 9 个；gpt-oss 用一整块标准宽度的前馈、一次叫醒 4 个。细切与共享专家要解决什么，见 DeepSeekMoE 一篇；gpt-oss 两样都没做，卡里也没讨论。

### 代价与边界

**整份卡没有一句话讲负载均衡。** 没有辅助损失、没有路由偏置、没有容量因子、没有丢 Token 策略。MoE 训练最难的那一块在这里是空白，所以无法判断它怎样撑住 36 层 × 128 个专家的训练，也无法判断这套粗粒度方案能不能迁移到别的规模。

### 这一节可以带走什么

> **决定 MoE 部署门槛的，往往不是总参数，而是非专家部分有多大。**

120b 的注意力加嵌入不到 2%，只要专家压得动，整机就装得下；20b 的非专家部分接近 9%，同样的招数收益就小。做单卡或端侧评估时，先算这个比例，再谈量化。

## 核心设计二：注意力——带状窗口交替、GQA，以及分母上的「弃权票」

§2.2 的注意力段落信息密度不低（PDF p. 5）：

- 沿用 GPT-3，注意力块在**带状窗口（banded window）与全稠密**两种模式之间交替，带宽 **128 个 Token**；
- 每层 64 个查询头，头维 64；
- 用 **GQA（Grouped Query Attention，分组查询注意力）**，8 个 KV 头，即每 8 个查询头共用一套 Key/Value；
- 用 RoPE（旋转位置编码），并用 YaRN 把**稠密层**的上下文长度扩到 **131,072 个 Token**；
- **每个注意力头在 softmax 分母上有一个可学习偏置**，类似 off-by-one attention 与 attention sinks，让这个头可以一个 Token 都不注意。

最后一条值得多说两句。普通 softmax 强制所有历史位置的权重加起来等于 1：即使前文没有任何值得看的东西，这个头也必须把注意力分出去，常见的结果是大量权重被倒在序列开头某个位置上。分母上多一个可学习的项，等于给这道选择题加一个「以上都不看」的选项，权重之和可以小于 1。

带宽 128 的窗口层意味着一半的层 KV Cache 不随上下文增长，长上下文的缓存主要花在稠密层上。**这是本文的推算**：卡里只说「交替」，没说从哪一层开始、比例多少。官方 `config.json` 的 `layer_types` 显示 36 层严格按「窗口、稠密」交替，窗口 128（外部补充）。

卡里没写的还有：带状层的位置编码怎么处理长上下文；「131,072」只出现在「稠密层用 YaRN 扩展」这句里，卡内没有一行直接写「模型支持的最大上下文是 N」。

## 核心设计三：harmony 格式长在权重里，不在 API 那一层

这是这份卡对工程最有用的部分。§2.5.1 只有三段（PDF p. 7），加上附录的两张示例（PDF p. 30–31），指向同一个结论：**这套格式是模型的一部分，拼错了模型就是在吃没训过的输入。**

![一轮工具调用：system、developer、user 三条输入各以 end 结束；模型先在 analysis 通道写思维链并以 end 结束，再在 commentary 通道向 functions.get_weather 发 JSON 参数并以 call 结束。](/reports/gpt-oss/figure18-harmony-turn.svg)

图上是卡内 Figure 17 与 Figure 18 的完整一轮。下面只补图上读不出的判断。

### 证据一：词表为它扩过

所有训练阶段都用 `o200k_harmony` 词表：在 GPT-4o 与 o4-mini 所用的 `o200k` 之上**加入 harmony 格式专用的 Token**，总大小 201,088（PDF p. 6）。

专用 Token 意味着它们占着嵌入矩阵的行、在训练里有自己的梯度。服务层把 `<|start|>` 换成普通字符串，模型看到的就不是「格式不好看」，而是一个从没见过的输入分布。卡里自己的措辞是：正确使用这个格式「对部署 gpt-oss 以发挥最佳能力至关重要」（PDF p. 7）。官方仓库的 README 说得更重：只能用 harmony 格式，否则不能正常工作（外部补充）。

### 证据二：角色层级是被训练出来的行为，而且被量出了弱点

卡里给的层级（PDF p. 7）：

```text
System > Developer > User > Assistant > Tool
```

指令冲突时按这个优先级裁决。这不是解析规则，是训练出来的倾向：他们收集了不同角色消息互相冲突的样例，监督模型服从更高层级（PDF p. 15）。既然是行为，就得测。§4.3 给了两组（PDF p. 15–16）：

| 评测（越高越好） | gpt-oss-120b | gpt-oss-20b | o4-mini |
|---|---:|---:|---:|
| 系统提示词提取（system 对 user） | 0.832 | 0.881 | 0.993 |
| 提示注入劫持（system 对 user） | 0.780 | 0.639 | 0.917 |
| 短语保护，system 对 user | 0.912 | 0.793 | 0.937 |
| 口令保护，system 对 user | 0.965 | 0.947 | 0.982 |
| 短语保护，developer 对 user | 0.909 | 0.661 | 0.912 |
| 口令保护，developer 对 user | 1.000 | 0.946 | 0.947 |

前两行是 Table 7（PDF p. 15），后四行是 Table 8（PDF p. 16）。卡里直接承认：两个模型在指令层级评测上**普遍弱于 o4-mini**，原因还需要研究（PDF p. 16）。它补了两点：一是 StrongReject 越狱评测上与 o4-mini 大致持平，弱的是「用户改写系统级约束」而不是「已知越狱」；二是开发者可以自己微调来加强这一项，这是开放权重才有的退路（PDF p. 16）。

**对做 Agent 的人**：不要把租户隔离、权限边界押在 developer 消息上。20b 在「developer 对 user 的短语保护」上只有 0.661。

### 证据三：通道是可见性控制，不是排版字段

harmony 引入三个通道（PDF p. 7）：`analysis` 放思维链，`commentary` 放函数工具调用（以及给用户看的行动预告，preamble），`final` 放给用户看的答案。卡里的原话是通道用来表示「每条消息预期的可见性」。

这让模型能在思维链中间穿插工具调用，也能在长动作之前先给用户一段预告（PDF p. 7）。**我们的解释**：这种「同一回合里三段文字给三类读者看」的语义，在只有 `content` 加 `tool_calls` 的 JSON 调用格式里拼不出来；思考文本要么混进用户可见区，要么塞进自定义字段变成模型没训过的形态。

### 证据四：结束符分两种

图里最系统级的设计是右列那两个结束符。`<|end|>` 表示这条消息说完了；`<|call|>` 表示这条消息说完了、但**在等外部结果**。解码循环只要看停在哪个 Token 上，就知道该把内容交还用户，还是该暂停去执行工具。如果工具调用也用普通结束符，服务端就得再跑一个解析器去猜「这段 JSON 是不是要调工具」。这一段是我们对 Figure 18 的解读，卡里没有逐个定义这些控制 Token。

### 多轮对话要删掉历史思维链

§2.5.1 的最后一个例子（PDF p. 7）：**多轮对话里，过去 assistant 回合的推理痕迹应当被移除。**

这条对写网关和客户端的人有直接后果。**我们的推演**：历史里的 `analysis` 内容不能原样回灌，否则模型看到的是它没训过的上下文形态；但删掉中间某段思考会让前缀缓存从那个位置起失效。上下文成本、分布一致性、前缀缓存命中率三者在这里要一起权衡。卡里只给了「应当移除」这一句，没有给具体策略或成本数字。

### 这一节可以带走什么

> **模型有工具调用和多种可见性时，消息格式应当当成模型规格的一部分来设计、测试和版本化。**

1. chat template 的正确性纳入模型验收，并且只有一份实现（OpenAI 为此另外开源了 harmony 库，外部补充）；
2. 「本轮结束」与「等待外部结果」用不同的停止符；
3. 「这段不给用户看」做成结构字段，而不是写在系统提示里的自然语言约定。

## 三档推理强度：同一套权重，靠一行系统提示切换

§2.5.2 只有一段（PDF p. 8）：模型被训练成支持 `low`、`medium`、`high` 三档，在系统提示里插入 `Reasoning: low` 这类关键字配置；档位越高，平均思维链越长。Figure 17 的示例里写作小写的 `reasoning: low`（PDF p. 30）。

**「多想一会儿」是训练出来的条件行为，不是推理时把输出上限调大。** 这个字符串一旦被中间层丢掉，档位就静默回落到默认值，不会报错。

|---|---:|---:|---:|---:|

长度只能读图估：medium 与 high 两档里，20b 的点都落在 120b 右边，GPQA 的 high 档 20b 接近 32k Token、120b 约 16k。卡里给的唯一一个长度点值是：**20b 做 AIME 平均每题用掉超过 20k 个 CoT Token**（PDF p. 9）。它的结论是「多数任务上是对数线性收益」，更长的思维链以显著更高的延迟和成本换准确率，建议按用例同时挑模型大小和档位（PDF p. 9）。

## 训练：整份卡里最短的一节

报告在训练上写了的，全部列在这里（PDF p. 6–8）：

- **数据**：纯文本，数万亿 Token，侧重 STEM、代码与通识；预训练阶段复用 GPT-4o 的 CBRN（化学、生物、放射、核）过滤器，重点滤掉危险的生物安全知识；知识截止 2024 年 6 月；
- **算力**：NVIDIA H100，PyTorch 加专家优化的 Triton kernel，用了 Flash Attention；120b 训练耗 **210 万 H100 小时**，20b 少将近 10 倍；
- **后训练**：用与 o3 类似的 CoT RL 技术，教模型推理与使用工具；数据覆盖代码、数学、科学等；因为 RL 技术相似，性格也和 ChatGPT 里的模型相近；
- **工具**：浏览工具（`search`、`open`）、有状态的 Jupyter 式 Python 工具、开发者自定义函数；可以通过系统提示开关，每种工具都有基础的参考 harness；
- **安全训练**：deliberative alignment 与指令层级（PDF p. 11、18）。

没写的比写了的多：确切 Token 数、来源配比、清洗与去重、合成数据比例、污染检查；GPU 数、墙钟时长、MFU；学习率、batch、优化器、衰减；RL 算法、奖励设计、阶段数、SFT 数据构成；负载均衡；任何一项消融。这不是遗漏，是体裁：卡在第 4 页就把自己定位成 model card。

### 吃亏的两项：指令层级与幻觉

指令层级见上文 harmony 一节。幻觉（Table 9，PDF p. 17）在**不给联网**的条件下测：

### 三条决定

**第一条：不对思维链施加优化压力。** OpenAI 的研究发现，监控推理模型的 CoT 有助于发现不当行为，而直接惩罚 CoT 里的「坏念头」会让模型学会藏起思考、行为照旧。因此两个开放权重模型都**不对 CoT 施加任何直接优化压力**，好让开发者自己实现 CoT 监控、也让研究社区继续研究可监控性（PDF p. 16）。代价写在同一页：这些 CoT 可能含幻觉内容和不符合 OpenAI 安全政策的语言，**开发者不应不加过滤、审核或摘要就直接展示给用户**（PDF p. 16）。

这条决定和 harmony 是咬合的：`analysis` 通道独立存在、多轮时删掉历史思考，都是在给「CoT 不受约束」划边界。格式、可见性与可监控性是同一件事的三面。

**第二条：自己扮攻击者，并说清哪些产物不发布。** 见下一节。

**第三条：把外部评审的分歧公开。** 同见下一节。

## Preparedness：先扮攻击者，再问会不会推高开源前沿

### 两个问题

默认 120b 在三个追踪类别上都没到 High 门槛（PDF p. 4、11–12）。卡里另外追问了两个开放权重特有的问题（PDF p. 12）：

1. **攻击者微调之后能不能到 High？** OpenAI 自己做了对抗微调版本（不发布），SAG（安全咨询小组）复核后认为，即使用 OpenAI 自己的训练栈做了强力微调，120b 在生物化学与网安上仍未到 High；
2. **发布 120b 会不会显著推高开源模型的生物能力前沿？** 结论是不会：多数评测上已有别的开放权重模型得分接近或持平。

### 对抗微调怎么做

模拟的攻击者「懂技术、有强后训练基础设施与 ML 知识、能收集有害领域数据、算力预算充足」，技术路线选**增量强化学习**，用 OpenAI 内部 o 系列 RL 训练栈，训练与评测都用最高推理档（PDF p. 18）。两个要素（PDF p. 18）：

- **helpful-only 训练**：额外一阶段 RL，奖励「服从不安全请求」的回答；
- **针对性拉满能力**：生物版额外端到端训练网页浏览、并用与生物风险相关的领域专家数据增量训练（bio max）；网安版用 CTF（夺旗赛）环境做领域数据（cyber max）。

方法细节写在一篇配套研究论文里，卡内没有给出编号或链接。

### 图例先读懂：launch candidate 是要发布的那个

Preparedness 的柱状图里反复出现几种版本：`launch candidate`（准备发布的默认模型）、`helpful-only`、`bio max`、`cyber max`（后三者是对抗微调版本，不发布）。竞品 Kimi K2、Qwen 3 Thinking、DeepSeek R1-0528 不做微调、不开浏览，但用越狱提示绕过拒答（PDF p. 19–20）。

长文本生物风险题（Figure 5，PDF p. 20）最能说明两者的区别：默认的两个 launch candidate 在五个阶段上几乎全是 0%（拒答），而 helpful-only 各版本与越狱后的竞品在 Acquisition、Magnification 等阶段普遍 80%–100%。**默认模型会拒答，能力上限要靠去掉拒答的版本来测**，这就是做对抗微调的理由。

### 生物：接近专家线，但复杂排障未达门槛

以下读自柱状图，取 120b 各版本的最高值：

| 评测 | 人类基线 | 120b 最高 | 该版本 | o3 | 最好的竞品 | 出处 |
|---|---|---:|---|---:|---:|---|

| ProtocolQA 开放版（108 题，pass@1） | 共识专家 54%、中位专家 42% | 28% | bio max | 39% | DeepSeek R1-0528 24% | Figure 7，PDF p. 21 |
| 隐性知识与排障（cons@32） | 共识专家 80%、第 80 百分位博士 63% | 76% | bio max | 77% | Kimi K2 75% | Figure 8，PDF p. 22 |

三个观察：

- **o3 在四张图里都是最高**，对抗微调后的 120b 没超过 o3；
- **竞品在多项上与 120b 相差无几**：隐性知识题上 Kimi K2 75% 对 120b 最高 76%，病毒学上 Qwen 3 Thinking 54% 对 55%。这就是「不会显著推高开源前沿」的依据；
- **在两道开放式排障题上，launch candidate 与对抗微调版本几乎同分**（ProtocolQA 27% 对 28%，TroubleshootingBench 25% 对 26%）。**我们的解读**：这两道题不触发拒答，默认模型的分数已接近它的能力上限。

卡里的定性是：文本型生物知识很强，但在复杂实验方案排障上未达高门槛，纯文本架构也限制了它在依赖视觉的实验场景中的适用性（PDF p. 19）。它还交代了一个时间窗口：一开始主要对标 DeepSeek R1-0528，**过程中 Qwen 3 Thinking 与 Kimi K2 发布，才加进对比集**（PDF p. 19）；外部评估方 SecureBio 当时只对比了 R1-0528，结论是对抗微调的 120b 普遍高于 R1-0528、低于 o3（PDF p. 23）。「不推高前沿」这个判断对发布时点很敏感。

### 网安：CTF 接近 o3，Cyber Range 全部为 0

CTF 题目 100 余道，每题 16 次 rollout、报 pass@12，高中级不再报（太简单）（PDF p. 24）。读自 Figure 10、11（PDF p. 25）：

|---|---:|---:|---:|---:|---:|---:|
| 大学级 CTF | 39% | 27% | 17% | 33% | 32% | 未画 |
| 专业级 CTF | 28% | 16% | 2% | 14% | 21% | 25% |

大学级 CTF 在 cyber max 的训练数据里，所以那张图不画它（PDF p. 25）。卡里主动指出自己的对比哪里不干净，还提醒这些结果**很可能是能力的下界**，更好的脚手架可能显著提高成绩（PDF p. 25）。

Cyber Range 是在模拟网络里做端到端攻击：5 个场景（1 个中等、4 个轻量），每个评测跑 30 次，三种配置（只给目标 / 给粗略计划 / 给部分解题代码）（PDF p. 26–27）。Figure 12（PDF p. 27）：o3、o4-mini、120b helpful-only、120b cyber max 在两类场景的 pass@12 上**全部 0%**；只有「给提示」的轻量场景 pass@1 出现 o3 1%、120b helpful-only 2%。卡里的原话是：没有模型能在无帮助或有提示的情况下解出任何场景（PDF p. 27）。

| OpenAI PRs（pass@1） | 44% | 39% | 37% | 37% | Figure 15，PDF p. 29 |
| PaperBench（10 篇子集，pass@1） | 21% | 25% | 7% | 11% | Figure 16，PDF p. 30 |

SWE-bench 这张图的口径和能力评测一节不同：固定 477 题子集、不把单元测试给模型；o3 与 o4-mini 用内部工具脚手架、每题平均 4 次算 pass@1（PDF p. 28）。120b 在两处都是 62 上下（Table 3 为 62.4），o3 在 Figure 2 是 69.1、在这里是 68。PaperBench 共 8,316 个可独立评分的子任务，来自 20 篇 ICML 2024 Spotlight 与 Oral 论文，这里测其中外部数据小于 10GB 的 10 篇（PDF p. 29）。**会做竞赛题和能复现一篇论文之间，差的是长程一致性**，120b 在 PaperBench 上只有 o4-mini 的一半不到。

### 外部评审：公布「没听哪几条」

请了 METR、SecureBio 与 Daniel Kang 独立评审对抗微调方法，共享了论文早期稿、非公开的微调数据集、方法与脚手架细节，开了一小时问答（PDF p. 18–19）。**外部评审共提交 22 条建议，OpenAI 采纳 11 条，其中包括评审标为高紧急度的 12 条里的 9 条**（PDF p. 19）。采纳的包括补充排障类微调数据、新做一个未污染的排障评测、更新过时的病毒学评测、明确专家基线等（PDF p. 19、31–32）。

附录 2 专门列出 3 条没采纳的高紧急度建议与理由（PDF p. 32）：

| 未采纳的建议 | OpenAI 的理由 |
|---|---|
| 把 best-of-N 脚手架推广到所有评测 | 相关实验已在别处部分做过，全量重跑的预期增益有限 |
| 从 Preparedness 门槛里去掉 ProtocolQA | 它提供独特的安全信号，去掉会留下大缺口；改门槛超出本次发布的范围 |
| 用闭源模型替换拒答后算联合表现 | 以往测试显示闭源模型在良性代理任务上本就不拒答（Gryphon 除外），这样算给不出多少信号 |

**「我们没听哪几条、为什么」这张表，比十张「我们做了什么」更能说明一份文件的可信度。** 同时要看到边界：方法的完整可复核性只对外部评审开放，公众拿不到微调数据与脚手架。

留白不是均匀分布的：**公开集中在「接口」与「后果」，留白集中在「配方」**。OpenAI 愿意让人知道怎么正确使用它、它会怎么出事，不愿意让人知道怎么再造一个它。前者是生态与责任，写得越细越有利；后者是竞争资产。

所以别把这份 model card 读成技术报告。本文里所有关于设计动机的解释，比如 top-4 内 softmax 的意义、粗粒度专家的代价、多轮删思考与前缀缓存的冲突，都是我们的推断，卡里没有支撑。

## 最值得带回自己项目的六条

### 1. 用参数账核对规格表

一张 6 行的参数表加三个维度数字，就能反推专家宽度、有无共享专家、嵌入是否绑定，再用 checkpoint 大小做第二次校验。**任何规格表，只要写得出参数计数公式，就该验一遍；验不过的地方，就是它没说的地方。**

### 2. 量化收益看「可量化参数占比」

120b 专家占 98%、20b 占 91%，同一套 MXFP4 下平均位数是 4.47 对 5.26。评估「量化后装不装得下」时先算这个占比，比看压缩率有用。

### 3. 消息格式按模型规格管理

格式进了词表，就进了权重。模板只留一份实现并纳入版本；「本轮结束」与「等待外部结果」分开停止符；可见性做成结构字段。

### 4. 指令层级是可测量的能力，不是假设

20b 在「developer 对 user 的短语保护」上只有 0.661（PDF p. 16）。把租户隔离押在系统消息上的 Agent，这个数就是风险敞口。把它做成回归测试，换模型就跑一遍。

### 5. 思维链的可监控性与可展示性要一起定

不对 CoT 施压，换来可监控性，代价是 CoT 不能直接给用户看（PDF p. 16）。**过滤什么、留什么给监控、历史里删不删**，三件事要同时决定。

### 6. 公布分歧比公布成绩更建立信任

22 条建议、采纳 11 条、3 条高紧急度未采纳并逐条给理由（PDF p. 19、32）。这个格式可以直接搬进内部评审、事故复盘与架构决策记录。

## 关键词回看

- **激活参数**：一个 Token 实际参与计算的参数，120b 为 5.13B，占总参数的 4.4%（PDF p. 5）。
- **粗粒度 MoE**：专家约等于一个标准宽度前馈（中间维 2880 为本文反推），每层 128 或 32 个，每 Token 选 4 个，没有共享专家。
- **top-4 内 softmax**：门控权重只在选中的 4 个专家之间归一化（PDF p. 5）。
- **MXFP4**：块级缩放的 4 位浮点，约 4.25 位/参数，只用于 MoE 权重（PDF p. 5）。
- **带状窗口与稠密交替**：窗口带宽 128 Token；稠密层用 YaRN 扩到 131,072（PDF p. 5）。
- **softmax 分母偏置**：每个头一个可学习偏置，允许这个头不注意任何 Token（PDF p. 5）。
- **harmony**：专用 Token 标出消息边界与作者，五级角色层级，三个通道 analysis / commentary / final（PDF p. 7、30–31）。
- **三档推理强度**：系统提示里写 `Reasoning: low` 这类关键字，是训练出的条件行为（PDF p. 8）。
- **not_unsafe**：安全评测的正向指标，按相关政策没有产出不安全内容的比例（PDF p. 13）。
- **launch candidate / helpful-only / bio max / cyber max**：待发布的默认模型，与三种不发布的对抗微调版本（PDF p. 12、18、25）。
- **pass@1 / pass@12 / cons@32**：一次答对率 / 12 次里至少一次答对 / 32 次多数投票，分别用在能力评测、CTF 与部分生物多选题上（PDF p. 8、24、21）。

## 最后的判断

**有证据支撑的**：

- 规格：116.8B / 5.1B 与 20.9B / 3.6B、128 与 32 个专家、top-4、窗口与稠密交替、GQA 8 个 KV 头、YaRN 131,072、分母偏置、201,088 词表、MXFP4 4.25 位、210 万 H100 小时（PDF p. 4–6）；
- 120b 在多数能力基准上超过 o3-mini、接近 o4-mini，20b 在竞赛数学上与 120b 相当（Table 3、Figure 1–2）；
- 指令层级普遍弱于 o4-mini，幻觉率高于 o4-mini，卡里主动写出（Table 7–9）；
- 默认模型与对抗微调版本都未到生物与网安的 High 门槛；Cyber Range 上所有模型 pass@12 为 0%；这些结果被作者标为能力下界（PDF p. 12、25、27）。

**只是作者观察或归因的**：

- 「数学强是因为能有效使用很长的思维链」（PDF p. 9），没有对照实验；
- 「健康表现—成本前沿上的大的帕累托改进」（PDF p. 9），没有成本数字；
- 「不会显著推高开源生物能力前沿」依赖评测时点，Qwen 3 Thinking 与 Kimi K2 是中途加入对比的（PDF p. 19）。

**完全没有公开的**：数据配方、全部超参、MoE 负载均衡、任何消融、GPU 数与墙钟、后训练算法与奖励、量化路径、服务吞吐与延迟、对抗微调的数据与论文。

如果只带走一句：

> **开放权重不是一个开关，是一条光谱。这份卡把「怎么用」和「会出什么事」写得很透，把「怎么造」整段留白，读它时要知道自己拿到的是哪一半。**
