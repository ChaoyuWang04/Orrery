# ADAS：元 agent 冻住，在代码空间里搜内层 agent 的工作流

<!-- release-date: 2024-08-15 -->

> 本文依据 **Automated Design of Agentic Systems**，arXiv:2408.08435v2，2025-03-02，ICLR 2025 会议论文，共 34 页（正文到 p. 11，致谢与参考文献 p. 12–18，附录 A–J 在 p. 19–34）。作者 Shengran Hu、Cong Lu、Jeff Clune，单位是英属哥伦比亚大学（UBC）、Vector Institute 与加拿大 CIFAR AI Chair。页码均指这份 PDF 自身的页码。文中区分三件事：**论文写了什么**、**我们如何解释它**、**哪些是外部资料补充**。

## 读前：先把几个容易混的词说成人话

**最外面的三个：**

- **智能体系统（agentic system）**：不是「问一句、答一句」，而是把基础模型当成模块，串上规划、工具与多步处理。论文举的例子是思维链（Chain-of-Thought，CoT）、自我反思（Self-Reflection）与 Toolformer（PDF p. 1）。
- **基础模型（Foundation Model，FM）**：GPT、Claude 这类预训练好的大模型。这篇从头到尾**不改权重**。
- **ADAS（Automated Design of Agentic Systems，智能体系统的自动设计）**：论文要立的研究领域，目标是自动发明新积木，或把已有积木用新方式拼起来（PDF p. 1–2）。

**这篇特有的结构词：**

- **元 agent（meta agent）**：外层那个「设计师」。它读档案、写代码、提出下一个内层 agent。它的提示词和流程在一次搜索里始终不变。
- **内层 agent**：被设计出来的系统，就是一段 `forward(taskInfo)` 的 Python 函数：这道题查几次模型、谁当专家、怎么投票、错了怎么改，全写在里面。
- **档案（archive）**：所有评过分的 agent 连同分数组成的库。它不只留第一名，次优的设计也留着，给元 agent 当**垫脚石（stepping stones）**（PDF p. 6）。
- **有趣性（interestingness）**：元 agent 被要求去提「新颖或值得做」的设计，不只贪当前分。这是从开放式算法那条线借来的做法（PDF p. 3、p. 5）。

**邻近工作，一句话对齐：**

- PromptBreeder 一篇只变异提示词文本，工作流不动；ADAS 在第 2 节正是拿它举例说明「搜索空间太窄」（PDF p. 4）。
- Darwin-Godel-Machine 一篇出自同一作者组，拆掉了本篇冻住的那个设计师，让档案里的 agent 改自己的代码；它的「没有自改进」对照就是把本篇的设定搬过去。
- GEPA 一篇改的是提示词，但评价时读的是轨迹文本；RRSI 与 AIDE2 两篇改的也是 harness 代码，外层是否会变、怎么约束改动各不相同；AlphaEvolve 一篇进化的是算法与 kernel 代码，不是 agent 架构。

## 一句话先说清

手工设计的 CoT、Self-Refine、多角色辩论已经很能打。论文的判断是：它们会走计算机视觉里 HOG 特征的老路，算力与数据涨上去之后，被学出来的方案取代（PDF p. 1–2）。

它给出的第一个可跑通的算法叫 **Meta Agent Search（元智能体搜索）**：一个冻住的元 agent 看着档案，用代码写出一个新的内层 agent，拿去验证集打分，写回档案，再读更新后的档案写下一个。ARC 上跑 25 轮，四个推理域各跑 30 轮。结果是阅读理解 DROP 的 F1 比最强手工基线高 13.6 分，多语言小学数学 MGSM 高 14.4 个百分点；把数学上搜到的 agent 原样搬到 GSM8K，还比最强手工基线高 25.9 个百分点（PDF p. 3、p. 7–8）。

> 搜索的对象从提示词扩成了代码；搜索的主体仍是一个冻住的设计师。改的是内层 agent 的 `forward()`，不是元 agent 自己，也不是模型权重。

这句话决定了这篇在「自进化」谱系里的位置，也决定了它的边界：搜出来的是已知积木的新拼法，评价只看一个标量，测试时的调用次数没有对齐。后面几节分别把这三件事讲透。

## 第一层矛盾：积木越来越多，拼法靠人调不过来

论文开头先承认现状：可靠地解决问题，往往需要一个多组件的复合系统，而不是一次模型查询；复杂任务还要接搜索引擎、代码执行与数据库（PDF p. 1）。社区已经发明了一批有效积木——思维链规划、记忆与检索增强（RAG）、工具使用、自我反思——但把它们拼成好用的系统，仍要靠领域专家手工调（PDF p. 1）。

问题叠在两处（PDF p. 2）：

1. **积木还没发明完。** 有用的积木数量巨大，靠研究社区一个个挖会很慢。
2. **就算挖完，组合也试不完。** 积木之间怎么接、怎么交互，面对海量应用仍要逐个手调。

论文把自己接到一条反复出现的历史上（PDF p. 1–2）：

| 领域 | 手工方案 | 后来被什么取代 |
|---|---|---|
| 计算机视觉 | HOG 特征 | CNN 学出来的特征 |
| 网络结构 | 人设计的 CNN | 神经架构搜索（NAS） |
| 偏好对齐 | DPO 这类手写损失 | 模型写出来的损失函数 |
| 科研流程 | 人写算法、跑实验 | The AI Scientist 自动研究管线 |
| 机器人环境 | 人搭仿真 | OMNI-EPIC 自动生成环境 |

背后的两份纲领是 Clune 2019 的 AI 生成算法（AI-Generating Algorithms，AI-GAs）与 Sutton 2019 的 Bitter Lesson：算力和数据涨上去，手工构件会被学出来的方案替换（PDF p. 1–2）。相关工作一节把 AI-GA 分成三根支柱——元学习架构、元学习学习算法、生成学习环境——ADAS 自认落在前两根上：学智能体的架构，并借上下文学习去「学会学习」（PDF p. 9）。

于是研究问题只有一句：能不能把智能体系统的设计自动化（PDF p. 2）。

### 三个零件：搜索空间、搜索算法、评价函数

ADAS 被定义成一个优化过程：用某个搜索算法，在某个搜索空间里找能优化评价函数的智能体系统（PDF p. 3，灰框定义；Figure 2 画的是这三块）。三个零件的人话是（PDF p. 4）：

- **搜索空间**决定「哪些 agent 有资格出现」。PromptBreeder 只变异提示词，工作流保持不变，于是另一种工作流根本不在空间里。也有人把 agent 写成图（GPT-Swarm）或前馈网络（DyLAN）。
- **搜索算法**决定「怎么走」。空间很大甚至无界，必须处理探索与利用的取舍。已有做法有强化学习（GPT-Swarm）和让基础模型迭代生成新解（PromptBreeder）。
- **评价函数**决定「什么叫好」。可以是性能、成本、延迟或安全。最简单的做法是验证集准确率——这篇实际用的就是它。

**可迁移启发。** 任何「自动设计 X」的项目，先把这三件拆开写下来。空间太窄，算法再强也搜不出新物种；评价函数只认一个标量，系统就朝这个标量长。本篇后面暴露的限制，几乎都能追到这两头。

## 核心设计一：把整个 agent 写成代码

### 旧问题：表示方式先砍掉了一截能发现的东西

论文把此前的 ADAS 尝试分成两类（PDF p. 9–10）：

1. **只学提示词。** OPRO、PromptBreeder、TextGrad 这一类，把指令措辞写得更好，但角色、工作流、工具接口都还是人预先钉死的。论文的批评是：这类提示词往往绑在特定域上，难迁移。
2. **学提示词以外的部件，但仍不是全部。** DyLAN 优化网络节点之间的连接；DSPy 与 Trace 在一组候选节点的笛卡尔积上优化；GPT-Swarm 用强化学习优化图上的边；AgentOptimizer 学工具；AutoFlow 发明一种写工作流的语言；Agent Symbolic Learning 想同时学提示词、工具和工作流。论文认为它们要么盖不住全部设计，要么搜索空间对搜索算法不友好。

### 新设计：代码当搜索空间，四条理由

论文主张：把整个智能体系统定义在代码里，让元 agent 用代码编程出越来越好的 agent（PDF p. 2–4）。理由按因果顺序是：

1. **图灵完备。** Python 这类语言图灵完备，理论上提示词、工具使用、工作流及其任意组合都写得出来（PDF p. 2，引 Boyer & Moore 1983、Ladha 2024）。
2. **可读。** 代码比网络或图好读，调试更容易，论文把这点同时算作安全上的好处（PDF p. 4）。
3. **能接人类已有的工作。** 可以在 LangChain 这类框架里搜，复用 RAG、搜索引擎工具；自定义的图空间做不到（PDF p. 4）。
4. **基础模型本来就会写代码。** 代码空间把模型最强的先验用上了；自定义图空间没有这份先验，搜索会更慢（PDF p. 4、p. 10）。

### 代价：理论空间和实际空间不是一回事

论文自己随即收口：理论上元 agent 可以从零写出任何积木，但连「查询基础模型」这种基本函数都不给，搜索会很没效率（PDF p. 4）。所以他们给了一个不到 100 行（不含注释）的框架，元 agent **只需要写一个 `forward` 函数**，输入任务信息，输出回答——和 FunSearch 只让模型写函数体是同一种做法（PDF p. 4）。

附录 C 把框架摊开（PDF p. 23–25）：

- 所有中间结果都装进一个具名元组 `Info`：名字、作者、内容、迭代序号；
- `FM_Module` 把若干条 `Info` 拼成结构化提示词，向模型要一段 JSON，默认模型是 `gpt-3.5-turbo-0125`、温度 0.5；
- `AgentSystem.forward` 是元 agent 真正要填的那个洞。附录还给了用这套框架写的 Self-Refine 示例：一个 CoT 模块、一个 Critic 模块，最多 5 轮（PDF p. 25）。

ARC 实验里预置工具只有两个：用生成的变换代码跑示例格子并拿反馈，以及把代码应用到测试格子上取答案（PDF p. 25–26）。没有搜索引擎，没有 RAG，也没有视觉编码器。

**我们如何解释它。** 图灵完备是搜索空间的上限论证，不是这次实验的描述。这次实验证明的是：在「Python 控制流 + 多次调用同一个文本模型 + 少量工具」这个子空间里，冻住的元 agent 能拼出超过手工基线的工作流。附录 G 那个叫「Verified Multimodal Agent」的设计，所谓视觉表征，是让一个 `FM_Module` 输出一段叫 `visual` 的文字字段，再由另一个模块用文字核实（PDF p. 32–33）——名字带 Multimodal，调用的仍是纯文本的 GPT-3.5。

**可迁移启发。** 宣称「能表示任何东西」之前，先把给搜索器的原语列出来。原语决定了能长出什么物种；FunSearch 搜函数体、这篇搜 `forward()`，都是「理论完备、实践收口」。

## 核心设计二：Meta Agent Search——档案在长，设计师不变

![Meta Agent Search 的循环：元 agent 读入档案，写出带摘要、名字和 forward 代码的新 agent，自反思直到新颖且无错，再在任务上测试并写回档案；下方是三个元 agent 起名的已发现 agent 示意，分别是多步同行评审、带核实的「多模态」和分而治之。](/reports/ADAS/fig1-meta-agent-search.png)

图引自原文 Figure 1（PDF p. 2）。循环里只有两样东西在变：档案越来越长，每轮多出一个新 agent。元 agent 那个框，第 1 轮和第 30 轮是同一个。下方三个示例的名字都是元 agent 自己起的，完整代码在附录 G（PDF p. 31–33）。

### 一轮具体做什么

正文第 3 节与附录 H 的 Algorithm 1 给的是四步（PDF p. 4–5、p. 33）：

1. **（可选）初始化档案。** 放进 CoT、Self-Refine 这类手工基线；附录 I 另做了空初始化对照。
2. **设计。** 元 agent 以档案为条件，先写高层想法，再写成代码，然后做**两轮自反思**，确保新颖且没写错。
3. **评价。** 用目标域的验证数据打分；运行出错就再反思、再改，最多 5 次。
4. **归档。** 把 agent 连同指标写入档案，进入下一轮，直到迭代上限。

提示词的细节在附录 B（PDF p. 21–23）：

- **主提示**要求元 agent 仔细观察已发现的 agent，想想能学到什么洞察、教训或垫脚石；鼓励从相关 agent 论文或其他领域的论文里找灵感；最后一句是全大写的「THINK OUTSIDE THE BOX」。目标写的是「提出有趣的新 agent 来最大化指定的性能指标」。输出必须是 JSON，三个键依次为 `thought`、`name`、`code`（PDF p. 21）。
- **第一轮自反思**同时问三件事：和档案比是否真有新意（要对比实现上的实际差异）、实现有没有错、不改整体框架的前提下细节怎么改（PDF p. 22）。
- **第二轮自反思**只盯代码，对照提示里收集的「错误实现示例」再改一遍（PDF p. 22）。作者说这份常见错误清单对提高生成代码质量很有效，格式提示借鉴了 DiscoPOP 那篇的做法（PDF p. 21）。
- **运行出错时**，提示要求沿用原来的想法，只调试当前实现（PDF p. 23）。

### 元 agent 冻住，是设计，不是省事

循环更新的是档案，不是元 agent。系统提示、主提示骨架、自反思流程、所用模型，在一次搜索里都不变。论文把「元 agent 也被 ADAS 改进」明确写成未来工作，叫**高阶 ADAS（Higher-order ADAS）**：元 agent 本身也是 agent，可以被改进，甚至可以有元–元 agent（PDF p. 10）。

所以如果一定要叫它「自进化」，准确的说法是：内层 agent 的代码设计在变，外层设计师冻住。Darwin-Godel-Machine 一篇做的正是把这层冻住的设计师拆掉；它把本篇的设定当成「没有自改进」的对照，报告这条线在编码基准上较早封顶（见那一篇，不是本文数据）。两边的曲线不要叠进同一句「自改进」叙事里。

### 探索靠一句自然语言，而不是一条采样公式

元 agent 看到的反馈就是性能数字：成功率或 F1（PDF p. 5）。探索与利用的平衡，靠的是提示里的「最大化指标」与「提出有趣的新 agent」两句话同时成立，外加第一轮自反思里那道「是否有新意」的自查。没有父代采样公式，没有新颖度打分。论文在未来工作里自己承认：搜索算法相对简单，只专注于探索有趣的新设计；Quality-Diversity、更经典的探索–利用方法都还没接进来（PDF p. 11）。

**可迁移启发。** 要让系统能靠组合前进，档案里必须留着次优的垫脚石。本篇的实现很朴素：全部写入，让下一代把档案当上下文读。Darwin-Godel-Machine 一篇则是给次优个体留非零被选概率。两种实现的共同点是：次优解必须还活着。

## ARC：看搜索怎么一步步爬上去

### 评测口径先说清

ARC（Abstraction and Reasoning Corpus，抽象与推理语料）每题给若干对输入–输出格子，要求学会变换规则，再预测测试格子（PDF p. 5）。论文沿用 Greenblatt 2024 的做法，让 agent 写变换代码，而不是直接填格子；格子在提示里表示成整数二维数组，每种颜色一个整数（PDF p. 6、p. 25）。口径是（PDF p. 6、p. 26）：

- 只从「Public Training Set (Easy)」里抽格子尺寸不超过 $5\times 5$ 的题；
- 验证 20 题，测试 60 题；每个 agent 在两边各评 5 次，报中位数与 95% bootstrap 置信区间；
- 按预测格子与参考答案的精确匹配（Exact Match）算准确率；
- 搜索 25 轮；元 agent 用 `gpt-4o-2024-05-13`，被设计的 agent 和基线都用 `gpt-3.5-turbo-0125`，为的是省钱。正文把两者写成 GPT-4 与 GPT-3.5，完整模型 ID 在附录（PDF p. 6、p. 26）。

这不是官方 ARC-AGI 评测。引用 Greenblatt 只是为了「写代码代替填格子」这个做法。

手工基线五条，用同一套框架实现，也全部作为档案种子（PDF p. 6、p. 30）：CoT；COT-SC，采 5 个答案再用多数投票或一次模型调用集成；Self-Refine，最多 5 轮、Critic 判对就提前停；LLM Debate，每个辩手一个角色、辩两轮；Quality-Diversity，简化版 Intelligent Go-Explore，基于已有答案迭代 3 次收集多样答案。论文特别说明，这里的「state-of-the-art」指的是它们代表了领域里的重要设计模式，不是排行榜第一（PDF p. 6）。

左图画的是「到目前为止最好的那个 agent」在测试集上的成绩，所以只升不降；浅蓝带是它的 95% 置信区间，前几轮宽到几乎盖住全部基线。读图要抓的是那五个台阶旁的标注，它们就是论文说的垫脚石：第 1 轮先试「先想高层策略、再写细节」；第 3 轮出现「多路 CoT 生成候选、精炼、再集成最好的几个」，正文说这个模式此后被反复使用；第 4 轮引入「动态记忆，做更多轮精炼」；第 8 轮「把上一个想法放大」；第 14 轮「引入多个批评者」成为最终最佳（PDF p. 5–6）。

正文还补了一条不在台阶上的血缘：「多样反馈」「按效率、简洁这类特质请专家评」「模拟类人反馈」分别在第 5、11、12 轮出现，最终那套复杂反馈机制是这三块的组合，而不是突然冒出来的（PDF p. 6）。这三轮没有刷新最高分，所以图上没有台阶——这正是「垫脚石刚出现时不一定高分」的例子。论文把这种组合比作用大模型做进化里的交叉（PDF p. 6）。

右图是最终最佳 agent，元 agent 给它起名 Structured Feedback and Ensemble Agent。附录 D 的 Code 3 是它的完整代码（PDF p. 27–29）。照着代码读，值得盯住的实现细节有：

- 5 个候选用温度 0.8 生成，一个示例格子都过不了的直接丢掉；
- 类人反馈温度 0.5，三位专家（效率、可读、简洁）温度 0.6，精炼温度 0.5，最终决策降到 0.1；
- 所谓「结构化反馈」，是把全部反馈拼成一个字符串，按空格切词，再用集合去重后重新拼起来（PDF p. 28）。这是词袋去重，连词序都丢了，不是语义上的整理。

**我们读附录代码的两处发现。** 其一，精炼循环里每过一次示例就把同一个候选再追加一次，排序取前 3 时，前 3 很可能是同一个候选的几份拷贝，「Top-3 集成」未必真在集成三个不同答案。其二，第 60 行用 `refinement_module(...)` 去「构造」最终决策模块，按字面是一次模块调用而不是新建模块；论文说附录为了对齐正文术语改过变量名（PDF p. 23），这更可能是改名时留下的笔误，但照抄这段代码跑不起来。两处都不改变论文报告的分数，只提醒：图上的「Ensemble」与代码行为不完全是一回事。

## 四个推理域：阅读和数学拉开，科学和多任务没拉开多少

### 设置

四个基准各自独立搜索，每个 30 轮（PDF p. 6–7）。为省钱都抽了子集（PDF p. 29）：

| 域 | 基准 | 验证 / 测试 | 每个 agent 评几次 | 题型 |
|---|---|---|---:|---|
| 阅读理解 | DROP | 128 / 800 | 1 | one-shot |
| 数学 | MGSM（多语言小学数学） | 128 / 800 | 1 | zero-shot |
| 多任务 | MMLU | 128 / 800 | 1 | zero-shot |
| 科学 | GPQA Diamond | 32 / 166 | 5 | zero-shot |

GPQA 题少，所以评 5 次，让总评测次数与其他域相当；DROP 用 one-shot 是跟 OpenAI simple-evals 的惯例（PDF p. 29）。除了 ARC 那五条基线，这里再加两条专攻推理的：Step-back Abstraction（先想解题涉及哪些原理）与 Role Assignment（先让模型从预设集合里选一个角色，再以该角色作答）；另加只优化提示词的 OPRO，用来证明「学全部部件比只学提示词强」（PDF p. 7、p. 30）。

## 迁移：换域、换模型，要逐格看

### 从数学换到别的域

把 MGSM 上最好的三个 agent 原样搬走，不重新搜索（PDF p. 7–8）。原文 Table 2（PDF p. 8）与附录 Table 4、Table 5（PDF p. 20）合起来：

| Agent | MGSM | GSM8K | GSM-Hard | SVAMP | ASDiv | DROP | MMLU | GPQA |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 该列最强手工基线 | 39.0 | 43.6 | 18.0 | 78.5 | 89.2 | 65.8 | 65.9 | 31.6 |
| Dynamic Role-Playing Architecture | 53.4 | 69.5 | 31.2 | 81.5 | 91.8 | 70.4 | 62.4 | 28.6 |
| Structured Multimodal Feedback Loop | 50.2 | 64.5 | 30.1 | 82.6 | 89.9 | 70.4 | 67.0 | 28.7 |
| Interactive Multimodal Feedback Loop | 47.4 | 64.9 | 27.6 | 80.6 | 89.8 | 71.9 | 64.8 | 29.9 |

第一行各列的最强基线不是同一个：MGSM 与 GSM8K 是 LLM Debate，GSM-Hard 与 DROP 是 Role Assignment，SVAMP 与 ASDiv 是 Self-Refine，MMLU 是 COT-SC，GPQA 是 Self-Refine。置信区间省去，见原表。

论文强调的两个数字是 GSM8K 高 25.9、GSM-Hard 高 13.2 个百分点（PDF p. 8）。但把整张表摊开，结论要分三档：

1. **同类数学题上很稳。** GSM8K、GSM-Hard 间隙很大；SVAMP、ASDiv 更简单，手工基线已在 78–89，发现的 agent 只高一截，天花板效应清楚可见。
2. **迁到阅读理解仍然赢。** DROP 一列三个都高于最强手工基线，是跨域里最干净的一列。
3. **迁到多任务和科学就不稳了。** MMLU 上 Dynamic Role-Playing 的 62.4 **低于全部七条手工基线**，另一个 64.8 也低于 COT-SC；GPQA 上三个都略低于 Self-Refine 的 31.6。

正文与 Table 2 的图注都写「consistently outperform」，MMLU 那一格是反例；附录 A 的措辞收窄成了「阅读与多任务上胜出、科学上持平」（PDF p. 20），比正文准确，但多任务那一格仍撑不住「胜出」。另外，这三个数学 agent 的代码附录没有给出，只能看到名字。

**我们如何解释它。** 数学上搜到的是一套对「多角色 + 反馈 + 集成」友好的控制流。它在需要离散推理的阅读题上仍然有用，在卡在知识上的题上没用——和 Table 1 里论文自己的假设是同一个方向。

## 空初始化：种子有用，但不是必要条件

附录 I 问：不把手工基线放进档案，还能不能搜过它们（PDF p. 33–34）。原文 Table 6（PDF p. 34）：

| 配置 | DROP | MGSM | MMLU | GPQA |
|---|---:|---:|---:|---:|
| 最强手工基线 | 65.8 | 39.0 | 65.9 | 31.6 |
| 空初始化 | $73.9\pm 0.9$ | $67.5\pm 3.3$ | $68.5\pm 3.3$ | $32.7\pm 3.2$ |
| 用手工基线做种子（主表） | $79.4\pm 0.8$ | $53.4\pm 3.5$ | $69.6\pm 3.2$ | $34.6\pm 3.2$ |

论文读出两句话（PDF p. 33–34）：空初始化仍然超过全部手工基线，代码空间本身就能搜；有好种子通常更好，但**数学是反例**——空初始化 67.5，有种子只有 53.4。作者的假设是：没有预置模式时，有限轮次里的探索更宽、推理策略更多样，而数学恰好吃这一套。

**我们如何解释它。** 种子是双刃的。它给元 agent 一套能跑的垫脚石，也可能把搜索钉在「多角色辩论、自我精炼」这些已有模式附近。数学上 14 个点的反向差，说明「站在人类肩膀上」不是无条件的加速。还要注意：主表与跨域迁移用的都是有种子那一次的结果；ARC 没有做空初始化。

## 发现的 agent 长什么样：新积木，还是新拼法

附录 G 给了 Figure 1 里三个示例的代码（PDF p. 31–33）。PDF 写前两个是在「阅读理解域（GPQA）」上发现的，第三个在数学域 MGSM 上发现的（PDF p. 31）。GPQA 是科学基准，代码里的角色也是物理、化学、生物专家；官方项目页把前两个标成科学问答上发现的。按代码与引用，前两个应读作科学域，「阅读理解」是笔误。

把它们与 ARC 上的最佳 agent 摊开，并按附录代码数一数**每道题要调用几次模型**：

| Agent | 实际在做什么 | 每题模型调用次数（按附录代码数） |
|---|---|---|
| CoT | 先推理再作答 | 1 |
| COT-SC | 5 路 CoT，再投票或调用一次模型集成 | 5–6 |
| Self-Refine | 作答后 Critic 批评、再精炼，最多 5 轮 | 2–11 |
| Verified Multimodal | 用文字「画」示意图 → 另一个模块核实 → CoT 解题 | 3 |
| Divide and Conquer | 拆子问题 → 四个专家轮流解 → 整合 | 2 + 子问题数（按换行切分，不设上限） |
| Multi-Step Peer Review | 四个学科专家作答 → 两两交叉批评 → 各自精炼 → 最终决策 | 21 |
| Structured Feedback and Ensemble（ARC 最佳） | 5 路候选 → 类人反馈 + 三专家反馈 → 精炼 3 轮 → 取前 3 集成 | 最多 41 |

调用次数是我们照附录 C、F、G、D 的代码与描述数出来的（PDF p. 25、p. 27–33），不是论文给的数字；ARC 那一行的 41 是 5 个候选都至少过一个示例时的上限，一个都不过时只剩 6 次。

两件事由此清楚：

**第一，积木没有一块是新的。** CoT、角色、批评者、集成、分而治之、自我精炼，全在基线集合里。论文真正展示的，是元 agent 能用代码把它们嵌套、加宽、改温度、加过滤条件，并让第 3 轮的「多路 CoT + 集成」成为第 14 轮更复杂机制的零件。领域定义写的是「发明新积木，和／或用新方式组合它们」（PDF p. 1–2），这次实验的证据支持后半句；如果「新积木」指一种新的工具接口、记忆结构或搜索算法，这次运行没有拿出来。

**第二，测试时的计算量没有对齐。** 发现的 agent 每题调用模型的次数，常是 CoT 的十几倍到几十倍。13.6 个 F1 点与 14.4 个百分点里，有多少来自更好的控制流，有多少来自「多调用了几十次」，论文没有拆。它把成本、延迟、鲁棒性写成未来的多目标 ADAS（PDF p. 10），等于承认这次只优化了性能这一个目标。

**可迁移启发。** 看任何「自动设计出来的 agent」，先问两件事：它引入了哪种基线里没有的原语？它在测试时多花了多少调用？两件都答不上，分数差就不能直接读成「设计更好」。自己做对照时，至少给基线一个按调用次数对齐的版本（例如把 COT-SC 的采样数加到同样预算）。

## 搜索有多贵

附录 J 只给了两个约数（PDF p. 34）：ARC 上一次完整的搜索加评测约 500 美元 OpenAI API 费用；四个推理域里每个域约 300 美元。主要开销不是元 agent 用的 GPT-4o，而是用 `gpt-3.5-turbo-0125` 评每一个新 agent。作者补了一句：当时更新的 `gpt-4o-mini` 价格不到 3.5-turbo 的三分之一且更强，同样的搜索大约能省到三分之一的成本。全文没有给墙钟时间、总 token 数或四个域的合计。

评价函数被论文自己评为「又贵又丢信息」：只用验证集上的一个数，丢掉了运行日志里的失败与成功模式（PDF p. 11、p. 34）。未来工作里提的改法是让元 agent 读详细的运行日志。GEPA 一篇后来走的正是这条路——让反思模型读轨迹文本，而不是把轨迹压成一个数。

## 安全：写在结论之前

第 6 节第一段就是安全考虑（PDF p. 10）。论文判断：以当时的基础模型和设定，生成代码做出明显恶意动作的可能性极低，但仍可能因能力或对齐不足而造成破坏。实际做了三件事：生成代码一律在隔离容器里执行；人工检查，确认没有有害行为；代码库里放了明确警告。做法对齐 SWE-Bench 与 Voyager 的受控执行环境（PDF p. 10）。

更外面一层是立场论证，论文自己标明超出本文范围（PDF p. 10）：

- ADAS 可能让通往 AGI 的速度超过纯手工路线；
- 他们仍认为发表是净收益：这类算法只用 API 就能写，不需要昂贵 GPU，社区应该知道它的可达性；
- ADAS 可以设计显式、可解释的工作流，提高可控与可审计性，从而降低恶意行为风险；
- 自改进系统的发展看来不可避免，他们希望推动安全的 ADAS，例如接入 Constitutional AI 这类机制。

**我们如何解释它。** 容器隔离与人工检查是实际做了的措施；「可解释工作流能降低恶意风险」是论证，实验里没有测。评价函数就是验证集准确率，这篇也没有报告系统去钻评价函数空子的案例——Darwin-Godel-Machine 一篇把安全写成目标之后，就观察到了拆检测器的行为，但那是后作的发现，不能回写到这篇。

## 限制：论文承认的，和我们读出来的

**论文写进未来工作的（PDF p. 10–11）：**

1. **元 agent 固定。** 高阶 ADAS 让元 agent 本身也被改进。
2. **只做了单步问答。** 没有多步环境交互，没有真实世界应用。
3. **只优化性能。** 成本、延迟、鲁棒性要靠多目标搜索。
4. **评价函数又贵又窄。** 没读运行日志；没处理没有标准答案的主观任务；每次只针对一个域搜，没有专门搜通才 agent。
5. **没有真正接入已有积木。** 搜索引擎、RAG、LangChain 函数、视觉能力、多模型路由都停在设想。
6. **搜索算法简单。** 没有 Quality-Diversity，没有更仔细的探索–利用。

**我们核对原件后额外留下的：**

7. **测试时调用次数不对齐。** 最佳 ARC agent 每题最多 41 次调用，CoT 是 1 次。
8. **「新组合」证据强，「新积木」证据弱。**
9. **ARC 是 $5\times 5$ 简单子集。** 「接近 50%」不能与官方 ARC-AGI 混用。
10. **「consistently outperform」有反例。** MMLU 上一个迁移 agent 低于全部手工基线，GPQA 上打平略低，Haiku 上也有低于基线的格子；MGSM 上最好的三个 agent 没有给代码。
11. **数学上有种子反而更差。** 53.4 对空初始化的 67.5，主表报的是前者。
12. **每个设定只报了一次搜索。** 四个域独立搜，但没有重复搜索、没有报告搜索本身的方差；置信区间只覆盖评测抽样。
13. **摘要里的「coding」指 ARC 上写变换代码，** 不是 HumanEval 或 SWE-bench 这类软件工程基准。

## 放回「哪个部件在自进化」这张表

| 工作 | 进化的部件 | 谁来改 | 外层变不变 |
|---|---|---|---|
| 本篇 ADAS | 内层 agent 的 `forward()` 代码 | 冻住的元 agent | 不变 |
| Darwin-Godel-Machine | agent 自己的代码仓库 | 被选中的父代改自己 | 没有独立的外层 |
| PromptBreeder | 任务提示与变异提示 | 同一个模型按变异算子改写 | 变异提示本身也在进化 |
| GEPA | 模块提示词 | 反思模型读轨迹后改写 | 不变 |
| AlphaEvolve | 算法与 kernel 代码 | 进化框架调度模型改代码 | 不变 |

这篇的真正贡献，不是某个名叫 Structured Feedback 的 agent，而是把三个零件立住了：代码当搜索空间、冻住的元 agent 当搜索算法、验证集分数当评价函数。后作几乎都在这三个零件上各做一次手术：Darwin-Godel-Machine 拆掉冻住的设计师，GEPA 把评价从一个数换成轨迹文本，RRSI 给 harness 的改动加上预算与筛选。

## 可迁移启发

1. **先定搜索空间，再谈搜索算法。** 只改提示词，就别指望搜出新工作流；把空间换成代码，上限立刻打开，实际能长出什么仍由你给的原语决定。
2. **「外层变不变」应当是一个可消融的开关。** 本篇把设计师冻住当默认；把它做成对照项，才能说清「自改进」到底贡献了什么。
3. **档案要留垫脚石。** 第 5、11、12 轮没刷新最高分的设计，是第 14 轮最佳 agent 的零件。只留第一名，这条血缘就断了。
4. **种子要留一条空初始化对照。** 数学上空初始化高 14 个点。越依赖多样推理策略的域，越值得对照。
5. **评价函数决定系统长成什么形状。** 只看准确率，搜出来的就是「更多调用、更深流水线」。想要能部署的 agent，目标里至少要有一项与费用或延迟相关的量，对照里要有按调用次数对齐的基线。
6. **迁移要按「同类 / 跨类 / 跨模型」分开报。** 数学迁数学很稳，迁阅读仍能赢，迁科学就不稳；GPT-3.5 上的第一名不是更强模型上的第一名。

## 关键词回看

- **ADAS**：把智能体系统设计写成搜索问题，三个零件是搜索空间、搜索算法、评价函数。
- **Meta Agent Search**：冻住的元 agent 读档案、写 `forward()`、两轮自反思、验证集打分、写回档案。
- **元 agent 冻住 / 高阶 ADAS**：本篇外层设计师不变；让它也被改进是论文自己写的未来工作，Darwin-Godel-Machine 一篇接着做了。
- **代码搜索空间**：理论上图灵完备，实践里是不到 100 行的框架加 `forward()`，ARC 上只多两个工具。
- **垫脚石**：第 3 轮的「多路 CoT + 集成」，第 5、11、12 轮的三种反馈，组合成第 14 轮的最佳 agent。
- **OPRO 对照**：只优化提示词，数学 30.6 对 53.4，是「工作流不能被提示词搜索替代」的证据。
- **+13.6 / +14.4 / +25.9 / +13.2**：DROP、MGSM、GSM8K、GSM-Hard 上相对该列最强手工基线的绝对差；后两个来自 MGSM 上搜到的 agent 原样迁移。
- **$5\times 5$ 简单子集**：ARC 实验的真实口径；「接近 50%」只在这个口径加 Claude 3.5 Sonnet 上成立。
- **每题调用次数**：CoT 1 次，ARC 最佳 agent 最多 41 次；论文没有按它对齐。
