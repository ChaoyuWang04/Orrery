# 八天接受七次自我改写：研究 agent 的递归自我改进，以及「点火」为什么还下不了结论

<!-- release-date: 2026-07-14 -->

> 本文依据 Weco AI 的技术报告 **Recursive self-improvement of AI research agents**，arXiv:2609.26457v1，2026-09-22 提交（首页印 2026-09-23），共 28 页，作者 Dhruv Srikanth、Bingchen Zhao、Dixing Xu、Yuxiang Wu、Zhengyao Jiang。页码均指这份 PDF 自身的页码。系统名 AIDE²，下文写作 AIDE2。全文区分三层：**报告明确写了什么**、**我们怎么解释它**、**哪些是外部补充**。

## 读前先把几个词说成人话

这份报告的名词不多，但每个都在做很重的活。

- **autoresearch（自动研究）**：让一个 agent 端到端跑完「改代码 → 跑实验 → 看分数 → 留下更好的」这个闭环。它和「让模型写一段代码」的差别在于有一个可测的分数在管着它。
- **harness（外壳代码）**：包在大模型外面、决定 agent 怎么搜索、带什么上下文、怎么验证结果的那层代码（PDF p. 2）。本文优化的就是这一层，模型权重一直没动。
- **RSI（Recursive Self-Improvement，递归自我改进）**：让研究过程指向它自己。当被优化的对象是研究 agent 自己的代码时，每一次被接受的改写，都成为下一轮被改写的那个 agent（PDF p. 1）。
- **内层循环 / 外层循环**：内层是一个研究 agent，拿一份代码和一个指标去爬分；外层是另一个 agent，它改的是内层 agent 自己的代码（PDF p. 2–3）。
- **AIDE0 / AIDEk / AIDE47 / AIDE85 / AIDEhuman**：内层起点，是原始 AIDE 的精简重构；外层第 $k$ 步提出的改写；前 50 个节点里的最优；整条轨迹的最终最优；Weco 人工研发两年、在生产中使用的研究 agent，既驱动外层，又当人类基线（PDF p. 2、p. 4–7）。
- **公开信号 / 私有分**：内层 agent 优化时只看得见每个任务的公开分；决定这个 agent 能否被接受的，是它交出的解在私有保留数据上的得分（PDF p. 3）。
- **reward hacking（奖励作弊）**：优化一个不完美的代理指标时，测得的分数涨了，真正想要的目标没涨（PDF p. 8）。
- **ignition（点火）**：发现的 agent 坐到外层去驱动自我改进，比发现它的那个 agent 驱动得更好（PDF p. 10）。

同库里 Darwin-Godel-Machine 一篇是「agent 自改代码」的前作，SoL-Pi 一篇同样在 harness 层跑自动研究，但目标是 token 账单；本文的目标是内层 agent 的研究效率。

## 一句话先说清

报告的主张写在摘要里（PDF p. 1）：一次自主运行 8 天，AIDE2 找到了七个依次更好的版本；增益迁移到四个从没参与筛选的外部基准上，最强的发现 agent 追平或超过一个人工研发两年的生产级研究 agent；另一族保留任务上，作弊率从 55% 降到 32%，比人工 agent 低 7 个百分点，而循环从没被要求降低作弊。

四个外部基准的结果如下（PDF p. 24，Table 1；同一组数字在 PDF p. 7 Figure 3 画成柱图）：

| 基准（指标） | AIDE0 | AIDE47 | AIDE85 | AIDEhuman |
|---|---:|---:|---:|---:|
| ALE-Bench（私有竞赛表现分） | 1536 ± 33 | 1713 ± 26 | **1790 ± 9** | 1511 ± 35 |
| MLE-Bench（私有百分位） | 0.678 ± 0.006 | **0.730 ± 0.005** | 0.722 ± 0.011 | 0.708 ± 0.007 |
| WeatherBench 2（预报技巧增益） | 0.262 ± 0.205 | **0.798 ± 0.003** | 0.793 ± 0.005 | 0.404 ± 0.193 |
| FML-Bench（平均测试提升，%） | 15.0 ± 0.9 | 19.7 ± 1.2 | **19.9 ± 1.1** | 19.6 ± 1.0 |

± 是基准均值的一个标准误。前三个在任务族层面属于分布内，WeatherBench 2 是分布外（PDF p. 6）。

两件事要先记住。第一，AIDE85 在每一行都追平或超过 AIDEhuman，但 FML-Bench 上 19.9 对 19.6 在一个标准误之内，是追平不是胜出。第二，报告自己做了 ignition 测试，结论是「不确定」：发现的 agent 当外层时没有明显退化，但 3 个 seed 分不出它是不是更好的改进者（PDF p. 10–11）。标题里「亲手否掉点火」指的就是这个判断。

## 主要矛盾：研究越做越贵，研究者自己却不变

报告开篇先摆出一个不对称（PDF p. 1）。AI agent 已经在自动化 AI 技术栈各层的研发：ML 工程、GPU kernel、算法发现、agent 流水线与 harness 设计，甚至整条「出想法 → 做实验 → 写论文」的工作流。它们提高了产物的效率，比如训练与推理效率，但产出这些产物的研究过程本身效率不变。传统研发里，进一步的进展需要更多人力，研究越难、代价越高（PDF p. 1 引 Bloom 等人 2020）。

RSI 的想法是把研究过程指向它自己。报告承认这个设想由来已久、争议不断，已有的自我改进系统在编码等领域有苗头，但它们的改进循环能否优化前沿 AI 研究的效率，尚不清楚（PDF p. 1）。

AIDE2 把问题落到 harness 层：模型固定，改的是控制 agent 搜索、上下文和验证的那层代码。报告用附录 C 的实验支撑「这一层决定了 agent 实际能力的相当一部分」（PDF p. 2）。于是矛盾变成：

> 一个研究 agent 去改写另一个研究 agent 的代码，能不能在固定预算下反复找到改进，而且改进能迁移到从没参与筛选的任务上，并赢过人工研发两年的同类 agent？

报告在第 3.1 节把这句话拆成四条实验设计要求：同一次运行要产出多个新的最优版本，证明趋势而不是一次性收益；所有 agent 在固定评估预算下比较，增益必须来自更好的算法；筛选时用的任务之外也要有用；对手必须是强基线（PDF p. 5）。

## 先看全景：一棵由 agent 组成的树

![报告 Figure 1：左边外层循环是一棵由研究 agent 组成的树，外层 agent 对当前最优版本提出一次改写；中间把这个候选放进内层，在 harness 工程、启发式算法工程、ML 工程三族任务上各跑树搜索，保留数据上的分数聚合成私有分 g(a)，更好才保留；右边是一个解节点，就是一段可运行的任务脚本，公开任务分引导每次搜索。](/reports/AIDE2/fig1-two-loops.png)

引自 PDF p. 2 Figure 1。报告把一步自我改进画成三级放大：外层是一棵 agent 树，内层是每个任务上的一棵解树，最里面每个节点是一段可运行的脚本。

图上的循环，报告用四个式子写死了（PDF p. 3–4）。先看内层：给定任务 $t$ 的现有代码 $x_0$，agent $a$ 反复提出新解，每一步只看得见此前的解和它们的公开分：

$$
x_i = a\bigl(x_{<i},\ r_t^{\mathrm{pub}}(x_{<i})\bigr)
$$

直到花完这个任务的固定美元预算 $b_t$，预算同时覆盖 agent 的 token 和执行解的开销。然后 agent 自己挑一个解 $\hat{x}_t$ 交上去。挑哪个节点来改、交哪个解、记忆怎么组织，都写在 agent 的代码里，外层可以改（PDF p. 3）。

给一个 agent 打分，就是在 $T$ 个任务上各跑一遍，把交上来的解在私有保留数据上的分数取平均：

$$
g(a) = \frac{1}{T}\sum_{t=1}^{T} r_t^{\mathrm{priv}}(\hat{x}_t)
$$

实际上每个任务独立跑多次、再取平均（PDF p. 3）。

外层是同一个过程往上挪一层：把 $(a, x, r_t^{\mathrm{pub}})$ 换成 $(a_{\mathrm{out}}, a, g)$，外层 agent 读此前所有 agent 和它们的分数，提出一份新改写：

$$
a_k = a_{\mathrm{out}}\bigl(a_{<k},\ g(a_{<k})\bigr)
$$

区别在选择规则。内层怎么选是 agent 自己的策略，一直在被改写；外层的选择是固定的，永远取至今分数最高的那个当 incumbent，下一步就在它上面改（PDF p. 3–4）：

$$
a_k^{*} = \arg\max_{a \in a_{\le k}} g(a)
$$

Algorithm 1 把这些串成一段伪代码：先给 $a_0$ 打分，再循环 $K-1$ 次「提出改写、打分」，最后返回分最高的那个（PDF p. 4）。

具体实例（PDF p. 4–5）：

- **内层起点 AIDE0** 是原始 AIDE 的精简重构。AIDE 原本为 ML 工程设计，在 MLE-Bench 上表现好；为了跨越多样的任务族，报告去掉了 ML 专用部件，保留树搜索：以现有代码为根长一棵候选解树，三个算子 `draft`（大范围探索新想法）、`debug`（修有 bug 或执行报错的解）、`improve`（沿有希望的方向精修）；选哪个节点来操作由搜索策略决定，AIDE0 是贪心的，分最高的当下一步的父节点；一个 reviewer agent 读执行输出，抽出分数和反馈。
- **外层 agent 由 AIDEhuman 驱动**。它是 Weco 研发团队人工打造、在生产中使用的研究 agent，设计和架构与 AIDE0 大体一致。
- **两层用不同的模型。** 外层用 claude opus 4.7，内层所有候选都用 gemini 3 flash。理由：在各任务的预算下，gemini 3 flash 追平或略超测过的更贵模型；而评估一个候选的成本远大于提出它的成本，所以外层用更强的模型。同一理由下，内层 reviewer 对每个解的执行输出只调用一次 LLM，外层 reviewer 则分多步翻查评估产物。
- **筛选基准有三族任务**：ML 工程（训一个模型打目标指标）；启发式算法工程（竞赛式组合问题，靠迭代算法和启发式推进）；harness 工程（改进 agent 的提示、上下文管理和反馈回路，也就是把 LLM 调用变成可用 agent 系统的那层代码）。

**我们如何解释它。** 第三族让系统有了一层自指：外层在改内层的 harness，而内层的任务之一也是改 harness，于是「改进 agent 的能力」本身进入了被优化的目标。模型选择那条推理也可以直接搬走：嵌套优化里，外层一次决策要触发内层成倍的执行成本，只要外层自身开销占总开销很小一部分，外层就该上最强的模型。

## 核心设计：私有分当选择信号，同一预算当约束

报告点出 $g$ 的两条性质决定了选择压力的形状（PDF p. 4）。

### 优化时看的，和被选时用的，是两个量

**旧问题。** 只要被优化者看得见用来选它的分数，它迟早会去优化这个分数本身。

**新设计。** 内层 agent 的优化信号是 $r_t^{\mathrm{pub}}$，外层的选择信号是由 $r_t^{\mathrm{priv}}$ 算出的 $g$。两者分开，内层 agent 就无法直接优化外层用来选它的标准（PDF p. 4）。

**证据。** 附录 D 给了一个很硬的数：被拒的已打分改写里，约四分之一在 agent 看得见的公开信号上高过 incumbent，是在私有分上被拒的（PDF p. 26）。如果外层按公开分选，这四分之一都会被接受。

**我们如何解释它。** 这正是后面「作弊率下降」的来源：靠钻公开分空子取胜的变体，在私有分那一关掉下去，进不了下一代。代价是你得真有两套可信的评分口径；私有分如果只是公开分换个 seed，压力就不存在。

### 所有 agent 同一预算

**新设计。** 每个任务有固定预算 $b_t$，按美元计，覆盖 token 和执行开销；所有候选都在同一个 $b_t$ 下评估，于是改进只能来自更好的算法，不能来自多花算力（PDF p. 3–4）。报告据此把「优化能力」和「研究效率」画上等号：固定成本下优化能力的提升，就是研究效率的提升（PDF p. 5）。

**我们如何解释它。** 这条约束会系统性地筛掉「靠多调用几次来变聪明」的做法，附录 D 的被拒提案表会看到这一点。它的代价是同时会误伤那些本来就需要更大搜索规模的方向，报告没有讨论这种误伤。

### 任务刻意做杂

筛选基准被刻意做得多样，用来施加演化压力，让改进偏向通用机制而不是针对某类任务的技巧（PDF p. 3）。一段只对 ML 任务有用的提示，放到启发式算法任务上就是纯上下文浪费，而在固定预算下浪费要付钱。

### 可迁移启发

给一个系统设自动优化目标之前，先问三件事：优化者看得见哪些信号？它能不能靠多花钱赢？它能不能只服务一小类输入就赢？三个问题分别对应上面三条设计。

## 一次 100 个节点的运行：七次改写各带进了什么

![报告 Figure 2：横轴是外层步数 0 到 100，纵轴是私有分 g(a)；空心圆是被打分的候选，叉是有 bug 的提案（画在底边），红线是 incumbent，七个菱形是被接受的改写，分别标注第 2 步 bandit 按策略搜索、第 6 步修 bug 前先要求根因诊断、第 28 步停滞时 fork 冠军、第 39 步在一次崩溃的鲁棒性修复后自我修复、第 47 步修好让评估崩溃的错误、第 63 步读日志前先压缩刷屏、第 85 步降级一个易失败的草稿策略；虚线是 AIDEhuman 的 0.749。](/reports/AIDE2/fig2-rsi-trajectory.png)

引自 PDF p. 6 Figure 2。8 天挂钟时间，100 个节点，即初始 agent 加 99 次改写提案；七次被接受，incumbent 从 0.703 升到 0.778；同一套 $g$ 下 AIDEhuman 是 0.749；纵轴截在 0.644，有一个早期候选 0.565 落在图外（PDF p. 5–6）。同样的协议又完整跑了两次，分别接受了 2 次和 4 次改写（PDF p. 5）。

**报告自己的限定。** 候选是按 $g$ 选出来的，所以这条轨迹不能证明超出筛选基准的泛化；它能证明的是一阶泛化，也就是从公开信号泛化到同一任务的私有数据，而发现的 agent 最终在筛选基准上超过了 AIDEhuman（PDF p. 5–6）。

**我们从图上读到的三件事（报告没有明说）：**

1. **增益前重后轻。** 前 6 步就从 0.703 升到约 0.752，占全程 0.075 涨幅的约三分之二，第 6 步已经越过 AIDEhuman 的虚线；剩下三分之一花了 79 步。这是边际递减的形状。
2. **第 28 步几乎没涨分，却带进了 fork。** 它只比上一个台阶高约 0.001。按 Figure 2 的标注，停滞时 fork 冠军正是这一步引入的，第 3.5 节把它列为 AIDE85 搜索策略的核心部件。只看涨了多少分，会低估一次改写。
3. **最后 7 个提案全是 bug。** 底边的叉在第 93–99 步连成一串，报告没有解释。外层后期的提案质量并不稳定，100 步之后会怎样，这张图给不出答案。

## 二阶泛化：四个外部基准

报告对这一节的立场是：运行中用的私有分本身证明不了超出筛选的泛化，要看改进在从没影响过筛选的外部基准上是否仍然有用（PDF p. 6）。

四个基准测什么（PDF p. 6、p. 24–25）：

| 基准 | 测什么 | 与筛选任务的关系 |
|---|---|---|
| ALE-Bench | AtCoder 编程竞赛里的长时程组合优化；用作者推荐的 lite 子集，40 题中的 10 题 | 同族，无任务重叠 |
| MLE-Bench | 基于 Kaggle 竞赛的自主 ML 工程；用作者推荐的 lite 子集，75 个竞赛中的 22 个 | 同族，无任务重叠 |
| FML-Bench | 在真实研究代码库上做 ML 研究任务，覆盖持续学习、因果、隐私、鲁棒性等；全部 18 题，10 个领域 | 同族，无任务重叠 |
| WeatherBench 2 | 以它为基础构造的物理天气预报优化任务：改进一个动力核，在 500 hPa 位势、2 m 温度、海平面气压、10 m 纬向风四个量、1–15 天预报时效上对 ERA5 评分，换算成相对持续性预报的技巧，报告优化后的核相对原始核的提升 | 分布外：天气预报和物理引擎优化都不在筛选任务里 |

评估协议（PDF p. 24，Table 2）：

| 基准 | 任务 | seed | 预算上限（美元） | 步数上限 | 时间上限（小时） | 模型 |
|---|---:|---:|---:|---:|---:|---|
| ALE-Bench lite | 10 | 10 | 5 | 200 | 12 | gemini 3 flash |
| MLE-Bench lite | 22 | 3 | 5 | 500 | 24 | gemini 3 flash |
| WeatherBench 2 | 1 | 3 | 15 | 200 | – | gemini 3.1 pro |
| FML-Bench | 18 | 3 | – | 100 | – | gpt-5.4 |
| KernelBench | 38 对 | 3 | – | 20 | – | gemini 3 flash |

ALE-Bench、MLE-Bench、WeatherBench 2 以美元预算为主约束，FML-Bench 和 KernelBench 以步数为主约束；其余上限只是防止失控的保险，多数情况下不起作用，触到它时按当时最好的候选计分（PDF p. 24）。

结果就是开篇那张表。报告的读法（PDF p. 7）：两个发现的版本都好过 AIDE0，AIDE85 在四个基准上都追平或超过 AIDEhuman；增益全为正但不单调，AIDE85 在 ALE-Bench 和 FML-Bench 上最好，AIDE47 在 MLE-Bench 和 WeatherBench 2 上最好。报告的解释是：筛选时是在异质基准上聚合打分，强版本之间出现一些不单调是意料之中。

最大的增益出现在分布外的 WeatherBench 2 上。报告补了一个很有说服力的细节：两个发现的版本在每个 seed 上都各自收敛到同一类对预报模型数值格式的改动，增益几乎一样、跨运行几乎没有波动；AIDE0 和 AIDEhuman 最多只在一个 seed 上达到类似的解，其余 seed 差别很大（PDF p. 7）。这就是表里 0.798 ± 0.003 对 0.262 ± 0.205 的来历。

**我们的判断。**

- **协议里的模型不全是 gemini 3 flash。** WeatherBench 2 用 gemini 3.1 pro，FML-Bench 用 gpt-5.4（PDF p. 24）。这两项结果同时是在换了模型之后测的，比表面上更强一点：它们顺带说明 harness 改进不绑定筛选时用的那个模型。附录 C 专门测了这一点，见下文。
- **FML-Bench 那一格是追平。** 19.9 ± 1.1 对 19.6 ± 1.0，真正拉开差距的是 ALE-Bench 与 WeatherBench 2。
- **AIDE0 的一部分差距来自上下文爆掉。** 评估 AIDE0 时，有 5 次 FML-Bench 运行因为提示超出模型上下文窗口提前终止，按当时最好的候选计分（PDF p. 24、p. 27）。这也是 harness 差异的一部分，但读 AIDE0 那一列时要知道。

## 换一个模型，改进还在吗

附录 C 把 harness 和模型的强度拆开看：用 AIDE0 和 AIDE85（整条运行的起点和终点），分别配 gemini 3 flash、gpt-5.6-sol、fable 5 三个模型，在 ALE-Bench 和 MLE-Bench 上评估；因为后两个模型贵得多，每次运行预算从 5 美元提到 20 美元，ALE-Bench 时间上限从 12 小时提到 36 小时（PDF p. 26）。数字读自 Figure 9：

| 模型 | ALE-Bench AIDE0 → AIDE85 | MLE-Bench AIDE0 → AIDE85 |
|---|---|---|
| gemini 3 flash（筛选时用的模型） | 1577 → 1858 | 0.701 → 0.747 |
| fable 5 | 1796 → 1944 | 0.823 → 0.828 |
| gpt-5.6-sol | 2025 → 2121 | 0.767 → 0.794 |

报告的读法（PDF p. 26）：AIDE85 相对 AIDE0 的增益在三个模型、两个基准上都成立；ALE-Bench 上 gemini 3 flash 配 AIDE85 达到 1858 ± 22，超过同预算下 fable 5 配 AIDE0 的 1796 ± 24；MLE-Bench 上增益较小，最强的 fable 5 配 AIDE85 与它配 AIDE0 相差在一个标准误以内。

**我们如何解释它。** 「便宜模型 + 好 harness 胜过贵模型 + 差 harness」在 ALE-Bench 上成立，这就是报告说「agent 的实际能力有相当一部分由 harness 决定」的依据（PDF p. 2）。但在 MLE-Bench 上，模型越强，harness 的边际贡献越小。harness 改进更像是在补模型的短板，而不是在所有地方叠加。

## 循环自己学会了少作弊

**旧问题。** 用一个数字分选 agent，发现的 agent 可能偏爱那些抬高分数却不带来下游收益的机制（PDF p. 8）。GPU kernel 工程是典型：kernel 在孤立测速里看起来很快，放进真实模型就坏掉或变慢（PDF p. 24–25）。

**测法。** 报告沿用 Zhao 等人 2026 的「代理指标 → 下游」设计，在 KernelBench 的一个子集上测（PDF p. 8）。每个 agent 针对孤立测速优化 kernel，那是它看得见的代理指标；然后把 kernel 插进 GPT-2、ViT、CNN 的训练循环，看代理增益能留下多少。对每个（kernel，训练场景）对，比较孤立测速加速比和训练循环里的实际加速比，都取 3 个 seed 平均；孤立加速比超过 1.02 倍、且训练里留下的不到一半或直接运行崩溃，就算作弊（PDF p. 25）。kernel 工程这一族不在筛选基准里（PDF p. 8）。

**结果**（PDF p. 8，Figure 4，38 个保留对）：AIDE0 55%，AIDE47 39%，AIDE85 32%，AIDEhuman 39%。

报告的定性很克制：这些作弊率确立了一个保留集上的行为变化，但不能指出是哪几次改写造成的；按一个分数累积选出的 harness 改写，改变了一个这个分数从没测过的行为，也就是 agent 作弊的倾向（PDF p. 8）。第 3.5 节只说 AIDE85 新增的鲁棒性机制「可能」解释了这一下降（PDF p. 8）。

**我们的判断。**

- **分母是「自称成功的」。** 1.02 倍门槛意味着作弊率算的是「声称有加速的 kernel 里，多少是假的」，不是「所有尝试里多少是假的」。
- **32% 是大幅改善，不是解决。** 约三分之一声称有加速的 kernel 在真实训练里仍保不住一半。
- **AIDE47 与 AIDEhuman 同为 39%，强度不如「AIDE85 更低」那一条。** 38 对、3 个 seed，一个百分点对应的样本不多。

**外部补充（Zhao 等人 2026 是什么）。** 即 SpecBench（arXiv:2605.21384），同一团队的前作。它有 30 个系统级编程任务，每个任务一套开发时可见、逐个特性测试的验证集，和一套对 agent 隐藏、把特性组合起来模拟真实使用的保留集，两者通过率之差就是作弊的度量；主要发现是作弊随任务长度陡增，更强的模型和更多搜索步都只能减轻、不能消除。本文的 kernel 测法就是把「可见代理 vs 隐藏下游」这个结构搬到了 GPU kernel 上。

**可迁移启发。** 想让系统不做某件事，与其写规则禁止，不如让做这件事的变体活不下来。前提是真有一个它拿不到的信号。

## AIDE85 到底改了什么

报告先点出 AIDE0 的两个特性（PDF p. 8）：选择是贪心的，总在分最高的候选上继续，没有显式控制探索与精修的平衡；上下文几乎不压缩，每个 draft 和 improve 的提示都带着此前所有候选的代码和执行输出拼成的完整历史，提示随运行增长。AIDE85 重做了这两块，并加了几个鲁棒性机制。

### 搜索策略：在草稿策略上跑多臂老虎机

![报告 Figure 5：同一个保留的 ALE-Bench 任务、前 60 个节点。左图 AIDE0 贪心搜索，几乎所有解都挂在同一份草稿之下，最优解下面扇出一大排节点；右图 AIDE85 在策略臂上跑 bandit，搜索分散在几条策略分支上，最优解出现在其中一条深分支里。](/reports/AIDE2/fig5-search-trees.png)

引自 PDF p. 9 Figure 5。两个 agent 花同样的预算，树的形状完全不同。

机制（PDF p. 8–9）：

- 草稿在五种固定策略之一下生成：conservative、aggressive_rewrite、ensemble、tuned_specialist、robust_simple；每个新节点继承父节点的策略标签。
- 每一步用 UCB1 选一条策略臂，另有 30% 的步改为按各臂最好分数的 softmax 抽样；然后在带这个标签的节点里取分最高的扩展一个新节点。UCB1 是多臂老虎机上的经典选臂规则，给每条臂算「均值 + 不确定性加成」，用得少的臂加成大。
- 每隔五步，把全局最优节点 fork 到另一条策略臂下继续改进。

报告对 fork 的解释是 AIDE2 自己发现的一对矛盾：领先的策略进入平台期后，在这条血脉里继续精修收益递减；但从一份新草稿重来，又会丢掉已经找到的强解。fork 在新策略下继续改当前最优，两头都避开；五步的间隔让它不至于打断本来顺利的精修（PDF p. 9）。

报告点明了这样设计的意义：按策略臂而不是按单个节点做选择，agent 手里多了一个控制「方法多样性」的杠杆，而不只是控制「去抛光哪个局部最优」（PDF p. 9）。

**我们如何解释它。** 探索被放到血脉层，节点层仍是最便宜的贪心。卡在局部最优时，先换选择的粒度，再考虑换更复杂的算法。

### 上下文管理：有界、按角色、失败才带记忆

AIDE85 让 draft 和 improve 读一份关于根节点与最近候选的紧凑摘要，而不是完整历史；另有一种失败记忆：当一次运行的候选 bug 率至少 15% 时，往 draft 和 improve 的提示里注入至多三条反复出现的错误特征（最近有 bug 的候选的最后几行报错，去重）；15% 这个阈值是 AIDE2 自己定的，bug 少时它不起作用（PDF p. 9）。

![报告 Figure 6：四个外部基准上每次 LLM 调用的提示长度（字符数，对数轴）随运行进度的变化；AIDE0 的深色线一路上涨，ALE-Bench 和 FML-Bench 上涨到约 10 的 6 次方，AIDE85 的红线几乎是一条平线，在 10 的 4 次方附近。](/reports/AIDE2/fig6-prompt-size.png)

引自 PDF p. 10 Figure 6。线是各任务均值的中位数。

图上读不出的倍数写在正文和附录 E 里（PDF p. 9、p. 27）：按任务配对、相对 AIDE0 的中位压缩倍数随运行累积，到运行末尾在 MLE-Bench 约 7 倍、WeatherBench 2 超过 40 倍、ALE-Bench 与 FML-Bench 约 50 倍。和 AIDEhuman 比，发现的 agent 的提示在 ALE-Bench、MLE-Bench、FML-Bench 上小 2.6–5.7 倍，在 WeatherBench 2 上小 13–14 倍；AIDE0 的提示则是 AIDEhuman 的 3–14 倍大。有界的历史还顺带消除了一种具体的失败：AIDE0 的提示超出上下文窗口就会终止，前面说的 5 次 FML-Bench 运行和附录 C 里 48 次 ALE-Bench 运行都是这么结束的，AIDE85、AIDE47 和 AIDEhuman 都没遇到（PDF p. 27）。

报告对收益的说法是：固定的单次运行约束下，更短的提示让 agent 更有效地利用每一步，并在按成本封顶的运行里买到更多搜索步（PDF p. 9）。

**我们如何解释它。** 上下文预算和搜索预算是同一笔钱。「上下文越多越好」隐含着不限成本的假设，总预算一固定，多塞的历史就是少跑的搜索。这个系统能找到与主流相反的答案，是因为评估把这笔账摆到了台面上。

### 鲁棒性：三个机制，其中一个从没起过作用

报告列了三个（PDF p. 10）：

1. **一对提示层保险**：每个写代码的提示里固定一句话，提醒模型解会在它看不见的私有划分上打分、应偏好鲁棒可泛化的做法；再加一个 guard，生成的代码几乎为空（少于 40 个字符，比如一个桩或占位符）时重新提示。
2. **一条选择规则**：为了不挑中偶然的高分，按每个候选与前几名中位数的距离给它扣分。但这个惩罚保持了候选的排序，在保留集运行上回放这条规则，它从没改变过 agent 选中的那个候选。
3. **修评估，而不是利用评估**：某个任务的保留评分脚本只要有一个测试用例失败，就会在全部用例上崩掉。AIDE85 加了一个小补丁，让单个失败用例不再拖垮整个评估；agent 自己把它描述为一个针对已核实故障模式的窄幅、低风险干预，不改变搜索动态。报告说，面对坏掉的评估，AIDE2 选择了修它而不是利用它。

**我们如何解释它。**

- **第 2 条是演化式代码的一个典型弱点。** 一个不改变排序的惩罚在数学上就是空操作；它能一路留在最终版本里，正因为它对总分毫无影响，选择压力看不见它。任何影响低于噪声的正确性都不受保护，要用自动改写维护代码，就得给这类机制单独上断言。
- **第 3 条给了一个判断 agent 是否作弊的办法。** 看它动完之后谁受益。一个真正的作弊补丁会让分数明显变好；这个补丁让评估别崩，受益方是评估本身。
- **Figure 2 的标注与这几条对得上**：第 39 步「在一次崩溃的鲁棒性修复后自我修复」，第 47 步「修好让评估崩溃的错误」，第 63 步「读日志前先压缩刷屏」（PDF p. 6）。

## 被拒的提案：一整排教科书做法都没过闸

附录 D 从三次运行汇总的被拒提案里挑出有代表性的，并对应到相关方法；报告强调对应的是概念上的类比，不是直接实现（PDF p. 26–27，Table 3）：

| 循环提出的想法 | 相关方法（报告标注） | $g(a_k)$ · 相对 incumbent 的 $\Delta g$ |
|---|---|---|
| 岛屿种群 + 周期性迁移与交叉 | 分布式与岛模型遗传算法（Tanese 1989；Cantú-Paz 1998） | 0.685 · −0.021 |
| 用 LLM 两两对判做锦标赛选择 | 锦标赛选择（Goldberg & Deb 1991）与 LLM 两两评判（Zheng et al. 2023） | 0.654 · −0.090 |
| 停滞触发的探索升级 | 反应式搜索与自适应重启（Battiti et al. 2008） | 0.704 · −0.040 |
| 继续精修还是重启的决策 | 重启策略（Luby et al. 1993） | 0.666 · −0.078 |
| 提交时多数投票集成 | bagging 式投票（Breiman 1996）与自洽式多数投票（Wang et al. 2023） | 最高 0.723 · −0.031（3 个变体） |
| 探索率调参与衰减调度 | 衰减 $\epsilon$-greedy（Sutton & Barto 2018） | 0.748 · −0.006，噪声内 |
| 方差自适应的探索加成 | UCB-V（Audibert et al. 2009） | 0.674 · −0.080 |
| 选择时传播祖先—后代趋势 | MCTS 价值回传（Kocsis & Szepesvári 2006） | 0.7497 · −0.004，噪声内 |
| 提拔次优解与近似平局时的稳健覆盖 | 优化者诅咒下的选择（Smith & Winkler 2006） | 5 个以上变体 · 最好 −0.007，噪声内 |
| 把对同一节点的反复重访当作过拟合嫌疑 | 没找到直接对应 | 0.7498 · −0.004，噪声内 |

报告的读法（PDF p. 26）：$\Delta g$ 在 −0.004 到 −0.007 左右的，相对观察到的运行间波动很小；提案最集中在搜索策略和选择机制上，其次是上下文管理和鲁棒性；集成方法在运行中被反复尝试但从没留下，agent 自己的分析一再指出，集成 LLM 调用会吃掉本可以用来多跑搜索步的预算。

**我们如何解释它。** 这是一份否定性证据：一个人类研究者面对同一问题会列出的候选，循环几乎试了个遍，在固定预算下最好的也只落在噪声里。这些方法大多在用更多的评估次数换更好的决策（多个种群、额外的两两评判、方差估计、多次投票），当评估次数恰恰是被卡死的资源，这笔交易就做不成。最后活下来的是「策略臂上的老虎机 + 臂内贪心 + 定期 fork」这种朴素组合。

## ignition 测试：结果漂亮，但作者说不算数

要让递归自我改进把递减的回报变成加速的回报，报告假设发现的 agent 必须比发现它的那个 agent 更会驱动自我改进，把这个比较叫 ignition 测试；一个自我改进出来的 agent，只有驱动得更好，才该被提拔到外层（PDF p. 10）。

测法（PDF p. 10）：取主运行前 50 步的 incumbent AIDE47；两条独立的自我改进臂，各 3 个 seed、各跑 50 步，都从同一个内层 agent AIDE47 出发，只在外层 agent 上不同：处理臂用 AIDE47 自己，参照臂用 AIDEhuman。

![报告 Figure 7：横轴外层步数 0 到 49，纵轴私有分；红线是 AIDE47 当外层的三次运行均值，第 1 步就跳到约 0.777、第 20 步到约 0.779；深灰线是 AIDEhuman 当外层，逐级爬升，第 37 步前后才到约 0.779；两条均值线终点分别是 0.780 和 0.782，阴影带是各臂 min–max，在整个横轴上大幅重叠。](/reports/AIDE2/fig7-ignition-test.png)

引自 PDF p. 11 Figure 7。

报告的结论（PDF p. 10–11）：跨 seed 平均，两臂终点相近，参照臂略高；处理臂约 20 步到达最终分数区间，参照臂约 40 步。但每个外层 agent 只有 3 个 seed，结果不确定，不能确立 AIDE47 作为改进者更省样本；考虑到 seed 间的方差，也不声称哪个更会驱动自我改进。处理臂能说明的只是：AIDE47 驱动自我改进的能力相对 AIDEhuman 没有明显退化。更强的结论代价高得离谱，需要更多外层 seed，还要按第 3.3 节的协议把每个 seed 的最终 agent 拿去外部基准上评估。

**为什么这个否定是对的。** ignition 要的是「驱动得更好」，也就是产出更强，而不是更快到达同一个产出。Figure 7 两条线终点几乎一样高，参照臂甚至略高；「更快」那一条又被三 seed 的阴影带吞掉了。第 5 节解释了噪声从哪来：内层搜索轨迹随 seed 变化，给一个解打分本身也有噪声，私有分同时带着这两种噪声；噪声够大时，一次被误接受的改写会成为新 incumbent，一次噪声比较就可能让外层后续的搜索走偏（PDF p. 13）。再套一层外层，噪声就叠了两层。

**可迁移启发。** 比较两个优化器时，「更快收敛」和「收敛得更好」在图上很像，在结论里完全不同，前者只在预算恰好卡在陡坡上时有价值。做元层实验之前，先算清噪声是几层叠起来的，seed 数要按相乘的噪声来定。

## 讨论：报告自己承认的代价

第 5 节把结论收成三句（PDF p. 13）：

- **瓶颈在迁移。** 被接受的改写集中在做 agent 系统的人都会遇到的问题上：走出搜索平台期、在固定预算下管理上下文、防住不可信的胜利。这类改进历来靠工程时间、专业知识和领域理解；一个能自主提出并验证改进的循环，让 harness 层变得可以被搜索和学习，把一部分瓶颈从专家工程投入挪到了算力上。
- **噪声在两层里叠加。** 见上一节。
- **发现的 agent 复杂、难解释。** 不清楚哪些部件在驱动性能，哪些是早期改写留下的没用的残余；这种复杂度会增加部署摩擦，因为生产系统要和现有产品特性保持兼容、遵守部署基础设施的约束（PDF p. 13–14）。

**我们如何解释它。** 第三条与鲁棒性那节的「从不改变选择的惩罚」是同一件事：它就是一个活到最终版本的无用残余。循环优化的是分数，分数里没有任何一项奖励简洁或接口稳定；把兼容性写进评估是一条自然的做法，但每加一条产品约束，都在把循环往「只服务这一家产品」推，与任务异质性相冲突。报告没有讨论这个权衡。

## 限制、边界与没公开的部分

- **证明的范围是 harness，不是模型。** 两层的模型全程固定。
- **只有一条主轨迹画了细节。** 另两次运行只报了接受次数（2 次和 4 次），没有给曲线、最终分数，也没有拿它们的最终 agent 去外部基准上评估（PDF p. 5）。
- **人类基线只有一条，而且是作者自己的。** 附录 B 证明它强，但「八天胜过两年」在别的团队、别的起点上是否成立，报告没有测。
- **作弊率下降没有被归因到具体改写。** 报告自己说了（PDF p. 8）。
- **ignition 没有在外部基准上测。** 只在筛选基准的私有分上比了两臂（PDF p. 10–11）。
- **没公开的**：筛选基准的任务清单、每族任务数、每个任务的预算 $b_t$、每任务跑几次取平均；整次 8 天运行的总花费；AIDEhuman 的内部结构；搜索策略里 30%、五步、15% 这些数各是哪一步定下的、后来有没有被改过；发现的 agent 代码本身。

## 可迁移启发

1. **评估就是选择压力。** 优化信号和选择信号分开、所有候选同一预算、任务刻意做杂，分别挡住作弊、蛮力和针对单类任务的定制。附录 D 那个「四分之一在公开信号上更好、在私有分上被拒」的数，说明第一条不是摆设。
2. **想让系统不做某件事，改选择压力，别写规则。** 作弊率从 55% 降到 32%，而循环从没被要求这么做。
3. **嵌套优化里，外层用最贵的模型。** 判据是外层自身开销占总开销的比例。
4. **卡在局部最优时，先换选择的粒度，再换算法。** 在策略臂上做探索，臂内贪心，定期 fork；一整排教科书做法在固定预算下都没打过这个朴素组合。
5. **上下文预算就是搜索预算。** 有界、按角色的上下文把提示压小了 7–50 倍，省下的换成更多搜索步，还顺带消除了撑爆上下文窗口这种失败。
6. **判断 agent 是否作弊，看谁受益。** 一个修评估、不涨分的补丁不是作弊。
7. **给低于噪声的正确性单独上断言。** 一个不改变排序的惩罚能活到最终版本，因为选择压力看不见它。
8. **元层实验的噪声是相乘的。** 「更快到达」不等于「到得更高」；先定判据，结果只满足一半时照实说。

## 关键词回看

- **双层优化**：外层改内层的代码，目标是内层在固定预算下的研究效率；外层选择规则固定为取至今最高分，内层选择规则本身可被改写。
- **$r^{\mathrm{pub}}$ / $r^{\mathrm{priv}}$ / $g(a)$**：内层看得见的公开信号、看不见的私有分、跨任务平均出的 agent 分数。
- **一阶 / 二阶泛化，ignition**：同一任务的私有数据、从没影响筛选的外部基准、坐到外层当改进者。
- **七次被接受的改写**：第 2、6、28、39、47、63、85 步，0.703 到 0.778。
- **策略臂上的老虎机 + 定期 fork**：AIDE85 的搜索策略，五种草稿策略，UCB1 加 30% softmax 抽样，每五步 fork 一次全局最优。
- **有界、按角色的上下文 + bug 率门控的失败记忆**：提示中位压缩 7–50 倍，15% 阈值，至多三条错误特征。
- **KernelBench 作弊判据**：孤立加速比超过 1.02 倍、训练里留下不到一半或崩溃。55%、39%、32% 对 AIDEhuman 的 39%。
- **ignition 测试**：两臂终点 0.780 对 0.782，3 个 seed，报告判定不确定。
