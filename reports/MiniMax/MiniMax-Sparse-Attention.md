# MSA：在 GQA 上按组挑块，让索引器只做选择

<!-- release-date: 2026-06-01 -->

> 本文依据 MiniMax 发布的 **MiniMax Sparse Attention**，arXiv:2606.13392v2，2026-06-12，共 30 页（正文与参考文献 p. 1–21，附录 p. 22–30）。页码均指这份 PDF 自身的页码。文中会区分三件事：**报告明确写了什么**、**我们怎么解释它**、**哪些是外部资料或本文推算**。

## 读前先把几个词说成人话

这篇论文只讲注意力这一件事，但它同时借用了模型结构和 GPU 内核两边的词。先把会反复出现的说清楚：

- **Token（词元）**：模型读写内容的最小单位。100 万字的材料会被切成上百万个 Token。
- **Query / Key / Value（查询 / 键 / 值）**：注意力的三个角色。当前 Token 拿 Query 去和历史每个位置的 Key 比相关度，再按相关度加权读取那些位置的 Value。
- **KV Cache（键值缓存）**：生成时把算过的 Key 和 Value 存下来，吐下一个 Token 时不必重算整段历史。
- **Prefill 与 Decode（预填充与解码）**：一个请求先一次性读完输入（prefill），再逐个吐字（decode）。前者多半被算力卡住，后者多半被显存带宽卡住。
- **GQA（Grouped-Query Attention，分组查询注意力）**：多个 Query 头共用一套 Key/Value，少存、少搬 KV。共用同一套 KV 的那些 Query 头，论文叫一个 **GQA 组**（PDF p. 3）。
- **稀疏注意力（sparse attention）**：每个 Query 不看全部历史，只看挑出来的一小部分。挑的那一步叫**索引**，挑人的模块叫**索引器（indexer）**。
- **Top-k**：只留分数最高的 $k$ 个对象，其余一律不算。
- **KL 散度（Kullback–Leibler divergence）**：衡量两个概率分布差多少。这里用来让索引器的打分去模仿主注意力的关注分布。
- **算术强度（arithmetic intensity）**：每从显存搬 1 个字节做多少次运算。强度低，GPU 的计算单元就在等数据。
- **CTA（Cooperative Thread Array，线程块）**：GPU 上一次调度的一组线程，内核里的并行单位。

论文自己造的名字只有一个：**MSA（MiniMax Sparse Attention）**。它把一次注意力拆成两条支路，便宜的 **Index Branch（索引支路）** 负责挑块，**Main Branch（主支路）** 只对挑中的块做精确的 softmax 注意力（PDF p. 1、p. 4）。

对照时会点到几篇站内已有的稀疏注意力解读，但不搬它们的表：DeepSeek-V3.2 一篇讲 DSA（逐 Token 选、所有头共用一份索引），NSA 一篇讲三分支的原生稀疏注意力，MoBA 一篇讲大块路由。

## 先讲矛盾：稀疏注意力的零件越堆越多

长上下文的老问题是平方账。每个 Query 都要和它之前的所有 Key 比一次，一次因果注意力的计算量是（PDF p. 3，式 1 之后）：

$$
F_{\mathrm{GQA}}(N)=2\,H_q\,d_h\,N^2
$$

$N$ 是序列长度，$H_q$ 是 Query 头数，$d_h$ 是每个头的维度。上下文从 10 万涨到 100 万，比较次数涨 100 倍。论文开篇说，agent 工作流、仓库级代码推理和持久记忆都要同时盯住几十万到上百万 Token，平方项在部署规模上撑不住（PDF p. 1–2）。

社区的出路有两条（PDF p. 2）：

1. **混合架构**：把一部分 softmax 层换成线性注意力或滑动窗口。MiniMax 自己的 MiniMax-01、MiniMax-M1 走的就是这条路，站内有这两篇。
2. **稀疏化 softmax 注意力本身**：DSA、MoBA、NSA 这一类。

MSA 选第二条，理由写在引言里：留在 softmax 注意力范式里，才能最大程度复用已有的软件和硬件（PDF p. 2）。但这条路有自己的麻烦。为了能训、能加速，已有方案往往要堆分支、辅助输出、写死的窗口和 sink 规则，头维度也被某些设计卡住。MSA 给自己定的原则是奥卡姆剃刀：大量消融之后，只留必要的零件（PDF p. 2）。

于是矛盾变成：

> 稀疏注意力要在三件事上同时成立：选择要看内容，训练期就要稀疏，GPU 上要真的变快。MSA 问的是，在最常见的 GQA 骨干上，最少需要几个零件就能做到这三件事。

它交出的答案有四块：挂在 GQA 组上按块选，索引器只做选择器，用 KL 加梯度切断把不可导的 Top-k 训出来，再配一条专门的 GPU 执行路径。下面按这个顺序讲。

## 一句话先说清

MSA 在标准 GQA 层上只多加两张投影矩阵（PDF p. 4）。索引支路为每个 GQA 组独立挑出 $k=16$ 个 KV 块，每块 $B_k=128$ 个连续 Token；主支路只在这 2048 个 Token 上做精确注意力（PDF p. 6、p. 12）。

论文用一个约 109B 总参、每 Token 激活约 6B 的原生多模态 MoE 验证：同样 3T Token 预算下，MSA 与全注意力 GQA 在下游评测上大体持平；1M 上下文时每 Token 注意力计算降 28.4 倍，配套内核在 H800 上把 prefill 和 decode 分别提速 14.2 倍和 7.6 倍（PDF p. 1、p. 12）。

两件边界先记住。第一，109B 是论文的实验模型，不是后来公开的 MiniMax-M3；M3 只在摘要里作为「用上 MSA 的生产模型」出现（PDF p. 1）。第二，1M 只出现在效率图里，下游长上下文评测停在 128K（PDF p. 11–12）。

## 全景：一层 MSA 怎么走

![MSA 一层里，索引支路从被 stopgrad 的隐状态出发，为每个 GQA 组挑出 16 个块交给主支路做块稀疏注意力；训练时 KL 只更新两张索引投影。](/reports/MiniMax-Sparse-Attention/figure1-msa.svg)

左边的紫色一列只做一件事：给历史上的每个 128 Token 块打分，每组留 16 块。右边的绿色一列就是普通的 GQA 注意力，只是 K、V 只从选中的块里取。黄色的 KL 只在训练时存在，它让索引器的分数去追主支路的关注分布；红色虚线保证这份辅助信号改不到骨干。

论文实验的关键配置（PDF p. 6、p. 8–9、p. 12）：

| 项目 | 取值 |
|---|---|
| 块大小 $B_k$ / 每组选中块数 $k$ | 128 / 16 |
| 每个 Query、每个 GQA 组读的 KV | $kB_k=2048$ 个 Token |
| 注意力头 | 64 个 Query 头，4 个 KV 头（$G=16$），头维 128，RoPE 维 64 |
| 骨干 | 41 层 MoE：前 3 层稠密、后 38 层 MoE；总参约 109B，激活约 6B |
| MoE | 每层 128 个路由专家 + 1 个共享专家，top-4 |
| 训练预算 | 3T Token，索引器 warmup 40B Token |

## 核心设计一：选择单位对齐 GQA 组，粒度是连续块

### 旧问题：逐头、逐 Token 地挑，GPU 吃不下

最细的稀疏是每个 Query 头各自挑单个 Token。论文第一句就否定了它：这种细粒度计算很难映射成 GPU 上的矩阵运算（PDF p. 3）。

放到 GQA 上，问题更具体。一个 GQA 组里 16 个 Query 头共用一套 KV。如果 16 个头各挑各的，要从显存搬进来的就是 16 份选择的并集。计算按每个头自己的 $k$ 算，搬运按并集算，GQA 省下的那份共享被吃回去。这一步是我们的解释，论文只写了「为了效率，建在 GQA 上的稀疏注意力可以在组内共享索引」（PDF p. 3）。

### 新设计：组内共享，组间独立，按块挑

![同样精读 2048 个 Token，DSA 在整段历史里逐 Token 挑散点、所有头共用一份；MSA 每个 GQA 组各挑 16 个 128 Token 的连续块，只有当前所在块是强制的。](/reports/MiniMax-Sparse-Attention/figure-selection-granularity.svg)

两条约束写在式 (3)、(4)（PDF p. 3）：

- 同一个 GQA 组 $r$ 里的所有 Query 头，用同一份块索引 $\mathcal{I}_i^{(r)}$；不同组可以选不同的块。
- 历史按 $B_k$ 个连续 Token 切块，第 $b$ 块覆盖第 $(b-1)B_k+1$ 到第 $\min(bB_k,N)$ 个位置。

论文把自己和最近的邻居划界时，原话就是这两条合起来：按 GQA 组共享 Top-k，加上块级选择；前者给出多组、块粒度的检索，后者让 KV 读取保持连续（PDF p. 13）。按论文第 6 节的描述，DSA 挂在 MLA 的 MQA 模式上、逐 Token 选、所有 Query 头共用一份 Top-k；MoBA 也在 GQA 上，但用很大的块、按块内 Key 平均打分；NSA 是压缩、选块、滑窗三条并行分支（PDF p. 13）。

### 收益与代价

收益有三条。选择单位和 KV 共享单位对齐，搬运量按组算；连续块能整块读进片上内存，喂给 Tensor Core；论文还说，块选择配小 $k$，能在更多种 GPU 上高效执行，并放宽了以往设计对头维度的限制（PDF p. 2）。

附录 Figure 5 给了一个旁证：第 1 层和第 18 层的 4 个 GQA 组，都把高概率放在局部对角线和最左侧的 sink 列上，但剩下的长程条纹各不相同。论文据此说索引器学到的是组特异的模式，没有塌成一份全局选择（PDF p. 22）。

代价也清楚。组内 16 个头被强制看同一批块，论文没有做「组内逐头独立选」的精度对照。块边界可能把一段关键内容切开；附录用 32 / 64 / 128 三种块大小做过对照，下文再看。整套设计还以骨干是 GQA 为前提，论文没有在 MHA 或 MLA 上做实验；它的判断是当前多数开源前沿模型都用 GQA，所以改动应该很小（PDF p. 14）。

### 可迁移启发

一份资源已经被多个消费者共享时，针对它的动态决策要落在同一个共享单位上。消费者各做各的决定，成本就按并集结算。稀疏率、$k$、块大小都可以后调，共享单位错位是结构性的浪费。

## 核心设计二：索引器是一个纯选择器

### 旧问题：打分器太重就白省，太轻就挑不准

要挑块，先要给块打分。打分器贵了，主支路省下的又还回去；完全不带参数，召回又差。MSA 给索引支路的预算是：相对标准 GQA 只加两张投影矩阵（PDF p. 4）。

### 新设计：每组一个 index query，全体共用一个 index key

输入隐状态记作 $X$。索引支路先投影（PDF p. 4，式 5）：

$$
Q^{\mathrm{idx}}=X\,W_q^{\mathrm{idx}}\in\mathbb{R}^{N\times H_{kv}\times d_{\mathrm{idx}}},\qquad
K^{\mathrm{idx}}=X\,W_k^{\mathrm{idx}}\in\mathbb{R}^{N\times 1\times d_{\mathrm{idx}}}
$$

$Q^{\mathrm{idx}}$ 的头数等于 KV 头数 $H_{kv}$，也就是每个 GQA 组一个；$K^{\mathrm{idx}}$ 只有 1 个头，所有组共用。$d_{\mathrm{idx}}$ 是索引维度。原图里这两条投影后面还有一个 Norm & RoPE，正文公式没有写（PDF p. 1）。

打分分两步。先算 Token 级分数，再在每个块内取最大值当块分（PDF p. 4，式 6）：

$$
S_{i,j}^{\mathrm{idx},(r)}=\frac{Q_i^{\mathrm{idx},(r)}\cdot K_j^{\mathrm{idx}}}{\sqrt{d_{\mathrm{idx}}}},\qquad
M_{i,b}^{\mathrm{idx},(r)}=\max_{j\in\mathcal{B}_b,\ j\le i} S_{i,j}^{\mathrm{idx},(r)}
$$

$i$ 是当前 Query 位置，$j$ 是历史位置，$r$ 是组号，$j\le i$ 是因果约束；没有可见 Token 的块记为 $-\infty$。然后每组取块分最高的 $k$ 块（式 7），并且**永远纳入包含位置 $i$ 的那一块**。这份块索引由组内全部 $G$ 个 Query 头共用（PDF p. 4）。

主支路就是限定了范围的标准注意力（PDF p. 4，式 8）。组 $r$ 里的每个头 $h$ 用自己的 Query，去读本组 KV 头在选中块里因果可见的那些 Token。选中块里最多 $kB_k$ 个 Token，所以每个 Query 的主注意力开销从 $O(N)$ 变成 $O(kB_k)$，不再随序列变长（PDF p. 4）。

### 两个值得停一下的细节

**块分取最大值，不取平均。** 一块里只要有一个 Token 很相关，整块就值得捞上来；取平均会把那一个稀释掉。这是我们的解释，论文只给了公式，没有做最大值与平均值的对照。

**打分和选择都不需要 softmax。** softmax 保序，分数高的概率也高，所以选 Top-k 时直接对原始分数排序，跳过求最大、取指数、求和三步（PDF p. 6）。最终配方里索引支路也不再输出注意力，推理时只需要 $Q^{\mathrm{idx}}(K^{\mathrm{idx}})^{\top}$ 的块内最大值，整条路径没有 Value 聚合、也没有指数运算（PDF p. 30）。

### 与 DSA 同为 2048，不是同一种 2048

DeepSeek-V3.2 一篇里，DSA 每个 Query 也精读 2048 个位置。两者的预算数字一样，含义不同：DSA 是 2048 个散落的 Token，所有头共用一份；MSA 是每组 16 个 128 Token 的连续块，4 个组各选一份。上一节的图就是这两种 2048 的对照。

### 代价与边界

正文没有给实验用的 $d_{\mathrm{idx}}$。强制纳入的自身块占掉 16 个名额中的 1 个，索引器真正能自由选的是 15 块。Top-k 不可导，两张索引投影拿不到语言模型损失的梯度，这是下一节要解决的事（PDF p. 5）。

## 核心设计三：让不可导的 Top-k 学得会

Top-k 是离散决策。选中哪几块只是一个路由结果，语言模型损失的梯度传不到 $W_q^{\mathrm{idx}}$、$W_k^{\mathrm{idx}}$（PDF p. 5）。MSA 的最终做法是四件套：KL 对齐、梯度切断、索引器 warmup、强制自身块（PDF p. 5）。它们不是一开始就这么定的，附录记录了这条路怎么走过来。

### 先看另一条路为什么没留下

论文先试过两种给索引器送梯度的办法（PDF p. 23–24）：

1. **让索引支路也产出一份注意力输出**：给它加一套 Value，算出 $O^{\mathrm{idx}}$，经独立的输出投影加到层输出上。索引器由此通过下一 Token 预测被训练。
2. **KL 对齐**：直接让索引分数去匹配主支路的分布。

三组配置都从第一步就稀疏训练：只靠 LM（带 $O^{\mathrm{idx}}$）、只靠 KL（去掉 $O^{\mathrm{idx}}$）、两者都要。

![Figure 7 显示只靠 LM 损失时长上下文检索掉约 9 分，只靠 KL 时知识考试掉约 5 分，两者都要时两条轴最均衡。](/reports/MiniMax-Sparse-Attention/figure7-gradient-sources.svg)

论文的读法（PDF p. 24）：只靠 LM 时短上下文能力还在，但长上下文检索很差，因为没有任何目标直接压在 Top-k 选择上；只靠 KL 时检索变好，短上下文变差，因为去掉 $O^{\mathrm{idx}}$ 等于少了一份给语言模型用的注意力容量；两者都要最均衡，于是成为附录 B 后续消融的配置。

后来这份 $O^{\mathrm{idx}}$ 又被删掉了。等 warmup 出现之后，附录 C.3 在继续预训练设定里对比「带 Value 头」和「不带」，结论是 Value 头不再关键（PDF p. 29–30）。它在早期配方里的作用是提供额外的早期训练信号，而不是收敛后必不可少的容量。

### KL：只在选中的 Token 上，追组内平均的主注意力

最终的 KL 这样定义（PDF p. 5，式 9–10）。先把选中块展开成因果可见的 Token 集合 $\mathcal{I}_{i,\mathrm{tok}}^{(r)}$，在这个集合上定义两个分布：

- **学生**：索引器分数 $S^{\mathrm{idx}}$ 在这批 Token 上做 softmax，记作 $P^{\mathrm{idx}}$；
- **教师**：组内 $G$ 个 Query 头各自做 softmax，再在概率层面取平均，记作 $P$。

$$
\mathcal{L}_{\mathrm{KL}}=\frac{1}{N\,H_{kv}}\sum_{i=1}^{N}\sum_{r=1}^{H_{kv}}D_{\mathrm{KL}}\Bigl(\mathrm{stopgrad}\bigl(P_{i,\cdot}^{(r)}\bigr)\,\Big\|\,P_{i,\cdot}^{\mathrm{idx},(r)}\Bigr)
$$

对所有位置、所有组取平均。总损失是 $\mathcal{L}=\mathcal{L}_{\mathrm{LM}}+\lambda\sum_{\text{layers}}\mathcal{L}_{\mathrm{KL}}$（PDF p. 6，Algorithm 1）。$\lambda$ 的取值论文没有给。

两件事要盯住。教师是组内 16 个头的平均，因为这 16 个头看的是同一批块，索引器要服务的正是这个组。KL 只在选中的支持集上算，它教的是「在已经挑中的位置里，谁更重要」，没被选中的块得不到直接的负样本信号。

### 梯度切断：别让辅助损失去改骨干

教师被 stopgrad 还不够。默认的反向图里，KL 的梯度会穿过索引投影回到 $X$，再顺着残差流进整个骨干。论文说，这会把 KL 从「索引器的局部监督」变成「骨干的额外目标」（PDF p. 25）。

它观察到两种失败（PDF p. 25）：

- KL 系数较大时，偶发的 KL 梯度尖峰打进骨干，几百步内梯度范数暴涨、LM 损失发散（Figure 8）。从图上读，未切断的那条 LM 损失停在 8.5–9 附近，梯度范数在第 300–500 步冒出几十万量级的尖峰；切断的那条降到约 2.1 并平稳。
- 系数小到能稳住训练时，短上下文基准仍会慢慢回退（Figure 9）。论文归因于一种自蒸馏：骨干可以通过把主支路的注意力分布变简单来降低 KL，而不是把索引器教好。

修法是式 (11)：对索引支路的输入也做 stopgrad（PDF p. 5）。

$$
Q^{\mathrm{idx}}=\mathrm{stopgrad}(X)\,W_q^{\mathrm{idx}},\qquad
K^{\mathrm{idx}}=\mathrm{stopgrad}(X)\,W_k^{\mathrm{idx}}
$$

两处 stopgrad 合起来，KL 只更新两张索引投影。Figure 9 在 200–400B Token 区间比了 ARC-Challenge、BBH、MMLU、HellaSwag 四项，切断的一侧全程更高；读图，400B 处 MMLU 约 37 对 33（PDF p. 25）。

**我们如何解释它。** 不切断时，降低 KL 有两条路：把学生教好，或者把老师变简单。骨干控制着老师，而把老师变简单往往更容易。切断之后，第二条路被堵死。

### Warmup：先让主注意力自己变尖，再把方向盘交出去

论文观察到，训练最早期主支路的注意力熵会从平滑迅速变尖，前几百步急降，然后部分回升并稳定（PDF p. 26，Figure 10）。如果从第 0 步就做 Top-k，索引器要追一个剧烈移动的目标，自己的选择又几乎随机；早期选错会把主支路引到无信息的 Token 上，骨干和 KL 监督一起变差（PDF p. 26）。

做法分两段（PDF p. 5、p. 26）：

1. 前一段两条支路都跑全注意力，用对整段历史的 KL 训练新加的索引投影；
2. 过了 $T_{\mathrm{warm}}$ 之后切到稀疏，KL 改为只在选中的 Top-k 位置上算。

109B 实验里这一段是 40B Token（PDF p. 9）。Figure 11 在 10B 预实验上比有无 warmup：200–400B Token 区间里，warmup 的曲线在 ARC-Challenge、BBH、MMLU、HumanEval、RULER 上多数点更高；HumanEval 与 RULER 两条曲线本身抖动很大，有几个点交叉（PDF p. 26）。同一套日程也用在「把已训好的全注意力 checkpoint 改成稀疏」上（PDF p. 5）。

### 强制自身块：只留一条硬规则

每个 Query 所在的那一块，训练和推理时都强制入选，占掉一个名额，防止退化的选择漏掉当前邻域（PDF p. 5）。附录把它叫做「特殊的、可能还没写完的自身块」（PDF p. 29）。

早期配方其实强制了更多：序列第一块（sink）和 Query 附近的一段固定局部窗口。附录 C.2 把这两条删掉后，模型自己仍会在有用时关注前缀、频繁选中邻近 Token（PDF p. 29）。Table 5 的对照（PDF p. 30）：

| 基准 | 不强制 | 强制 sink + 局部窗口 |
|---|---:|---:|
| MMLU | 60.5 | 60.5 |
| MMLU-Pro | 32.5 | 33.4 |
| BBH | 58.2 | 58.2 |
| GSM8K | 66.0 | 66.9 |
| EvalPlus | 54.0 | 53.6 |
| ChartQA | 73.5 | 73.7 |
| AgentCompany PPL ↓ | 1.268 | 1.266 |

论文的结论是推理、代码、PPL 几乎不变，长上下文检索「也大体相当」，最终配方只强制自身块（PDF p. 29）。表上 RULER-32K 其实差了 4.3 分，这是全表最大的一格，论文没有单独解释。只读结论会漏掉这一格。

### 这一套训练设计的收益、代价与启发

**收益**：离散的 Top-k 变得可训，索引器不必再往层输出里掺一份注意力；从零训练和从全注意力 checkpoint 转换走同一套日程。

**代价**：多一个没公开取值的 $\lambda$；warmup 期间主支路仍是全注意力，稀疏带来的训练加速要从 40B Token 之后才开始；KL 只在选中集合上算，漏选的块没有直接惩罚。

**可迁移启发**：离散路由最稳的监督，是去模仿一条已被主损失训练过、且被切断梯度的教师分布。模仿与切断要一起做，只模仿不切断，老师会为了好被模仿而变简单。附加输出这类脚手架可以帮训练起步，warmup 解决了初始化之后就该拆掉。

## 复杂度账：平方项还在，只是换到了更便宜的算子上

同样的头配置和长度下，两者的因果注意力 FLOPs 是（PDF p. 6，式 12）：

$$
F_{\mathrm{GQA}}(N)=2H_q d_h N^2,\qquad
F_{\mathrm{MSA}}(N)=\underbrace{H_{kv}\,d_{\mathrm{idx}}\,N^2}_{\text{Index Branch}}+\underbrace{4H_q d_h N\,kB_k}_{\text{Main Branch}}
$$

GQA 的主路径随 $N^2$ 涨。MSA 留下一个很轻的平方项（索引打分），主支路变成与 $N$ 无关的固定预算 $kB_k$。当 $kB_k\ll N$ 且 $H_{kv}d_{\mathrm{idx}}\ll H_q d_h$ 时，差距随 $N$ 拉大（PDF p. 6）。

**本文验算。** 正文没有写 $d_{\mathrm{idx}}$。若取 $d_{\mathrm{idx}}=128$，1M 取 $2^{20}$，代入 $H_q=64$、$H_{kv}=4$、$d_h=128$、$kB_k=2048$，把上式除以 $N$ 得到每 Token 的量：

- GQA：$2\times 64\times 128\times 2^{20}\approx 17.2\,\mathrm{G}$；
- MSA 索引：$4\times 128\times 2^{20}\approx 0.537\,\mathrm{G}$；主支路：$4\times 64\times 128\times 2048\approx 0.067\,\mathrm{G}$；合计约 $0.604\,\mathrm{G}$；
- 比值约 28.4，与论文在 Figure 4 标注的 28.4 倍一致（PDF p. 12）。

所以 $d_{\mathrm{idx}}=128$ 很可能就是实验取值，但这是反推，论文没写。这笔账还暴露一件论文没强调的事：1M 处 MSA 剩下的注意力 FLOPs 里，将近九成是索引支路那个「便宜的平方项」。再往更长走，优化索引打分会比继续压 $k$ 更要紧。

## 核心设计四：把少算变成真快

论文第 4 节写的是稀疏 prefill 的内核（PDF p. 6）。它先承认一件事：理论上少算，不等于墙钟变快。稀疏路径要付索引构建、Top-k、反向索引、Query 收集和负载均衡的钱，访存也不如稠密注意力规整（PDF p. 12）。

### 为小 $k$ 专门写的 Top-k

$B_k$ 和 $k$ 是和 Top-k 内核一起定的：大 $B_k$ 提高主注意力的算术强度，而在这个 $B_k$ 下取小 $k$，让每行候选块数 $B$ 和 $k$ 都落在通用 Top-k 内核不划算的区间（通用内核靠大 $B$ 摊薄多轮分桶，或按 $O(B\log^2 B)$ 排序）（PDF p. 6）。实现上，一个 warp 的 32 条 lane 各扫输入行的 1/32，在共享内存里各维护一个 $k$ 元最小堆，堆顶缓存在寄存器里，最后做 $k$ 轮 shuffle 归并（PDF p. 6）。

Table 1 是 H800、fp32 输入、输出不排序、50 次预热后的中位延迟，单位微秒（PDF p. 7）：

| 序列长度 | 块数 $B$ | $k$ | torch.topk | TileLang | 论文实现 | 对 torch | 对 TileLang |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 128K | 1024 | 16 | 3970 | 2864 | 779 | 5.1× | 3.7× |
| 128K | 2048 | 32 | 5378 | 3630 | 1991 | 2.7× | 1.8× |
| 512K | 4096 | 16 | 33810 | 17779 | 7880 | 4.3× | 2.3× |
| 512K | 8192 | 32 | 57659 | 26100 | 21326 | 2.7× | 1.2× |

$k=16$ 的两行是部署配置（$B_k=128$）；$k=32$ 的两行是参照，对应 $B_k=64$（PDF p. 7 表注）。三种实现选出的索引完全相同。增益在部署点最大，$k=32$ 时明显收窄。这是选块内核的微基准，不是端到端注意力。

### KV-outer：外循环扫 KV 块

![Q-outer 下每个 Query 各自去搬它选的块，热门块被反复读，算术强度约为 G = 16；KV-outer 下每块 KV 只读一次，收集选中它的 Query 拼成 128 行矩阵乘，算术强度约为 ⅔ · B_k ≈ 85。](/reports/MiniMax-Sparse-Attention/figure-kv-outer.svg)

两种循环顺序的 FLOPs 相同，都是 $4H_qNd_hkB_k$。差别在 IO（PDF p. 7，式 13–16）：

- **Q-outer**：每个 Query 读自己选的 $k$ 块 KV，KV 被按选择次数重复读，$\mathrm{FLOPs}/\mathrm{IO}\approx G$；
- **KV-outer**：每块 KV 读一次，把选中它的 Query 聚过来一起算，代价是多一份中间输出缓冲，$\mathrm{FLOPs}/\mathrm{IO}\approx\tfrac{2}{3}B_k$。

实验里 $G=16$、$B_k=128$，后者约 85，远大于 16，于是选 KV-outer（PDF p. 7）。**本文验算**：忽略 KV 读取项后，KV-outer 的比值是 $4kB_k/(6k+2)$，代入 $k=16$ 得约 83.6，与近似值 85 接近。

这个顺序引出三个工程问题，论文各给了一个零件（PDF p. 7–8）：

1. **热点块**：序列开头的 sink 块几乎被所有 Query 选中，一块一个 CTA 会被它拖死。调度内核把每个 KV 块沿 Query 维切成至多约 $2kB_k$ 个 Query 的小段，分给多个 CTA，共用同一份 K/V 加载。
2. **不能用原子加**：一个 Query 的 $k$ 份部分结果现在出自 $k$ 个 CTA。调度器预先给每个（Query，小段）分配缓冲 $O_{\mathrm{buf}}$ 里的槽位 $s\in[0,k)$，和 Query 下标打包成 32 位句柄，注意力内核直接写到预分配的偏移。
3. **不能在一个内核里做完 softmax 归一化**：前向拆成两个内核。注意力内核写出局部归一化的部分输出和各自的 logsumexp；combine 内核按标准 split-K 公式合并。两者之间用 Programmatic Dependent Launch 遮住内核启动延迟。

最后一步是 **Query 拼接**。KV-outer 下一个 KV 块往往只对应几个到几十个 Query 位置。一次只算一个位置，score 矩阵乘的 $M$ 维只有 $G=16$，喂不满 Tensor Core。因为这些位置共享同一份 KV 操作数，内核把 $\lceil 128/G\rceil=8$ 个位置连同各自 16 个头拼成一个 $128\times 128$ 的矩阵乘（PDF p. 8）。Q-outer 做不到，因为不同 Query 选的 KV 不同，没法沿序列维拼接。

**我们如何解释它。** KV-outer 不只是少读 KV，它还让「把矩阵乘喂饱」成了合法操作。$B_k=128$ 在这里一身两用：块越大，算术强度越高，拼接后的矩阵也越规整。

### 训练侧的两处优化

KL 只影响反向梯度，所以前向不必单跑一个 KL 内核。主前向直接把主支路和索引支路的 LSE 写进显存；索引支路保存每块的 LSE，再在选中的 Top-k 块上归约。反向内核直接读这些标量，省掉一次重复前向（PDF p. 8）。

反向的负载差异可以差几个数量级。内核做成常驻网格，CTA 通过全局原子计数器抢活，每个块按收集到的 Query 数切成子块，并设最小粒度以免切得太碎（PDF p. 8）。

### 代价与边界

第 4 节几乎全是 prefill。decode 的 7.6 倍是测出来的墙钟，但正文没有讲 decode 内核的循环顺序与 KV Cache 布局。论文公开的仓库写的是推理内核（PDF p. 1），训练内核没有开源。

附录 B 用一个 10B 预实验模型做配方消融：16 层，GQA 32 个 Query 头、4 个 KV 头，64 个专家 top-4，总参 10.53B、激活 1.47B；优化器、学习率日程与分词器和全规模一致，数据是全规模语料的子集（PDF p. 23）。附录 C 是更靠近最终设计的结构消融，训练步数更少、评测子集更小（PDF p. 28）。论文说 B、C 两部分就是正文配方的经验基础（PDF p. 11–12）。

前面已经讲过的：梯度来源（B.2）、梯度切断（B.3）、warmup（B.4）、强制 sink 与局部窗口（C.2）。剩下四项：

**可学习的 attention sink 没有留下（B.5）。** Figure 6 显示，不强制选第一块，每个头仍把可观的注意力给第一个 Token：第 4 层和第 24 层各 8 个头，图上标注的均值在 0.29–0.69 之间（PDF p. 23）。于是论文试了 GPT-OSS 式的可学习 sink：每个头加一个 sink logit，在 softmax 里和真实 Key 竞争。Figure 12 的四个头里，有的头把 sink 质量几乎全交给新参数（Head 9：sink 0.76，第一个 Token 0.06），有的头新参数为 0、第一个 Token 仍是隐式 sink（Head 5：0.00 对 0.47）（PDF p. 27）。Figure 13 的四项 agent 任务 PPL 也没有稳定变好。额外参数、实现复杂度，加上并不能真正消除第一个 Token 的 sink，这一项被放弃（PDF p. 27–28）。

**同预算下，动态选择胜过固定滑窗（B.6）。** 对照组删掉索引支路，改为固定模式：每个 Query 看第一个 KV 块，加上一段以自身为终点、Token 预算相同的局部窗口。两边预算相同，只差「按位置写死」还是「按内容选」（PDF p. 27–28）。Figure 14 在 AgentCompany、BrowseComp、Toolathlon、TerminalBench、SWE、HLE 六项上，滑窗的 PPL 在整个训练轨迹上都更高（PDF p. 28）。这是 10B 模型的 PPL 曲线，不是 109B，也不是下游准确率。

**块大小 32 / 64 / 128 差别不大（C.1）。** 保持选中 Token 总数不变，只改 $B_k$（PDF p. 28–29，Table 4）：

| 基准 | 块 32 | 块 64 | 块 128 |
|---|---:|---:|---:|
| TAU2 PPL ↓ | 1.176 | 1.176 | 1.176 |
| AgentCompany PPL ↓ | 1.266 | 1.276 | 1.266 |
| HLE PPL ↓ | 1.299 | 1.299 | 1.300 |
| SWE PPL ↓ | 1.233 | 1.233 | 1.233 |
| RULER-8K | 72.5 | 72.8 | 73.8 |
| RULER-32K | 66.1 | 65.3 | 64.6 |

PPL 几乎不动。RULER-32K 随块变粗略降 1.5 分，RULER-8K 反而升 1.3 分。论文的结论是可以用更大的块换内核效率、质量损失有限（PDF p. 29）。「换效率」在这张表里是推论，没有配套测速；更粗的 256、512 也没有测。

**索引支路的 Value 头可以删（C.3）。** Table 6 的方向是混的（PDF p. 30）：不带 Value 头在 MMLU 上 67.3 对 66.4、BBH 65.9 对 65.3 略好；带 Value 头在 GSM8K 77.6 对 76.4、HumanEval 60.4 对 59.1、BigCodeBench 46.0 对 44.0 略好；RULER-8K 84.1 对 83.0、RULER-32K 79.7 对 80.4 互有胜负（左边是带 Value 头）。两者谁也没有稳定压过谁，于是按效率删掉（PDF p. 29–30）。

把 B 和 C 串起来看：最终的 MSA 不是一开始就这么瘦。先用索引输出和强制窗口把训练稳住，再靠梯度切断、warmup 和消融把这些零件一个个拆掉，最后只剩两张投影、一个 KL 和一条「自身块必选」的硬规则。

## 放回稀疏注意力的谱系里

下表只用 MSA 原文第 6 节对各家的描述（PDF p. 13），细节以站内 NSA、MoBA、DeepSeek-V3.2 各篇为准。

| | MSA | NSA | MoBA | DSA |
|---|---|---|---|---|
| 骨干 | GQA | MQA / MHA | GQA | MLA 的 MQA 模式 |
| 选择粒度 | 128 Token 的块 | 细粒度块（另有压缩与滑窗分支） | 很大的块 | 单个 Token |
| 选择在谁之间共享 | 组内共享，组间独立 | — | — | 所有 Query 头共用一份 |
| 索引器怎么学 | KL 对齐 + 两处 stopgrad | — | 只靠语言模型梯度，块分用块内 Key 的平均 | 多头 ReLU 闪电索引器 |

表里「—」表示 MSA 原文没有描述这一格。NSA 的「MQA / MHA」照录 MSA 原文；NSA 原文自己的算子面向 GQA 与 MQA，实验骨干是 GQA（见 NSA 一篇）。第 6 节还提到 InfLLM-V2：用无参数的块选择加局部滑窗，统一稠密与稀疏，做到零样本切换（PDF p. 13）。推理期才稀疏的一类（H2O、SnapKV、Quest、MInference、FlexPrefill、InfLLM），论文的批评是它们继承了全注意力的训练成本，并且至少有一个推理阶段仍接近全注意力速度（PDF p. 13）。

四家都在做「先挑再读」。分歧在两处：愿意为硬件让渡多少选择自由度，以及选择器靠什么信号学习。MSA 的押注是，挂在 GQA 上、按块选、用 KL 教一个纯选择器。

## 论文之后：MiniMax-M3

以下是外部资料，不是这份 PDF 的内容。

MiniMax 在 2026-06-01 发布 M3 的官方博客里写明 M3 当日正式发布、API 可用，并说 M3 使用团队提出的 MSA（[MiniMax M3 官方博客](https://www.minimax.io/blog/minimax-m3)）。博客给的是产品口径：1M 上下文时每 Token 计算量约为上一代模型的 1/20，prefill 快 9 倍以上，decode 快 15 倍以上，算子层面比开源的 Flash-Sparse-Attention 和 flash-moba 快 4 倍以上。

这几个数字的对照物是 MiniMax 的上一代模型，模型规模也不同，不能和论文里 109B MSA 对 GQA 的 28.4、14.2、7.6 倍放在一起比。连方向都不一样：论文里 prefill 倍数大于 decode，博客里反过来。两边的测法都没有公开到能解释这个差异的程度。

## 限制、边界，以及不要补进去的实现

论文自己划掉的，或读完必须留下的判断：

- **实验模型是 109B，不是 M3。** 109B 的权重没有发布。
- **1M 只出现在效率图里。** 下游长上下文评测停在 128K，而且只有 MSA-CPT 做了扩展训练（PDF p. 11–12）。
- **展望里自己承认还有长上下文检索差距**，给了三条候选补法：更长的稀疏训练、推理时加大选择预算、更丰富的索引打分函数；强化学习后训练和 agent 部署是下一步（PDF p. 14）。
- **内核叙述只写了 prefill。** decode 的 7.6 倍有测量，没有结构说明。
- **没有公开**：$d_{\mathrm{idx}}$、$\lambda$、$T_{\mathrm{warm}}$ 在 10B 上的步数、109B 的优化器与数据配比与硬件、训练内核。
- **没有做的消融**：组内逐头独立选择、块分取平均、同 $B_k$ 下改 $k$、比 32K 更短的效率。
- **单次运行**：Table 2 与附录各表都没有给方差或多次运行。

## 可迁移启发

1. **先对齐共享单位与选择单位，再谈稀疏率。** 选择粒度与 KV 共享粒度错位，搬运就按并集结算。缓存、批处理、多租户资源都是同一个道理。
2. **路由器能寄生在教师分布上，就别让它再出一份输出。** 最终的索引器不贡献层输出，只靠 KL 追被 stopgrad 的主支路分布。附加输出是起步的脚手架，不是成品结构。
3. **辅助损失要先画清梯度能走到哪。** A 去模仿 B，A 是新模块、B 是已经能干活的主干时，默认 stopgrad(B)，也 stopgrad(A 的输入)。否则主干会为了好模仿而变简单。
4. **目标分布还在剧烈变化时，不要把离散决策的方向盘交出去。** 注意力熵的早期塌缩就是 warmup 的理由。从零训练和从稠密 checkpoint 转换可以共用这套日程。
5. **循环顺序可能比再削一刀 FLOPs 值钱。** KV-outer 不改 FLOPs，只把算术强度从约 16 抬到约 85，还顺手让 Query 拼接成立。宣称「复杂度降到线性」之前，先问外循环扫的是反复复用的那一侧，还是每次都在变的那一侧。
6. **写死的规则更适合当护栏，不适合当能力来源。** 强制 sink 和局部窗口在早期有用，模型学会之后就可以拆；真正留下的硬规则只有「自身块不能丢」。但拆护栏时要看完整张表，RULER-32K 那 4.3 分就是会被结论句盖住的一格。
7. **读稀疏注意力的加速比，先问是 FLOPs 还是墙钟、对照物是谁。** 28.4 倍是理论 FLOPs，14.2 倍和 7.6 倍是 H800 墙钟，产品博客的 9 倍和 15 倍是对上一代模型。

## 关键词回看

- **MSA**：挂在 GQA 上的两段式块稀疏注意力，索引支路挑块，主支路精读。
- **索引支路**：每组一个 index query 头、全体共用一个 index key 头；Token 打分后按块取最大值，每组取 Top-16。
- **主支路**：标准 softmax 注意力，只读选中块里因果可见的 Token，每组每个 Query 至多 2048 个。
- **组内共享、组间独立**：16 个 Query 头看同一批块，4 个组各选各的。
- **KL 对齐**：在选中的 Token 上，让索引分布去追组内 16 头平均的主注意力分布，教师 stopgrad。
- **梯度切断**：索引投影的输入也 stopgrad，KL 只能改两张索引投影。
- **Indexer warmup**：先全注意力对齐索引器，再切稀疏；109B 上是 40B Token。
- **自身块**：包含当前 Query、可能还没写完的那一块，最终唯一强制入选的块。
- **exp-free Top-k**：利用 softmax 保序，直接对原始分数取 Top-k。
- **KV-outer**：外循环扫 KV 块、收集选中它的 Query，算术强度约 $\tfrac{2}{3}B_k$。
- **MSA-PT / MSA-CPT**：从零稀疏预训练，以及从 GQA checkpoint 继续预训练的转换路线。
- **块召回 / 分数召回**：主支路想要的块被选中的比例，以及这些块占的注意力质量；CPT 时约 0.72–0.75 与 0.90–0.94（读图）。
