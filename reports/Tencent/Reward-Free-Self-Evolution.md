# Reward-Free：零掉的是推理时的外部奖励，不是训练老师；先画地图再做题

<!-- release-date: 2026-04-20 -->

> 本文依据本地 `papers/Tencent/Reward-Free-Self-Evolution.pdf`，即 **Training LLM Agents for Spontaneous, Reward-Free Self-Evolution via World Knowledge Exploration**，arXiv:2604.18131v1、2026-04-20 提交（封面日期 April 21, 2026），共 24 页。页码均指 PDF 自身的页码。作者来自腾讯与香港科技大学（广州），项目负责人是腾讯的 Yan Wang（PDF p. 1）。文中会区分三件事：**论文明确写了什么**、**我们怎么解释它**、**哪些是外部资料或本文推算**。

## 读前先把几个词说成人话

这篇论文的标题很大，技术动作其实很窄：让网页 agent 进一个没见过的网站时，先自己把网站逛一遍、写一份导览，再拿这份导览去做题。难点只有一个：写导览时还没有题，拿什么告诉模型「这份导览写得好」。

先把会反复出现的词说清楚：

- **Agent（智能体）**：会一步步调用工具、看环境反馈、再决定下一步的模型。本文里就是一个会点击、滚动、跳转网页的浏览器 agent。
- **世界知识（World Knowledge，记作 $K$）**：一份针对**某一个具体环境实例**写的 Markdown 导览。论文举的例子是 ACL 2025 官网、某个游戏世界、某个复杂代码仓（PDF p. 3）。它不是通用常识，也不是可复用的技能包；它是「这个网站有哪些栏目、每页讲什么、网址是什么」。
- **原生进化（Native Evolution）**：进入新环境后、任务出现之前，自己探索并写出 $K$ 的那一段。论文把「会不会自己先画地图」叫做元进化能力（meta-evolution capability）（PDF p. 3–4）。
- **知识增强执行（Knowledge-Enhanced Execution）**：任务出现后，带着 $K$ 去做题（PDF p. 3）。
- **结果奖励（outcome-based reward）**：不看导览写得漂不漂亮，只看它让下游题的命中率涨了多少。这条奖励**只在训练时用**（PDF p. 4–5）。
- **SFT（Supervised Fine-Tuning，监督微调）**：让强教师 Gemini-2.5-Pro 走完整条探索轨迹，学生逐步模仿最好的那条（PDF p. 5）。
- **RFT（Reinforcement-based Rejection Sampling，基于拒绝采样的强化微调）**：学生自己采若干条轨迹，用结果奖励挑最好的，再拿它们微调。论文也把它叫 Rejection Sampling Fine-Tuning（PDF p. 5）。它**不是** GRPO 这类带优势函数的在线策略梯度。
- **入口图 $G(U)$**：把网站先建成链接图、按链接数给每页打分、再按网址前缀聚类，得到的结构化入口。推理时 agent 拿到的是这份聚类文件，不是光秃秃的首页网址（PDF p. 7、p. 14）。

## 一句话先说清

2026 年的「自进化 agent」大多还要人给任务、给奖励、给工作流；把这些拿掉，进化就停了。论文的第一句话就说，当前的自进化研究「很大程度上是一种幻觉」（PDF p. 1）。

它的回答是把 agent 的生命周期拆成两段：**先探索、写 $K$，后做题**。写 $K$ 这一段靠训练学会，训练信号是「这份 $K$ 让固定执行器在一组真题上多答对了多少」。训练完，agent 进新网站就自己写 $K$，推理时不再需要题库、奖励或人工指令。

结果写得很硬（PDF p. 1、p. 7–8）：

- Qwen3-30B-A3B 在 WebWalker 子集上从 22.04 到 40.91，Seed-OSS-36B 从 16.26 到 37.50，摘要约成「20% 提升」；
- 把 Seed 写的 $K$ 借给没训过的 Qwen3-14B，它在两个域上超过了不带 $K$ 的 Gemini-2.5-Flash。

但标题里的 Reward-Free 要读准。**零掉的是推理时的外部奖励**；训练时有 600 道带标准答案的题、有教师模型、有很贵的结果奖励，推理时还有聚类入口图和一份生成说明。下面会把这条边界单独摊开。

## 主要矛盾：自进化还在等人发课本

![Figure 1 把自进化分成三类：经验驱动靠人给任务和打分，对抗式靠人搭出题解题流水线，本文的元学习驱动让 agent 先探索环境再压缩成世界知识，底部的人类依赖条从红到绿递减。](/reports/Reward-Free-Self-Evolution/fig1-paradigms.png)

*图：引自原文 Figure 1（PDF p. 2）。底部的「Human Dependency」色条是作者的示意，不是量化数据。*

论文把已有做法收成两类，再把自己放在第三类（PDF p. 2–3）。图上读不出的，是每一类到底还要人提供什么：

| 范式 | 人还要提供什么 | 论文的批评 |
|---|---|---|
| 经验驱动进化 | 针对目标环境的任务和奖励函数，外加更新机制：改系统提示、扩外部记忆、扩工具与技能库，或直接微调 | agent 在学人编的「课本」，只是被动适应 |
| 对抗式进化 | challenger 出题、solver 解题的合作流水线 | 人从出题挪到了搭工作流；agent 仍困在合成的「习题册」里 |
| 元学习驱动进化（本文） | 训练阶段的题库、教师和结果奖励；推理阶段尽量少 | 声称推理时不要任务、不要奖励、不要工作流 |

对抗式那一类引用了 [30–34]，其中包括 R-Zero 与 Dr. Zero（PDF p. 3，文献见 p. 12）。本站两篇都已收录：R-Zero 是出题与解题两个角色共进化，Dr. Zero 把同样的思路搬到搜索 agent 上。本篇对它们的批评只有一句：任务和奖励交给了 agent 自己产，但对抗游戏本身仍是人搭好的。

另一条对照是 Test-Time Training：推理时做梯度更新，和 vLLM、DeepSpeed-Inference 这类高吞吐推理框架不兼容；本篇把观察压成 $K$ 放进 prompt，推理时不改权重（PDF p. 3）。

于是矛盾变成：

> 想让 agent 在推理时不依赖任何人给的任务和奖励，就得让它在训练时学会「先探索、再总结」。可探索阶段本身没有任务，也就没有逐步的标准答案。**写 $K$ 的训练信号从哪来**，是这篇论文要解决的全部问题（PDF p. 4）。

人进新城市、学新软件会自发先认路，这是论文的动机类比（PDF p. 1），不是实验能证明的事。实验能检验的只有那个工程问题。

## 先看全景：两段生命周期，两阶段训练

论文把标准 agent 写成反应式策略：$a\sim\pi(a\mid o,\mathrm{Task})$，每个动作都条件于当前观察 $o$ 和预先给定的任务（PDF p. 3）。新框架把它拆成两段（PDF p. 3）：

1. **原生进化**：进入环境 $E$，自己探索并总结，$K\leftarrow\pi_{\mathrm{evolve}}(K\mid E)$。论文写明这一段「在推理时」不要任务也不要奖励。
2. **知识增强执行**：任务出现后，$a_t\sim\pi_{\mathrm{task}}(a_t\mid o_t,K,\mathrm{Task})$。

![Figure 2 分三栏：左栏是数据生成，agent 在 Web、Code、Game 环境里规划、探索、总结、精修，写出世界知识；中栏上半是教师模型生成多条轨迹、奖励计算器选出最好一条做 SFT，下半是学生自己采轨迹、再按奖励挑最好的做拒绝采样，迭代两轮得到最终模型；右栏是推理时先自己进化出世界知识，再带着它执行环境任务。](/reports/Reward-Free-Self-Evolution/fig2-overview.png)

*图：引自原文 Figure 2（PDF p. 4）。图中 RFT 起点标的是 $\pi_0$，正文 3.3 节写的是 SFT 之后的 $\pi_{\theta_1}$（PDF p. 5），以正文为准。*

读图要注意两点。

第一，左栏画了 Web、Code、Game 三种环境，**实验只做了网页**。论文说原则与领域无关，落在网页是因为网页够乱、够动态，是个好试验台（PDF p. 4）。全文没有代码仓或游戏世界的表。

第二，$K$ 被实现成 Markdown 文档，好让现有 agent 不改动作空间就能读。论文拿 Anthropic 的 skills 仓库作对照：skill 提供任务特定的功能，比如网页应用测试；$K$ 记的是某个环境实例的内在逻辑（PDF p. 3 及脚注）。

**我们如何解释它。** 这是一次接口选择，不是一次世界模型突破。$K$ 没有动力学，没有可查询的状态，就是一份按栏目组织的导览。好处是即插即用，还能借给别的模型；代价是上限被上下文长度和摘要质量同时卡住，后面 RQ4 会看到写太长反而掉点。

元进化能力被拆成两块（PDF p. 4）：**规划与探索**，先定计划、优先走高价值区域；**信息管理**，把大量异质观察压成信息密度高的 $K$。后面的训练、入口图和 token 预算，都是在分别喂这两块。

## 核心设计一：结果奖励，地图好不好看它能不能帮你做题

### 旧问题：探索没有标准答案

写导览时没有题，没法逐步打分。若对导览的文风、格式打分，监督又回到了人类偏好。论文要的信号只问一件事：这份 $K$ 有没有用。

### 新设计：用下游命中率的增量当分数

对环境 $E$ 准备一组下游任务 $T_E$，一份 $K$ 的奖励定义为它带来的成功率增益（PDF p. 4，式 1）：

$$
R_{\mathrm{evolve}}(K)=\mathrm{Success}(T_E\mid K)-\mathrm{Success}(T_E\mid\varnothing)
$$

前一项是带着 $K$ 做题的表现，后一项是什么先验都不给的基线。落到实现上，一个网站有 $M$ 道带答案的题 $\{(Q_j,A_j)\}_{j=1}^{M}$，成功率就是命中比例（PDF p. 5，式 2）：

$$
\mathrm{Success}(T_E\mid K)=\frac{1}{M}\sum_{j=1}^{M}\bigl[f(Q_j,K)=A_j\bigr]
$$

$f(Q_j,K)$ 是 agent 拿着 $K$ 对问题 $Q_j$ 给出的答案，方括号是「答对记 1，答错记 0」。训练集是 20 个网站上的 600 道深搜题，用它们的标准答案算成功率（PDF p. 4）。

### 工作机制：打一次分，要把整组题跑一遍

![示意图分训练和推理两条泳道：训练时，探索写 K 的上限是 500 步，写完后要带着 K 把该站 M 道题各跑一遍、每题上限 100 步，再减去不带 K 的基线得到 R_evolve，并按它筛选轨迹；推理时同样探索写 K，然后只答真正到来的那道题，不再打分。](/reports/Reward-Free-Self-Evolution/reward-cost.svg)

*图：本文根据 PDF p. 4–6 的式 1–2、3.2–3.3 节与 4.1 节步数和时间上限画的机制示意，不是实测时间轴；绿、紫方块长度按步数上限画，实际步数会更短。*

这张图要看出三件事。

第一，奖励是**延迟的、轨迹级的**。一条探索轨迹几百步，分数要等 $K$ 写完、再拿去跑完一组下游题才出现。教师轨迹平均 374.8 步，每步 3322.4 个 token（观察加动作）（PDF p. 5）。

第二，奖励是**相对量**。减掉无 $K$ 基线，问的是「这张地图值不值」，不是「这个 agent 本来多强」。SFT 阶段明确用 Qwen3-30B-A3B 当评估 $K$ 的执行器（PDF p. 5），所以式 1 的数值绑定在这个执行器上。

第三，奖励**只在训练时出现**。论文把「训练时靠奖励、推理时不要奖励」称为原生进化的标志（PDF p. 5）。

### 收益

有了这把尺，教师的三份 $K$ 可以挑一份，学生自己采的也可以挑。教师挑出的 $K^\ast$ 让 Qwen3-30B-A3B 在训练题上的准确率平均比零知识基线高 10.72 个绝对百分点（PDF p. 5）。这说明信号本身是有区分度的。

### 代价与边界

- **贵。** 论文自己承认，每评一份 $K$ 都要让辅助 agent 跑一组下游题，训练循环里实时算分不现实（PDF p. 5）。这直接决定了下一节不上 GRPO。
- **题库没有消失，只是被提前用掉了。** 推理时「无任务」成立，是因为 600 道带标签的题在训练时已经把「什么样的 $K$ 有用」教进了权重。
- **训练与评测的判分口径没有对齐证明。** 式 2 写的是答案相等；主评测用的是 LLM 裁判做语义等价判定（PDF p. 6–7）。训练时 $f(Q,K)=A$ 具体怎么判，论文没写。
- **RFT 阶段的评估执行器没有写明。** SFT 写了用 Qwen3-30B-A3B；RFT 只说用 $R_{\mathrm{evolve}}$（PDF p. 6）。Seed-OSS-36B 的候选是不是也拿 Qwen 打分，PDF 没交代。

### 可迁移启发

「过程没有标准答案，就用下游效用当过程的分数」是一套干净的模板。写代码库索引、写内部 wiki 导览、写工具说明，都可以问同一句：这份摘要让一个固定执行器在一组真题上多答对多少。代价也一起迁移：你得先有一组真题，才能训出「以后不看真题也会写摘要」的策略。

## 核心设计二：SFT，先让教师把「乱逛」变成可模仿的行为

### 旧问题：会照着指令逛，不会压出有用信息

RQ1 里有直接证据：同一份专家 prompt，未训练的 Qwen 基座自己写 $K$，WebWalker 从不写 $K$ 的 22.04 掉到 19.50（PDF p. 7–8）。论文的解释是，基座能跟着复杂探索指令走，但压不出高价值信息，反而产出噪声或幻觉，执行时把自己带偏（PDF p. 8）。探索本身可以是负资产。

### 新设计：教师采三份，按奖励留一份

教师 $\pi_T$ 是 Gemini-2.5-Pro。它在多样的网页环境里互动、自己写结构化的 $K$。每个训练网站采 3 份候选 $\{K_i\}_{i=1}^{3}$，用上一节的奖励挑出最好的 $K^\ast$，连同完整探索轨迹一起留下（PDF p. 5，式 3）：

$$
T^\ast=\{Q,o_1^\ast,a_1^\ast,o_2^\ast,a_2^\ast,\ldots,o_k^\ast,a_k^\ast\}
$$

$o$ 是每步观察，$a$ 是每步动作。学生 $\pi_{\theta_0}$ 在这些轨迹上做逐步模仿，得到 $\pi_{\theta_1}$。

### 工作机制：教师 prompt 是一份三段式工作流

教师不是自由发挥。附录 C.1 给它的 prompt 很长（PDF p. 18–21）：

- **第 0 段，规划**：读聚类统计，按各类网址数的比例分配 token 预算（经验值每条页面 50–80 token、每个类目头 100–150 token），把计划写进文件。
- **第 1 段，逐类处理**：每个类目先强制读预算，再结合结构分 `[score:S]` 和语义相关性挑页面、抓取、按模板写入导览，最后标记完成。
- **第 2 段，收尾**：超出上限就压缩，低于下限就回去多抓页面扩写，最后在开头加一段 Overview。

约束包括：只收本域页面、必须摘要不能照抄、每条页面记录必须带完整网址、按计划分配篇幅而不是平均分（PDF p. 18）。

SFT 的目标写得很清楚：学生学会这些复杂动作之后，推理时**不再需要密集的 prompt**（PDF p. 5）。对照附录 C.2，训练后的 agent 拿到的生成说明确实短得多，但仍给了工具、处理模式和 token 上下限（PDF p. 21–22）。

### 收益

SFT 之后两个骨干都已大幅离开基线：Qwen 在 WebWalker 上从 22.04 到 38.17，Seed 从 16.26 到 28.57（PDF p. 7，Table 1）。

### 代价与边界

- **工作流被搬进了权重，不是消失了。** 论文批评别人依赖人设计的工作流，自己把工作流写进教师 prompt，再蒸馏给学生。这是合法的训练技巧，但「不要工作流」只对训练后的推理成立。
- **「好」是相对 Qwen3-30B-A3B 定义的。** 3 份候选按这个执行器的增益来挑。
- **训练超参全空。** 学习率、epoch、长轨迹如何截断、是否只在动作 token 上算损失，PDF 都没给。

### 可迁移启发

目标行为是长程、稀疏、只有结果才知道好坏时，先用强模型加可执行清单把行为采出来，再按下游效用挑最好的那条给学生模仿，仍是最稳的冷启动。关键不在「有没有 SFT」，而在筛选标准是不是下游效用。只按格式或教师自评挑，Prompt-only (Base) 那种「越探索越吵」就会回来。

## 核心设计三：RFT，轨迹太长、奖励太贵，所以不上在线 GRPO

### 旧问题：GRPO 在这里算不动

SFT 只能模仿教师走过的路；论文还想让学生自己试错，长出更好的探索和信息管理策略（PDF p. 5）。标准在线 RL（比如 GRPO）在这个设定下不可行，原因有两条（PDF p. 5）：

1. **地平线极长**：写一份 $K$ 要几百步，奖励稀疏，反向传播的显存开销巨大；
2. **奖励评估太重**：见上一节那张图，评一份 $K$ 要把一组题跑一遍。

### 新设计：采样和更新解耦

学生 $\pi_{\theta_1}$ 自己探索训练网站，产出 $C$ 份候选 $K$；用 $R_{\mathrm{evolve}}$ 打分，只留分数最高的轨迹，作为下一轮的训练集。这个过程做两轮，最终策略记为 $\pi_{\theta^\ast}$（PDF p. 5–6）。

### 工作机制：多采样、只留最好、再模仿

论文在引言里把它称作「on-policy」的拒绝采样（PDF p. 2），意思是候选由当前策略自己采。但更新本身是在筛过的轨迹上做监督微调，没有优势函数、没有 KL 约束，也不把落选轨迹当负样本。

**我们如何解释它。** 采样是同策略的，更新是离线的模仿。它比 GRPO 便宜的地方在于：每轮只需要为「选哪条」付评测费，不需要为每个 token 算梯度权重。它丢掉的是差轨迹里的信息，学到的是「当前策略能采到的最好」，不是「好在哪、差在哪」。

### 收益

Table 1 里 RFT 相对 SFT 大体向上：Qwen 的 WebWalker 平均 38.17 → 40.91、WebVoyager 平均 51.50 → 57.44；Seed 的 WebWalker 平均 28.57 → 37.50、WebVoyager 平均 56.00 → 56.79（PDF p. 7）。论文据此说结果奖励提供了正确信号，学生最终超过了教师（PDF p. 8）。

但不是每一格都涨：Qwen 的 Conference 从 45.05 降到 43.14，Seed 的 Wolfram 从 71.73 降到 63.04、Dictionary 从 53.49 降到 51.16（PDF p. 7）。

### 代价与边界

- **$C$ 没有给数字**，筛选阈值、每轮吃多少轨迹也没给（PDF p. 6）。
- **第二轮收益有限**，下面 RQ3 的 Figure 4 专门讲。
- **题库仍在。** RFT 打分依然要那 600 道题，它没有把训练监督也零掉。

### 可迁移启发

长程 agent 训练里，若单条轨迹就有几百步、奖励还要另开一条评测流水线，别默认上 GRPO。拒绝采样用「更多评测」换「更少反向传播」，通常更先跑得起来。代价是 $C$、阈值和迭代次数几乎没有理论指导，只能看下一轮还涨不涨。

## 核心设计四：入口图 $G(U)$，「自发探索」不是从裸网址起步

### 旧问题

子页面很多的网站，直接给首页网址、放任自由探索，会跑很久，输出也不稳定（PDF p. 7）。

### 新设计：先建图、打分、聚类

1. 把网站建成有向图，页面 A 链到页面 B 就连一条 A → B 的边；
2. 每页的重要性按入度、出度加权（PDF p. 14，附录 A）：

$$
\mathrm{Importance}(v)=0.7\cdot d_{\mathrm{in}}(v)+0.3\cdot d_{\mathrm{out}}(v)
$$

$d_{\mathrm{in}}$ 是有多少页指向它，$d_{\mathrm{out}}$ 是它指向多少页；

3. 按网址前缀从第一段路径开始递归切分，直到每组满足一个规模约束。这个约束的具体数值 PDF 没给（PDF p. 14）。

得到的 $G(U)$ **替换原始首页**，作为环境的结构化入口（PDF p. 7）。

附录 B.1 是 SIGCHI 官网的处理结果：5 个簇、221 个网址，簇大小 $[40,10,130,21,20]$；`https://sigchi.org/conferences/upcoming` 得分 227，活动簇里大量页面只有 11 分（PDF p. 14–15）。B.2 是写出来的 ACL 2024 导览：2 个类目、分析了 31 页，每条是日期、场馆、截止日这类可执行事实加网址，不是页面原文（PDF p. 15–18）。

训练后 agent 的 prompt 还按站点规模分两种模式：不超过 250 个网址用 FULL，每条都收；更大就用 SELECTIVE，每类按分数最多取 20 条（类目不超过 8 个时）或 10 条（PDF p. 22）。

### 收益

这是让长程探索稳下来的工程前置。论文说它滤掉噪声、把大站切成可解释的簇，显著降低了探索时的认知负担（PDF p. 7）。后面所有实验都建立在「agent 面对的是已经聚类打分的入口」这个前提上。

### 代价与边界

这一步把相当一部分「探索」挪回了确定性脚本。0.7 和 0.3 是手定的权重，不是学出来的；按网址前缀聚类，遇到不按路径组织的网站会切错。Figure 1 把本文的人类依赖画得很短，但 $G(U)$ 的爬取、打分、聚类在推理时仍然要跑。**我们把它算作推理阶段仍在的系统脚手架**，不是模型内化的能力。

### 可迁移启发

想让模型「自己探索」一个大环境，先问它是不是在一个已被切成目录的空间里走。代码仓的目录树、文档站的侧栏、API 的分组标签，都是 $G(U)$ 的近亲。把建目录算进系统成本，再谈模型有多自发，数字才可比。

## 「零奖励」到底零掉哪一层

四个设计讲完，可以把标题拆开了：

| 层 | 论文实际做了什么 | 还留下什么 |
|---|---|---|
| 训练时的奖励 | 有。$R_{\mathrm{evolve}}$ = 带 $K$ 命中率减不带 $K$ 命中率（PDF p. 4） | 600 道带答案的题、教师 Gemini-2.5-Pro、评估执行器 |
| 推理时的外部奖励 | 无。进新环境不再算 $R_{\mathrm{evolve}}$，也不给任务集（PDF p. 5） | — |
| 推理时的人类指令 | 摘要说推理时不需要人类指令（PDF p. 1） | 入口图 $G(U)$；附录 C.2 的生成说明，含工具、处理模式与 token 上下限（PDF p. 21–22）；Cognitive Kernel-Pro 脚手架 |

所以 Reward-Free 的准确读法是：

> 把「这份地图好不好」的监督全部提前折进训练；推理时只跑已经内化的探索策略，不再现场打分。

这个切分本身有工程价值：几百步的探索轨迹，现场打分确实太贵。但把它读成「整个生命周期都没有奖励、没有人」，就会把题库、教师和入口图一起洗掉。

## 实验怎么证明

### 设置：网页脚手架、两个骨干、1427 条过滤后的题

框架是 Cognitive Kernel-Pro，网页环境用 Playwright。动作只有预定义的 `click`、`scroll`、`goto`、`goback`、`stop`；每步观察是当前可见组件的可访问性树（accessibility tree）。轨迹在三种情况下结束：agent 自己判定完成、步数到上限 $t$、墙钟超过 $L$ 秒（PDF p. 6）。

| 阶段 | 步数上限 $t$ | 时间上限 $L$ | temperature / top-p |
|---|---:|---:|---|
| 生成世界知识 | 500 | 43200 秒（12 小时） | 0.3 / 0.95，为了候选更多样 |
| 下游答题 | 100 | 3600 秒（1 小时） | 0 / 0.95，为了答案更稳 |

骨干是 Qwen3-30B-A3B-Instruct-2507 与 Seed-OSS-36B-Instruct（PDF p. 6）。

评测用的是两个基准的子集，不是全量：WebWalker 的 conference、game、organization、education 四个域各随机十个网站；WebVoyager 只取 Wolfram、Apple、Dictionary、Coursera 四个站。两边都滤掉骨干靠预训练知识就能直接答的题，最后剩 1427 条，指标一律是准确率（PDF p. 6）。

判分都用 LLM 裁判，而且两边不是同一个（PDF p. 6–7、p. 22–24）：

- **WebWalker**：Qwen-2.5-32B 判最终答案与标准答案是否语义一致，输出 0 或 1。附录 C.3 明写不必字面匹配，更短的答案、不同日期格式、同义转述都算对。
- **WebVoyager**：Gemini-2.5-Flash，按官方协议吃问题、agent 答案和每一步的可访问性树，判 SUCCESS 或 NOT SUCCESS。附录 C.4 有一条容易打架的规则：答案与树矛盾时信树，答案里有树里没有的信息时信答案。

没有人工复判，没有裁判一致性数字，也没给 1427 条在两个基准里各占多少。

### RQ4：地图不是越长越好

在 prompt 里显式规定生成长度的上下限，测 Qwen3-30B-A3B 的五档（PDF p. 9，Figure 5，数值读自图上标注，正文也引了其中几个）：

| 长度设置 | Conference | Game |
|---|---:|---:|
| 0（不写 $K$） | 24.28 | 23.65 |
| 4k–8k token | 40.55 | 30.74 |
| 8k–16k | 49.85 | 39.71 |
| 16k–32k | 48.05 | 41.56 |
| 32k–64k | 51.96 | 40.72 |

从短到中收益大，再拉长就进入平台期。论文的归因：太短会丢关键信息，中等长度能装下要点，太长会引入冗余噪声、干扰执行（PDF p. 9）。

**我们如何解释它。** 这和入口图、教师 prompt 里的 token 预算是同一件事：$K$ 被当成要精打细算的上下文配额，不是越全越好的知识库。但「过长有害」只在 Game 上看得到（41.56 → 40.72），Conference 在 32k–64k 反而最高。另外，主实验 Table 1 到底用了哪个长度区间，论文没写；RQ4 的 51.96 不能读回 Table 1 的 43.14。

### Case：ACL 2024 的两个日期

Figure 6（PDF p. 10）的题目是：ACL 2024 的印刷订单服务注册截止日，和主会场馆更新公告之间隔几天。原图是两栏文字轨迹，这里转成表：

| | 不带世界知识 | 带世界知识 |
|---|---|---|
| 第 1 步 | 从首页开始找注册截止日 | 从 $K$ 里读到印刷服务截止 2024-08-09；场馆页写了 Centara Grand，但没有公告日期，转去相关页面找 |
| 中间 | 第 4 步找到截止日 2024-08-09 | — |
| 收尾 | 第 7 步用「ACL 场馆通常提前 3–6 个月公布」的历史规律，把最早公告日估成 2024-02-01，算出 190 天 | 第 2 步找到场馆更新公告日 2024-05-05，算出 96 天 |
| 结果 | 错，共 7 步 | 对，共 2 步 |

这个例子说明两件事：地图把「去哪一页找」变成了先验；地图里没有的字段，agent 会去现场补，而不是硬编。附录 C.5 的执行 prompt 正是这样写的：摘要里已有答案就直接答（少见），有相关子页就去那些网址找，不确定或找不到就回首页重走，摘要全无关就整支作废从首页开始（PDF p. 24）。$K$ 是索引加摘要，不是封闭世界。

它只是一个例子，不单独证明方法成立。

## 限制、边界，以及不要补进去的实现

第 5 节结论很短（PDF p. 10）：两阶段训练让 agent 自发探索并蒸馏世界知识，推理时不需要人类指导或奖励；两个骨干约 20% 绝对提升；知识可迁移，14B 超过不带 $K$ 的 Gemini-2.5-Flash；最后一句落到自主自进化、通往 AGI。全文没有 Limitations 一节。

**被实验支持的：** 在过滤后的网页深搜子集上，训练后的 agent 自己写的 $K$ 能抬高命中率、减少答题步数；未训练基座直接写 $K$ 可能有害；SFT 与第一轮 RFT 贡献最大；$K$ 可以借给没训过的模型；长度收益递减。

**只是观察，不能升格的：** Figure 1 的人类依赖色条；Figure 6 一个例子；「探索的 scaling 比参数的 scaling 更关键」作为一般规律；结论里的 AGI。

**实验范围：** 只有网页。Figure 2 画了 Code 与 Game，没有对应的实验（PDF p. 4）。读成「通用环境自进化」超出了证据。

**没公开、会影响复现的：**

- RFT 的候选数 $C$、筛选阈值、每轮训练集大小；
- SFT 与 RFT 的优化器、学习率、batch、长轨迹截断方式、损失算在哪些 token 上；
- 600 道训练题如何构造，20 个训练网站与评测网站是否重叠，训练题与 1427 条评测题如何去重；
- 聚类的规模约束、主实验实际用的 $K$ 长度；
- 生成 $K$ 的实际步数、墙钟、算力与费用；
- 训练奖励里的「答对」怎么判，是否与评测裁判同一口径；
- RFT 打分时的执行器是否仍固定为 Qwen3-30B-A3B。

## 可迁移启发

1. **把「认识环境」和「完成任务」拆开。** 进一个新代码仓、文档站、后台系统，先生成一份带网址（或路径）的导览，再做具体工单。这一条不依赖本文的训练配方，今天就能用。
2. **过程没有标准答案时，用下游效用给过程打分。** 三份摘要里留下让固定执行器多答对的那份。Prompt-only (Base) 说明：会走流程不等于会压缩。
3. **长程、奖励贵时，拒绝采样通常比在线 GRPO 先跑得起来。** 采样与更新解耦，用评测换反向传播；记得看第二轮是否已经开始波动。
4. **给摘要设配额。** 在本文的网页设定里，从 4k–8k 加到 8k–16k token 收益最大，再往上基本持平；再长要提防噪声。repo map、内部 wiki 同理。
5. **先把环境切成目录，再谈模型有多自发。** $G(U)$ 是这套方法能跑起来的前置，不是细节；把它算进系统成本，不同方法之间才可比。
6. **分清哪些是配方依赖。** Gemini-2.5-Pro 教师、600 道带答案的题、Cognitive Kernel-Pro、12 小时生成预算，都不是随手可复用的超参。换一类环境就得重做题库，否则 $R_{\mathrm{evolve}}$ 没有定义。

## 关键词回看

- **世界知识 $K$**：针对某个环境实例写的 Markdown 导览，按类目列页面摘要和网址；推理时放进 prompt，不改权重。
- **原生进化 / 知识增强执行**：先探索写 $K$，任务出现后带着 $K$ 做题。
- **结果奖励 $R_{\mathrm{evolve}}$**：带 $K$ 命中率减不带 $K$ 命中率；只在训练时用，贵在每评一次要跑一组题。
- **SFT**：教师 Gemini-2.5-Pro 每站采 3 份 $K$，按奖励留一份，学生逐步模仿；教师轨迹平均 374.8 步、每步 3322.4 token。
- **RFT**：学生每站采 $C$ 份、按奖励留最好的再微调，做两轮；采样同策略，更新是模仿，不是 GRPO。
- **入口图 $G(U)$**：链接图打分（0.7 入度 + 0.3 出度）加网址前缀聚类，替代首页作为入口。
- **Prompt-only (Base)**：未训练基座照专家 prompt 写 $K$，结果比不写还差，是「探索会变成负债」的证据。
- **约 20 个点 / 17% 步数 / 18.3**：WebWalker 上两骨干的绝对提升，答题步数的平均降幅，Seed 的 $K$ 借给 Qwen3-14B 的两域平均增益。
- **Reward-Free 的准确含义**：推理时不打分，训练时的题库、教师和奖励都在。
