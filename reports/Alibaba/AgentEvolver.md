# AgentEvolver：自进化的三件事是出题、导航和归因，改的是训练环，不是 Agent 代码

<!-- release-date: 2025-11-13 -->

> 本文依据 **AgentEvolver: Towards Efficient Self-Evolving Agent System**，阿里巴巴通义实验室（Tongyi Lab, Alibaba Group），arXiv:2511.10395v1，2025-11-13 提交（封面右上角印 2025-11-14），共 29 页：正文 p. 1–27，参考文献 p. 27–29。七位共同一作是 Yunpeng Zhai、Shuchang Tao、Cheng Chen、Anni Zou、Ziqian Chen、Qingxu Fu、Shinji Mai，通讯作者 Zhaoyang Liu 与 Bolin Ding，其余作者为 Li Yu、Jiaji Deng、Zouying Cao、Jingren Zhou（PDF p. 1）。首页给出的代码仓是 [modelscope/AgentEvolver](https://github.com/modelscope/AgentEvolver)。页码均指 PDF 自身页码。文中区分三件事：**论文明确写了什么**、**我们怎么解释它**、**哪些是外部资料或我们自己的读图与计算**。

## 读前先把几个词说成人话

这是一篇 **Agent 训练方法 + 训练系统** 论文，没有基座架构和预训练配方。它问的是：面对一个没有现成题库、也没有现成奖励的新环境，怎样让大模型自己出题、自己复用探索经验、自己把稀疏的终局分拆成逐步功过，最后仍接到一个普通的策略梯度更新上。

会反复出现的词：

- **rollout（轨迹生成）与 trajectory（轨迹）**：让当前策略自己去环境里干一遍活叫 rollout，干出来的一次完整执行叫一条轨迹。
- **GRPO（Group Relative Policy Optimization，组相对策略优化）**：同一道题采一组轨迹，用组内均值与标准差把奖励变成优势，不训 value 模型。出处见 DeepSeekMath 一篇。论文说当前 LLM Agent 训练基本都是 PPO 或 GRPO 一类（PDF p. 2）。
- **稀疏终局奖励**：几十步的工具调用，只在最后给一个对错。评测环境 AppWorld 与 BFCL v3 都是这种（PDF p. 18）。
- **交互沙箱（interaction sandbox）**：只有状态、动作和转移的环境接口，**没有目标，也没有奖励**（PDF p. 3）。
- **代理任务 / 代理奖励（proxy task / proxy reward）**：真正要考的目标任务分布事先不知道，系统先在沙箱里自己造一套训练用的任务和打分办法（PDF p. 4）。
- **经验（experience）**：在这里不是回放缓冲区里的状态转移，而是一段自然语言：什么时候用、具体怎么做。靠检索塞进提示词，用 **上下文学习（In-Context Learning，ICL）** 引导下一步（PDF p. 8–9）。
- **avg@8 / best@8**：每个实例独立跑 8 次，取平均与最好的任务完成率（PDF p. 18）。best 是多次取最好，不是无偏的 pass@k。

三条机制各管训练流的一段，先各记一句：

- **Self-Questioning（自出题）**：环境 → 任务。先在环境里乱走，再根据走过的路出题，把走过的路提成参考解，再让裁判对照参考解给整条轨迹打分。
- **Self-Navigating（自导航）**：任务 → 轨迹。把过去的成败写成经验；一半 rollout 带着经验走、一半不带；训练时把经验 token 剥掉，再只给正优势的经验样本放宽裁剪。
- **Self-Attributing（自归因）**：轨迹 → 策略。让另一个 LLM 给每一步判 GOOD 或 BAD，和终局分分开标准化后相加，再累加成逐步优势。

## 它改的是哪一层

名字里带「Agent」「RL」「自进化」的工作很多，先分清各自改的是哪个部件。下面的对照是我们的读法，论文正文没有和这些工作做实验比较：

| 工作 | 改的是什么 |
|---|---|
| Agent-Lightning | 已写好的 Agent 运行时与训练器之间的接口 |
| SkyRL-Agent | 多轮长程轨迹在集群上的异步流水线调度 |
| Polar | 把观测点放到模型 API，harness 当黑盒原样跑 |
| AReaL-SEA | 多 Agent 合成对话并为每道题产出可执行 checker，再做结果奖励 RL |
| SEAL | 模型给自己写自编辑指令，再更新权重 |
| Alita | 工具 / 技能库，自己造 MCP 工具 |
| Darwin-Godel-Machine | Agent 改写自己的代码 |
| Agent-Workflow-Memory | 从轨迹里归纳可复用的工作流记忆 |
| Absolute-Zero、R-Zero | 题库与课程，出题者与解题者自博弈 |
| **AgentEvolver** | **出题、探索时的经验复用、稀疏奖励的逐步拆分这条训练环**；策略本身仍用 GRPO 类更新改权重 |

「自进化」在这篇里指的是训练信号由 LLM 自己长出来，而不是 Agent 改自己的代码或 harness。

## 一句话先说清

训一个会用工具的长程 Agent，卡在三件都贵的事上（PDF p. 1–2）：

1. **没有题**：新环境里工具的功能往往未知，手工造足够多样的多步任务成本很高。
2. **探索浪费**：内在奖励、UCB 一类探索技巧用在长程工具 Agent 上常常无效，因为每条 rollout 本身就贵；于是训练仍靠 PPO / GRPO 海量采样，论文称之为「近似蛮力的探索，冗余轨迹多、学习价值有限」。
3. **样本利用率低**：GRPO 把终局的一个分平均地记到每一步，分不清关键决策和无关步骤（PDF p. 11）。

它的回答不是换一个优化器，而是把「学习的主动权」从人设计的流水线交给 LLM，沿标准训练流的三段各放一个机制（PDF p. 2）。实验在 AppWorld 与 BFCL v3 上，用 Qwen2.5-7B / 14B 当策略：三件齐上后，7B 两基准平均 avg@8 从零样本的 15.8 升到 45.2，14B 从 29.8 升到 57.6（PDF p. 19，Table 1）。摘要自己把这些称作**初步实验**（PDF p. 1）。

正文把 7B 的这段提升写成「improves by 29.4%」（PDF p. 19）。按 Table 1 相减，29.4 是两个百分数之差（45.2 − 15.8），也就是 29.4 个百分点，不是相对提升 29.4%。同一段里其余几个百分数也都是这样的差，下文统一写成「个点」。

## 全景：环境 → 任务 → 轨迹 → 策略

![AgentEvolver 总览图分三栏：左栏 Self-Questioning 从环境出发，经环境探索（可用工具、环境画像、好奇心驱动的探索）、任务合成（探索轨迹加用户偏好的难度与风格，得到带参考轨迹的任务草稿）、任务策展（回放参考轨迹，成功的留作可行任务，不可达的丢掉）产出任务；中栏 Self-Navigating 从经验池检索经验，一部分 rollout 带不同经验、一部分不带，训练时把经验遮掉再优化；右栏 Self-Attributing 让 LLM 读任务、轨迹和奖励后逐步判 GOOD 或 BAD，归因分与终局分各自归一化后合成逐步奖励，再从后往前累加成逐步优势并广播到 token，最后更新策略。引自原文 Figure 2（PDF p. 3）。](/reports/AgentEvolver/fig2-overview.png)

三栏分别对应训练流的三段，箭头是数据流，不是墙钟时间。系统层面，同一件事被画成一个由主控驱动的四段循环（PDF p. 15，Figure 10）：

| 段 | 模块 | 对应机制 |
|---|---|---|
| A 任务合成 | Task Manager：经环境服务探索、合成并过滤任务 | Self-Questioning |
| B 轨迹 rollout | 并行 Rollout Workers，经 Context Manager 拼提示、调异步 LLM 服务 | Self-Navigating 的混合采样发生在这里 |
| C 经验摘要 | Experience Manager：召回与语义摘要 | Self-Navigating 的经验池 |
| D 样本构造与更新 | 组织上下文、算优势，Trainer Workers 算损失、更新参数，再把权重写回 LLM 服务 | Self-Attributing 与策略更新 |

另有两块支撑设施不属于三条机制：管多轮上下文怎么拼、怎么裁的 **Context Manager**，以及把环境做成独立服务的 **Environment Service**（PDF p. 16–18）。三条机制回答「训练信号从哪来」，这两块回答「多轮 Agent 在系统里怎么跑」。

## 问题形式化：沙箱不给题，也不给分

论文先把环境和标准马尔可夫决策过程切开（PDF p. 3，式 1）：

$$
\mathcal{E}=(\mathcal{S},\mathcal{A},\mathcal{P})
$$

$\mathcal{S}$ 是可观察状态，$\mathcal{A}$ 是可执行动作，$\mathcal{P}(s'\mid s,a)$ 是转移。标准写法是 $(\mathcal{S},\mathcal{A},\mathcal{P},r,\gamma)$；这里拿掉了奖励函数 $r$ 和折扣 $\gamma$，意思是**环境不告诉你该做什么，也不告诉你做得好不好**。

真正要考的是一个未知的目标任务分布 $p_{\mathrm{target}}(g)$。每个任务 $g$ 对应一个目标状态 $s_g$，有一个真实奖励 $R_g(s,a)$；策略是目标条件的 $\pi_\theta(a\mid s,g)$，要在目标分布上最大化期望价值（PDF p. 4，式 2–3）：

$$
J_{\mathrm{target}}(\theta)=\mathbb{E}_{g\sim p_{\mathrm{target}},\,s_0\sim p_0}\bigl[V^{\pi_\theta}(s_0,g)\bigr]
$$

因为 $p_{\mathrm{target}}$ 和 $R_g$ 都不知道，论文把自进化定义成构造两个映射（PDF p. 4，式 4–5）：

- **代理任务生成** $F_{\mathrm{task}}:\mathcal{E}\to\Delta(G)$，从沙箱得到训练任务分布 $p_{\mathrm{train}}=F_{\mathrm{task}}(\mathcal{E})$；
- **代理奖励设计** $F_{\mathrm{reward}}:\mathcal{E}\times G\to(\mathcal{S}\times\mathcal{A}\to\mathbb{R})$，为每个任务造一个奖励函数 $\hat{R}_g$。

然后在代理任务和代理奖励上训练，希望真正的 $J_{\mathrm{target}}$ 跟着涨（PDF p. 4，式 6–7）。Self-Navigating 被写成第三件事：不改目标函数，只让策略少跑废轨迹（PDF p. 4）。

**我们如何解释它。** 这一节真正的设计判断只有一句：**先承认新环境不会给你题、也不会给你分，再把「出题」和「打分」做成系统里的一等公民**。后面三条机制就是这两个映射的实现：Self-Questioning 实现 $F_{\mathrm{task}}$，顺带给出一个轨迹级裁判当 $F_{\mathrm{reward}}$ 的兜底；Self-Attributing 实现更细的逐步 $F_{\mathrm{reward}}$；Self-Navigating 改的是采样效率。

有一个边界容易读漏。「沙箱没有奖励」是形式化设定，评测用的 AppWorld 和 BFCL v3 其实都有官方判分（PDF p. 18）。论文不是说真实环境永远打不出分，而是说**不能假设每个新环境都配好了任务分布和稠密奖励**。

### 可迁移启发

凡是「环境接口已经有了，题库和过程监督还没有」的项目，先问 $F_{\mathrm{task}}$ 和 $F_{\mathrm{reward}}$ 各由谁在做。两件事都还靠人的话，后面的优化器再稳，也只是在一个很小的人工题库上打转。

## Self-Questioning：先在环境里走一遍，再问「这能解决什么问题」

![Self-Questioning 流水线：用户给出环境画像与用户偏好；① 探索阶段在地图环境里行走，留下一条动作与观察交替的轨迹；② 任务合成阶段把这条轨迹和用户偏好（难度、风格、评分细则）合在一起，问「这条路能解决什么问题」，得到一个查询（例如规划回家的路线）和一份参考解；③ 任务策展阶段经去重与用户自定义过滤，再派一个 Agent 沿参考解回放，确认查询与解都可行。引自原文 Figure 3（PDF p. 5）。](/reports/AgentEvolver/fig3-self-questioning.png)

### 旧问题

论文把数据困难写成两条（PDF p. 4–5）：新环境大多没有现成的训练数据，手工造多步复杂任务很贵；已有数据又常常多样性差、分布偏。对工具 Agent 来说两条会叠在一起，因为你甚至还不知道环境里有哪些 API 能用。

### 新设计：顺序反过来

普通题库是「先有题，再让模型去找答案」。这里反过来：**先探索，再根据探索轨迹问「这能解决什么问题」，并把走过的路提成参考解**（PDF p. 6–7）。论文点明了这个顺序的好处：题是在探索之后才出的，所以出出来的题可以超出当前策略的能力，而它的正确答案已经在探索阶段被真实执行过（PDF p. 7）。

它要回答四个问题（PDF p. 5）：怎样理解一个未知环境并找到有价值的状态；怎样出既合用户偏好又足够多样的题；怎样避免幻觉、保证题可执行；怎样给整条轨迹一个代理奖励。

### 机制一：环境画像当动作先验，高温 LLM 当好奇心

**环境画像（environment profile）** 用「实体、属性、操作」三类条目把环境写成一份说明书，作为初始状态 $s_0$ 的一部分，让好奇心别漫无目的（PDF p. 5–6）。Figure 4 的例子是示意沙箱里的一张游戏地图：实体是地图，属性有道路、建筑、红绿灯，操作有移动、等灯过路口、进入建筑（PDF p. 6）。实验给 AppWorld 和 BFCL 都建了画像，但真实画像没有印出来（PDF p. 18）。

探索策略是一个高温 LLM，每步看画像和历史状态选动作（PDF p. 6，式 8）：

$$
a_t\sim\pi_{\mathrm{explore}}(\cdot\mid s_t,s_{t-1},\ldots,s_0),\qquad s_{t+1}\sim\mathcal{P}(\cdot\mid s_t,a_t)
$$

高温是为了撞见非常规的交互和隐藏状态。为了兼顾覆盖与深度，探索分两段（PDF p. 6）：前 $N_b$ 步**广度优先**，先摸清环境的基本语义；之后改**深度优先**，沿前面发现的有希望方向往下挖，同时只看最近 $N_d$ 个观察，防止过早收敛到一种行为。实验取 AppWorld $N_b=3$、$N_d=17$，BFCL $N_b=3$、$N_d=27$；探索 Agent 是 Qwen-Plus，温度 1（PDF p. 19）。

### 机制二：按难度和风格把轨迹变成题，并提出参考解

用户偏好卡两根轴（PDF p. 6）：**难度**按潜在解涉及多少实体、属性、操作来量；**风格**由用户给的评分细则规定。合成时先把探索轨迹压成「用户输入、LLM 动作、执行结果」，加上偏好 $u$，交给 LLM 写出候选查询 $g$（PDF p. 7，式 10），于是 $F_{\mathrm{task}}(\mathcal{E})=\Psi(\Phi(\mathcal{E}),u)$。

参考解的提取利用了出题顺序：把简化后的动作–观察序列和对应题目交给 LLM，抽出完整的解题过程，作为代理金标（PDF p. 7）。实验要求合成题涉及 2 个实体、3 个属性、3 个操作，难度为 hard；合成用 Qwen-Plus 默认设置（PDF p. 18–19）。

### 机制三：去重、回放、可选的分布混合

合成出来的题质量参差，所以要过滤，让 $p_{\mathrm{train}}$ 更像 $p_{\mathrm{target}}$（PDF p. 7）：

- **合成过程中**：先按词面重叠去重，超过阈值当场丢，实验阈值 0.8（PDF p. 19）；再用向量模型做语义相似检查，引导生成避开相似轨迹（PDF p. 7）。
- **合成之后**：再做一轮词面去重，然后**拿参考解在环境里真跑一遍**，执行失败的题视为参考解可能是幻觉，整题丢掉（PDF p. 7）。Figure 3 右栏的「Try Replaying」就是这一步。
- **分布混合（可选）**：没有外部数据时 $p_{\mathrm{train}}=F_{\mathrm{task}}(\mathcal{E})$；拿得到目标分布的样本时，用 $p_{\mathrm{hybrid}}=(1-\lambda)p_{\mathrm{target}}+\lambda p_{\mathrm{task}}$，$\lambda\in(0,1]$（PDF p. 7，式 11–12）。实验在混合数据上训练时，把来自合成题的优势乘 0.5，以减少偏差、稳住训练（PDF p. 19）。

### 机制四：带原则、对照参考解的 LLM 裁判

合成题没有环境金标奖励，所以还要给整条轨迹一个代理分。论文把这个 **LLM 裁判（LLM Judge）** 定位成 $F_{\mathrm{reward}}$ 的通用兜底：不为具体环境优化，用户有自己的环境奖励时可以替换（PDF p. 8）。它守两条原则（PDF p. 8）：

1. **相关与重复检查**：轨迹里出现与任务无关、幻觉或冗余的步骤又没有清楚理由，直接零分；
2. **连续打分**：正确解落在高分段，错误尝试落在低分段，具体分数看步数效率和中间错误，保留部分进度。

然后对照参考解核对：参考解里的关键步骤是否都在 Agent 的执行里出现，允许功能等价的替代路径（PDF p. 8）。实验用 Qwen3-235B-A22B 当裁判，理由是它更能遵守复杂的评分标准（PDF p. 19）。

### 收益：证据在第 7.3 节

Table 1 里，只加 Self-Questioning（即在合成题上用裁判分做 RL），7B 两基准平均 avg@8 从 15.8 升到 36.1，14B 从 29.8 升到 52.3（PDF p. 19–20），是三个机制里一次性跳得最远的一段。

合成题与人工题库的对比（PDF p. 20，Table 2，avg@8 / best@8）：

| 模型 | 训练数据 | AppWorld | BFCL v3 | 平均 |
|---|---|---|---|---|
| Qwen2.5-7B | 零样本 | 1.8 / 5.6 | 29.8 / 42.4 | 15.8 / 24.0 |
| | 原始 $p_{\mathrm{target}}$ | 16.1 / 25.5 | 58.8 / 74.0 | 37.5 / 49.8 |
| | 合成 $p_{\mathrm{train}}$ | 23.2 / 40.3 | 49.0 / 60.6 | 36.1 / 50.5 |
| | 混合 $p_{\mathrm{hybrid}}$ | 21.8 / 36.3 | 65.3 / 75.6 | 43.6 / 56.0 |
| Qwen2.5-14B | 零样本 | 18.0 / 31.4 | 41.6 / 54.1 | 29.8 / 42.8 |
| | 原始 $p_{\mathrm{target}}$ | 46.1 / 61.5 | 68.6 / 74.3 | 57.4 / 68.0 |
| | 合成 $p_{\mathrm{train}}$ | 44.3 / 65.5 | 60.3 / 72.1 | 52.3 / 68.8 |
| | 混合 $p_{\mathrm{hybrid}}$ | 48.4 / 68.1 | 73.0 / 81.1 | 60.7 / 74.6 |

论文的读法：合成数据相对零样本显著提升，接近原始数据；混合数据则完全超过只用原始数据（PDF p. 20）。更细地看：7B 在 AppWorld 上合成已经超过原始（23.2 对 16.1），在 BFCL 上却明显不如（49.0 对 58.8）；14B 两个基准的 avg@8 都是合成低于原始，要靠混合才反超。「接近人工题库」成立的是平均，尤其是 best@8，不是每一格。

裁判与数据量的两组消融原文画成柱图与折线，数字都标在图上（PDF p. 21，Figure 12）：

| 裁判配置（Figure 12b） | avg@8 |
|---|---:|
| 朴素裁判：无原则、无参考解 | 22.5 |
| 有原则、无参考解 | 33.1 |
| 有原则 + 参考解 | 44.3 |

| 合成样本数（Figure 12a） | 100 | 200 | 500 |

论文的判断：数据质量再高，只用朴素裁判几乎涨不动；原则能区分 rollout 质量；加上参考解后大幅提升，接近人工题库的训练效果（PDF p. 21）。数据量上，100 条就已经有较好表现，再加样本增益递减（PDF p. 20）。两张图都没写是哪个模型、哪个基准；两处 44.3 都与 Table 1 里 14B 在 AppWorld 上的 +Questioning avg@8 相同，我们推断是这一格，原文没有写明。

### 代价与边界

- **并非零人工。** 环境画像和用户偏好仍要人写；探索与合成用的 Qwen-Plus、裁判用的 Qwen3-235B-A22B，都比 7B / 14B 的策略大得多。
- **跨域不对称**（PDF p. 21，Table 3，avg@8 / best@8）：

| 模型 | 训练数据 | AppWorld | BFCL v3 |
|---|---|---|---|
| Qwen2.5-7B | 零样本 | 1.8 / 5.6 | 29.8 / 42.4 |
| | AppWorld 合成题 | 23.2 / 40.3 | **36.1 / 45.0** |
| | BFCL 合成题 | **1.2 / 4.2** | 49.0 / 60.6 |
| Qwen2.5-14B | 零样本 | 18.0 / 31.4 | 41.6 / 54.1 |
| | AppWorld 合成题 | 44.3 / 65.5 | **56.0 / 68.9** |
| | BFCL 合成题 | **22.9 / 40.8** | 60.3 / 72.1 |

  加粗是跨域格。论文强调 14B 从 AppWorld 迁到 BFCL 只比域内训练低 4.3 个点（60.3 − 56.0），并据此说能力可泛化（PDF p. 21）。但 7B 在 BFCL 合成题上训练后，AppWorld 从零样本的 1.8 掉到 1.2。跨域收益主要成立在 14B、而且是从 AppWorld 往 BFCL 带，不是对称的。
- **参考解受探索覆盖面限制。** 探索没走到的功能边界，出题和裁判会一起看不见。回放能去掉明显不可执行的题，去不掉「能执行但没价值」的题。

### 可迁移启发

1. **先探索再出题**，参考解来自真实执行，而不是让另一个模型对着 API 文档空想。
2. **回放当门禁**：合成题必须能在环境里再跑通一遍，这是最便宜的幻觉过滤。
3. **裁判要有锚**：原则能分开质量，对照参考解才把分数钉到这个环境上。
4. 环境画像是一份便宜的先验：先用实体、属性、操作把「这里什么算合法动作」写成短文，往往就够把乱走收住。

## Self-Navigating：经验写进提示词，训练时再剥掉

![Self-Navigating 三阶段：① 经验获取，从历史轨迹提炼经验存入经验池，按查询召回、重排、改写；② 经验混合 rollout，同一查询下一组不带经验（null）、一组带经验（exp），各自产出优势为正或为负的轨迹；③ 经验并入，训练前把经验部分划掉只留查询与轨迹，对带经验且优势为正的样本放宽裁剪上界后更新策略模型。引自原文 Figure 6（PDF p. 9）。](/reports/AgentEvolver/fig6-self-navigating.png)

### 旧问题

常规 RL 靠反复随机试错，轨迹冗余、收敛慢；而长程工具轨迹每一条都贵（PDF p. 8）。人不会这样学：人会从过去的失败里抽出教训，下次有针对性地用。

### 新设计：经验是一段可检索的自然语言

每条经验有两段（PDF p. 8–9）：**When to use** 写适用条件，同时当检索的触发器，和查询做向量匹配；**Content** 写具体指令、注意事项或推荐策略。Figure 5 的 AppWorld 例子是：调用一个尚未确认存在或行为不明的 API 之前，先用 `apis.api_docs.show_api_doc` 看规格，删除或修改这类关键操作尤其如此（PDF p. 8）。经验全用自然语言，既可解释，又能用向量检索（PDF p. 9）。实现细节指向 ReMe 仓库（PDF p. 9 脚注）。

**建池。** 从 Self-Questioning 得到的合成题里抽任务，让初始策略每题独立跑 $N_{\mathrm{pc}}$ 次；轨迹按分数分成成功与失败，从成功、失败或成败对比里提炼经验，再用一个 LLM 评估经验是否可靠，最后写入向量库（PDF p. 9，式 13）。实验 $N_{\mathrm{pc}}=4$（PDF p. 19）。

**检索。** 查询与经验各编码成向量，按余弦相似度取 Top-$k$，再经重排与改写让经验更贴当前任务（PDF p. 9–10，式 14）。实验 $k=5$（PDF p. 19）。

### 机制一：一半带着经验走，一半自己走

只靠经验会把探索堵死。所以同一道题的 $N$ 条 rollout 分成两组（PDF p. 10，式 15）：不带经验的 $\mathcal{T}^{(v)}$，和把检索到的经验按模板 `{system prompt}<EXP>{exp}</EXP>{query}` 塞进初始提示的 $\mathcal{T}^{(e)}$。带经验的条数 $N_e=\lfloor\eta\cdot N\rfloor$，实验 $\eta=0.5$（PDF p. 19）。

两组在**同一个组内**统一标准化优势（PDF p. 10，式 16）：

$$
\hat{A}(\tau)=\frac{R(\tau)-\mu_R}{\sigma_R+\varepsilon_{\mathrm{norm}}}
$$

$\mu_R$、$\sigma_R$ 取自整组混合轨迹。带经验和不带经验的轨迹用同一把尺子比好坏。

### 机制二：训练时剥掉经验，只给正优势的经验样本放宽裁剪

**经验剥离（experience stripping）。** 训练序列里若还留着 `<EXP>…</EXP>`，模型可能背下这段外部文本，而不是把推理吸收进自己的策略。所以算梯度之前把经验 token 删掉，只剩 `{system prompt}{query}{trajectory}`（PDF p. 10–11，Figure 7）。rollout 阶段照样享受经验，训练阶段逼模型自己会。

剥掉之后立刻出现一个**离策错配**：采样时的条件是「查询 + 经验」，训练时的条件只剩查询，被优化样本的概率分布比 rollout 时窄得多，经验组的重要性比 $r^{(e)}$ 会失控地变大（PDF p. 11，引用 Yan 等人 2025）。PPO / GRPO 的裁剪能按住一部分，但裁得太狠，又会把经验引导出的有用梯度一并掐掉。

**选择性放宽（selective boosting）。** 只对经验组里**优势严格为正**的样本，把裁剪上界从 $\epsilon_{\mathrm{high}}$ 换成更大的 $\hat{\epsilon}_{\mathrm{high}}$；负优势样本仍用原来的上界（PDF p. 11，式 17）。目标函数是两组样本各自的裁剪项之和：

$$
\mathcal{L}(\theta)=-\frac{1}{N}\Bigl[\sum_{i=1}^{N_v}\min\bigl(r_i^{(v)}\hat{A}_i^{(v)},\,\mathrm{clip}(r_i^{(v)},1-\epsilon_{\mathrm{low}},1+\epsilon_{\mathrm{high}})\hat{A}_i^{(v)}\bigr)+\sum_{j=1}^{N_e}\min\bigl(r_j^{(e)}\hat{A}_j^{(e)},\,\mathrm{clip}(r_j^{(e)},1-\epsilon_{\mathrm{low}},1+\epsilon_j)\hat{A}_j^{(e)}\bigr)\Bigr]+\beta\,\mathrm{KL}(\pi_\theta\,\|\,\pi_{\theta_{\mathrm{old}}})
$$

其中 $\epsilon_j=\hat{\epsilon}_{\mathrm{high}}$ 当 $\hat{A}_j^{(e)}>0$，否则为 $\epsilon_{\mathrm{high}}$。实验取 $\epsilon_{\mathrm{low}}=\epsilon_{\mathrm{high}}=0.28$，$\hat{\epsilon}_{\mathrm{high}}=0.6$（PDF p. 19）。

式 17 里的重要性比写成整条轨迹的概率比 $\pi_\theta(\tau)/\pi_{\theta_{\mathrm{old}}}(\tau)$，而第 5 节又把优势广播到 token；实现里比值按轨迹算还是按 token 算，原文没有写清。$\beta$ 与训练配置里的 KL 系数 0.001（PDF p. 18）是否是同一项，也没有对上。

### 收益

**不训练，只在推理时塞经验。** Figure 13a 在两个基准上画了有无经验的柱，数字标在柱上（PDF p. 22）：

| AppWorld | 15.35 → 20.32（+4.97） | 25.17 → 31.68（+6.51） |
| BFCL | 32.83 → 38.60（+5.77） | 52.20 → 59.13（+6.93） |

正文写成平均「↑5.4% avg@4、↑6.7% best@4」（PDF p. 22），与四个差值两两平均一致（我们的计算），同样是百分点。图没有写用的是哪个基座。

**训练后：显式 ICL 对隐式内化。** Table 4 用 Qwen2.5-14B，在 dev 集上报 avg@4 / best@4，测试时一律不带经验（PDF p. 19、p. 22）：

### 代价与边界：两个旋钮都是短期与长期的交换

**经验比例 $\eta$。** 插图说明推理时经验越多越好；曲线说明训练时不是（PDF p. 23）。论文的解释：较大的 $\eta$ 早期涨得快，但压住了探索，长期更差；$\eta=0.5$ 最平衡。这张图纵轴标的是 Avg@8，而这一节的其余消融报的是 avg@4，原文没有说明。

**裁剪上界 $\hat{\epsilon}_{\mathrm{high}}$。** 在 $\{0.4,0.6,0.8,1.0\}$ 里扫（PDF p. 23）：放得越宽，前 20 步越快，但到 80 步会过拟合到有偏的轨迹上；0.6 最均衡。读图补一个细节：0.6 在前 20 步其实落后于基线，它赢在后 60 步的增长。

两个旋钮讲的是同一件事：**经验能把 Agent 更快地领到高分区，但领得太多，策略就不再自己探索**。经验池的冷启动也依赖 Self-Questioning 产出的合成题（PDF p. 19），这不是一个无中生有的记忆系统。部署时要不要继续塞经验，论文没有做主实验。

### 可迁移启发

1. **用的时候塞，学的时候剥。** rollout 时往提示里加检索笔记、工具手册或成功案例，训练时却把这些 token 留在序列里，模型学到的是「看见这段提示就会做」。
2. **提示条件与训练条件不一致时，别只靠默认裁剪。** 这里的做法很窄：只给正优势的经验样本放宽上界，负样本仍夹紧，和「所有样本一律 clip-higher」不是一回事。
3. **比例要留给探索。** 一半带、一半不带，是这篇在 $\eta$ 上扫出来的平衡点，不是定律。

## Self-Attributing：把终局一个分，拆成每一步的功过

![一条 4 步轨迹的奖励怎样变成逐 token 的优势：① 另一个 LLM 一次读完整条轨迹，逐步判 GOOD 或 BAD（示例里第 2 步是 BAD）；② GOOD 记 +1、BAD 记 −1；③ 过程通道用组内各轨迹的平均归因分做标准化得到 p1–p4，终局分 R 在组内单独标准化得到 o；④ 逐步奖励是 α 乘过程分，终局分只加在最后一步；⑤ 从后往前累加得到每一步的优势；⑥ 每一步生成的所有 token 共用这一步的优势，再接进式 17。按原文式 18–21 与 Figure 2 右栏重画的机制示意，不是实测。](/reports/AgentEvolver/attribution-reward.svg)

### 旧问题

GRPO 一类方法用稀疏的轨迹级奖励，把所有动作一视同仁，分不清关键决策和无关步骤（PDF p. 11）。长程工具轨迹里这个病尤其重：前 20 步都在正确地查 API，第 21 步删错一个字段，整局零分，前 20 步一起挨罚；反过来，前面走了很多弯路、最后一步修正过了测试，弯路也一起被奖励。

### 新设计：从「把终局分往回传」改成「事后判每一步的贡献方向」

论文把信用分配从时间传播改成贡献归因：让 LLM 回头判断每个动作对结局是正贡献还是负贡献（PDF p. 11）。学习信号拆成两个维度，**过程质量**（这一步有没有贡献）与**终局效果**（整条轨迹成没成），两路各自标准化再融合，最后映射到 token 级优势交给 GRPO（PDF p. 11）。它是第 2 节 $F_{\mathrm{reward}}$ 的具体实现。

### 机制一：一次调用，逐步打 GOOD / BAD

为了让跨步依赖看得见、又少花调用，归因是**单次、整体**的：任务、所有中间步、最终得分放进同一个提示，要求逐步输出分析和 GOOD / BAD 判断（PDF p. 12，Figure 8–9）。系统提示的规则可以缩成三条（PDF p. 12）：

- 终局分 **> 0**：对解有正贡献的步标 GOOD，无关、中性或有害的标 BAD；
- 终局分 **≤ 0**：只有主动纠正或减轻错误的步才标 GOOD，引入、传播或没修掉错误的标 BAD；
- 只看动作的技术影响，忽略礼貌之类的表面因素。

论文强调它和手写的**过程奖励模型（Process Reward Model，PRM）** 的差别（PDF p. 12）：二元标签不需要按任务设计打分表；用 LLM 的情境判断代替刚性启发式；输出的是方向，不是精确幅度，幅度交给后面的标准化和终局通道。实验用 Qwen-Max 做归因，整条轨迹一次批量调用（PDF p. 19）。

### 机制二：标签变成 ±1，按轨迹做标准化

GOOD 记 $+1$，BAD 记 $-1$，不引入任意的标量幅度，以免梯度被幅度带偏（PDF p. 12）。

标准化统计量在哪一层算，是一个关键选择。按步算的话，更长、更绕的轨迹会主导均值和方差；于是先对每条轨迹的归因分取平均，再在「各轨迹平均分」这个群体上算 $\mu_{\mathrm{attr}}$、$\sigma_{\mathrm{attr}}$，然后对每一步做（PDF p. 13，式 18）：

$$
\hat{r}_t^{\mathrm{attr}}=\frac{r_t^{\mathrm{attr}}-\mu_{\mathrm{attr}}}{\sigma_{\mathrm{attr}}+\epsilon}
$$

$\epsilon$ 取 $10^{-8}$ 之类的小常数。这样每条轨迹在统计里权重相同，不论长短。

**实现一节和这里不一致。** 第 7.1.3 节写的是标签映射成有符号单位分，「例如 GOOD → 1.0，BAD → 0.0 或 −1.0」，并对归因分做「组内 step-level 标准化」（PDF p. 19）。方法节是轨迹级、BAD 必为 −1；实验节允许 BAD 为 0，并改口成 step-level。原文没有统一。方差接近 0 的退化情形，实现会把对应信号中性化（PDF p. 19）。

### 机制三：两路分开标准化，终局分只加在最后一步

终局奖励 $R_{\mathrm{out}}$ 就是第 3.4 节裁判给的轨迹分，在训练组内单独标准化成 $\hat{r}^{\mathrm{out}}$（PDF p. 13，式 19），避免一路的尺度吞掉另一路。两路按下式合成（PDF p. 14，式 20）：

$$
\hat{r}_t=\alpha\cdot\hat{r}_t^{\mathrm{attr}}+\mathbf{1}_{t=T}\cdot\hat{r}^{\mathrm{out}}
$$

$\mathbf{1}_{t=T}$ 只在最后一步为 1，$\alpha\ge0$ 控制归因通道的比重。实验把终局权重 $\beta$ 固定为 1、只调 $\alpha$（PDF p. 19）；式 20 里并没有 $\beta$ 这个符号。

优势沿用 DeepSeekMath 那种不打折扣的未来奖励累加，$\gamma=1$（PDF p. 14，式 21）：

$$
A_t=\sum_{k=t}^{T}\hat{r}_k
$$

论文还建议把 $\alpha$ 当课程用：先大后小，先把过程打稳，再对准任务目标（PDF p. 14）。主消融取 $\alpha=0.1$（PDF p. 24）。

### 机制四：广播到 token，接回式 17

语言模型的策略梯度要 token 级优势：属于第 $t$ 步的每个 token 都用 $A_t$（PDF p. 14）。这些优势同时用于不带经验和带经验的两组 rollout，接进式 17，经验组仍保留选择性放宽（PDF p. 14）。

三条机制就在优化器入口汇合：Questioning 提供任务和终局分，Navigating 提供混合轨迹和裁剪规则，Attributing 提供逐步优势。优化器本身仍是 GRPO 风格，没有另发明一种策略梯度。

### 收益：两路缺一不可

Table 5 在 dev 集上报 avg@8 / best@8，全部只在 Self-Questioning 的合成题上训练（PDF p. 24）：

| 模型 | AppWorld | BFCL v3 | 平均 |
|---|---|---|---|

### 代价与边界

- **教师比学生强一个量级。** 归因用的是 Qwen-Max，策略是 7B / 14B；逐步标签的质量上限在这个教师，不在 GRPO。
- **过程通道只给方向。** GOOD / BAD 不是逐步的金标，$\gamma=1$ 的累加仍会让一次靠后的成功把前面每一步都加上同一份终局分；过程通道只能缓解，不能消除。
- **$\alpha$ 大了会讨好裁判。** Figure 16 是直接证据：过程监督能加速，也能把策略训成「迎合打分器」，必须留一路真正的任务成败把它钉住。
- **消融只在合成题上做。** Table 5 量的是「合成题的裁判终局分 + 逐步归因」，不是「官方环境奖励 + 逐步归因」（PDF p. 24）。

### 可迁移启发

稀疏终局分的补法有三种：学一个 PRM；把终局分均匀铺到每一步；或者像这里，**让一个会读轨迹的模型只输出方向，幅度交给标准化与另一路终局分**。方向比幅度好迁移；两路必须分开标准化，否则「过程通道」只是把终局分换个名字再加一遍。$\alpha$ 适合当旋钮，而且要放小。

## 框架与基础设施

第 6 节把三条机制收成一个可以跑的系统，强调三件事：从环境到权重更新的清晰数据流、面向多轮 Agent 的分层 rollout、以及用解耦的模块替换算法（PDF p. 14）。

### 分层 rollout：Agent 逻辑与运行时服务分开

rollout 分三层（PDF p. 15）：底层是环境服务与 LLM 服务，每个 worker 处理单步环境或单次推理，暴露标准接口；中层是 Rollout Worker，一条轨迹的基本采样单元；顶层是 Rollout Manager / 主控，调度多个 worker、定义终止条件、协调课程。设计原则是**把 Agent 逻辑与运行时服务解耦**：环境和 LLM 是独立服务，Agent 逻辑封在 Context Manager 里，同一套 rollout 设施可以挂 ReAct、planner–executor 或工具 Agent，不改服务层（PDF p. 15）。可替换的模块是 Task Manager、Rollout 与 Context Manager、Experience Manager、训练管线（PDF p. 15–16）。

**我们如何解释它。** 这里解耦的是**这套训练环内部**的「上下文怎么拼」和「环境 / LLM 怎么服务化」。你仍要在它的 Context Manager 里写 Agent 逻辑，不是把任意已有 Agent 程序原样接进来训练；后者是 Agent-Lightning 与 Polar 两篇的切面。

### Context Manager：一条可改的时间线，加一份只读快照

![四种上下文管理模板的时间线：Basic Causal 从任务起一路追加动作与观察，只留一条时间线；Reasoning-Augmented 每次动作前先写 think，每步各存一条时间线快照；Sliding Context Window 在窗口满时把旧内容抽成一条记忆消息，开新窗口从记忆接着写；Self-context Managing 在上下文超限时发出上下文操作提示，由策略自己对每条消息选择保留、丢弃或压缩，新时间线里被丢的消息变成 discarded、被压缩的变成 obs 2'。黄色块是计算策略损失的 LLM 动作 token，蓝色块是环境 token 或被掩码的 token，紫色块是记忆 token。引自原文 Figure 11（PDF p. 16）。](/reports/AgentEvolver/fig11-context-templates.png)

长程 RL 里，上下文怎么管是一笔隐藏成本。论文看到两种范式的对立（PDF p. 16）：因果的多步 rollout 时间一致性好、却不能改历史（引 Search-R1）；逐步独立的多轮 rollout 可以随意编辑、却很贵（引 GiGPO）。Context Manager 想同时保住因果训练的效率、在需要时改历史、并最终让 Agent 自己管理上下文。

它建在两个原语上（PDF p. 16–17）：**活时间线（Live Context Timeline，LCT）** 是可改的工作上下文；**时间线快照记录器（Timeline Snapshot Recorder，TSR）** 是只读缓冲，策略每生成一个动作就冻结一份 LCT。rollout 结束后 TSR 做时间线合并：删掉冗余子序列，对齐重叠段的损失掩码。在这之上定义四种上下文管理模板（PDF p. 17）：

| 模板 | 做法 | 论文给的定位 |
|---|---|---|
| Basic Causal | 严格因果追加，结束时只留最后一份快照 | 高效、确定，适合搜索式 RL；不能改历史，显存随长度线性涨 |
| Reasoning-Augmented | 每个动作前先写 `<think>` | 对没有推理能力的模型（文中举 Qwen2）用结构化提示加额外奖励；对已有推理能力的 Qwen3-14B 提升一致性与效率 |
| Sliding Context Window | 超过阈值就把旧内容压成一条记忆消息，开新窗口 | 保住局部因果，显存近似恒定，可以拉到任意长的局 |
| Self-Context Managing | 超限时让策略对每条消息选保留、删除或压缩（压缩交给外部摘要 LLM） | 细粒度管 token 预算，适合环境吐出大量无用文本的场景 |

四种模板共用 LCT–TSR，差别只在上下文演化的控制权从规则交给模型的程度（PDF p. 17）。

### Environment Service

环境做成独立服务，不再与训练循环焊死，可远程、可并发、可按需隔离（PDF p. 17）。接口按 Gym 风格覆盖初始化、取状态、逐步执行、评估与生命周期，参数可在运行时配置，也允许接 MCP 与用户自定义函数（PDF p. 17–18）。高并发靠 Ray actor 做轻量隔离，不依赖容器沙箱；预配置环境有 AppWorld、BFCL、WebShop、Crafter，对外统一走 HTTP（PDF p. 18）。**实验只用了 AppWorld 与 BFCL v3**，WebShop 和 Crafter 只出现在基础设施清单里。

## 限制、口径与只是初步的地方

论文没有单独的「局限」一节，下面这些要从摘要、实验范围和结论里读出来：

- **初步实验。** 摘要自己用了 preliminary（PDF p. 1）。规模是 7B / 14B、两套工具基准、8 张 A100；没有墙钟、没有裁判调用成本与 token 预算，也没有用同一套环去训 Figure 1 里的更大模型。
- **教师与学生不在一个量级。** 探索与合成用 Qwen-Plus，轨迹裁判用 Qwen3-235B-A22B，归因用 Qwen-Max。7B / 14B 的涨分里有多少来自「更强的模型在出题和打分」，没有单独消掉。
- **口径在表与表之间跳。** Table 1 是 test-normal、avg@8；Table 4 是 dev、avg@4；Table 5 的 AppWorld 是 dev；Figure 13b 纵轴是 Avg@8；Table 7 换成 Qwen3-14B 与 0–1 比例。
- **方法与实现有几处对不上。** 归因标准化方法节写轨迹级、实现节写 step-level；BAD 的赋值方法节为 −1、实现节允许 0；终局权重 $\beta$ 与「Eq. 23」在公式列表里不存在；式 17 的重要性比写成轨迹级，KL 项的 $\beta$ 是否就是 0.001 没有钉死；Table 6 的步数与 Figure 15 的百分比横轴对不上。
- **WebShop、Crafter、MCP、用户自定义函数只出现在基础设施。** 不能读成已经和三条机制一起跑通的实验。
- **没有与自进化或训练框架类工作做实验对照。** 前面「它改的是哪一层」那张表是我们的读法。

结论一节列了三个下一步，都还没有实验（PDF p. 26–27）：走向更复杂、更有真实价值的环境（多 API 企业工作流、安全关键工具链、交错的长程目标），并把环境与出题课程一起设计；接到更大的策略模型，看出题质量、导航冗余与归因精度是否随规模改善；把探索、经验抽象、自我归因和推理收进同一个模型，做「模型级」的自进化。

## 可迁移启发

1. **先问任务从哪来，再问优化器叫什么。** 这篇最大的一跳是 Self-Questioning，不是任何一个裁剪常数。
2. **参考解要来自环境，不要来自另一个模型的想象。** 先走一遍再出题，金标路径天然可执行；回放是最低成本的门禁。
3. **经验用自然语言写，检索当条件，训练时剥掉。** 随之而来的离策错配要专门修，只对变好的样本放宽裁剪。
4. **显式 ICL 与隐式 RL 是两个时间尺度。** 推理时塞经验能立刻涨分，天花板在检索；要把能力留在权重里，得让剥掉经验之后的策略继续拿到正优势。
5. **过程通道只给方向，幅度交给标准化与终局分。** 两路分开标准化，终局分只加在最后一步，$\alpha$ 放小。
6. **有真题时仍可加合成题扩边界，但给它降权。** 混合数据时合成题优势乘 0.5，是一条很具体的工程默认值：合成题管多样性，真题当锚。
7. **上下文模板是训练设计的一部分。** API 列表很长、相关的很少时，让模型学会丢弃与压缩，可能比再加一层滑动窗摘要更对症；Table 7 只是一个基座上的一张表，方向可记，数字别外推。

## 关键词回看

- **交互沙箱 $\mathcal{E}=(\mathcal{S},\mathcal{A},\mathcal{P})$**：有动态、没奖励、没目标的环境接口。
- **$p_{\mathrm{target}}$ / $p_{\mathrm{train}}$ / $p_{\mathrm{hybrid}}$**：未知的目标任务分布、合成的训练分布、两者的混合。
- **$F_{\mathrm{task}}$ / $F_{\mathrm{reward}}$**：从沙箱造任务、为任务造奖励的两个映射。
- **环境画像**：用实体、属性、操作写成的动作先验。
- **参考解**：探索阶段真实执行过的动作–观察序列，提出来当代理金标，并用回放验证。
- **LLM 裁判**：相关与重复检查、连续打分、对照参考解的轨迹级打分器。
- **经验（When to use / Content）**：可检索的自然语言教训。
- **经验混合 rollout / 经验剥离 / 选择性放宽**：一半带经验采样；训练前删掉经验 token；只对正优势的经验样本放宽裁剪上界。
- **逐步归因**：另一个 LLM 一次读完轨迹，给每步判 GOOD / BAD。
- **双通道合成奖励**：过程分与终局分分开标准化，终局分只加在最后一步，再不打折扣地累加成优势。
- **LCT / TSR / CMT**：可改的工作上下文、每次动作冻结的只读快照、四种上下文管理模板。
- **avg@k / best@k、TGC / SGC**：$k$ 次的平均与最好；任务目标完成与场景目标完成。
