# MemAgent：窗口锁在 8K，把长文读成一段可覆盖的记忆，再用多对话 RL 教它记什么

<!-- release-date: 2025-06-29 -->

> 本文依据本地 `papers/ByteDance/MemAgent.pdf`，即 **MemAgent: Reshaping Long-Context LLM with Multi-Conv RL-based Memory Agent**，arXiv:2507.02259v2、2026-07-29 提交，共 29 页，ICLR 2026 会议版。作者来自清华大学智能产业研究院（AIR）、ByteDance Seed，以及两家的联合实验室 SIA-Lab；通讯作者是 Mingxuan Wang 与 Hao Zhou（PDF p. 1）。页码均指这份 PDF 自身的页码。文中会区分三件事：**论文明确写了什么**、**我们怎么解释它**、**哪些是外部资料或本文推算**。

## 读前先把几个词说成人话

这篇论文不发明新的注意力，也不把窗口拉到百万。它问的是一件更朴素的事：一个只有 8K 窗口的模型，能不能像人读书那样边读边记笔记，最后只看笔记答题；以及这个「记笔记」的动作怎么训。

先把会反复出现的词说清楚：

- **上下文窗口（context window）**：模型一次前向能看见的 token 上限。普通注意力里每个 token 都要和窗口里其他 token 比一遍，计算大致随长度平方增长。
- **KV Cache（键值缓存）**：生成时留下的中间结果，窗口越长缓存越大。
- **块（chunk）**：把长文档按固定长度切开的一段。本文默认每块 5000 token（PDF p. 6）。
- **覆盖式记忆（overwrite memory）**：窗口里一段长度固定的普通 token。每读完一块，模型生成一段新记忆，**整段替换**旧的，而不是往后追加（PDF p. 3）。
- **GRPO（Group Relative Policy Optimization，组相对策略优化）**：同一道题采一组回答，用组内均值把奖励变成优势（advantage），不训练价值模型。**DAPO** 是在它上面修了几处默认陷阱的版本，本站 DAPO 一篇讲过。
- **RLVR（Reinforcement Learning from Verifiable Rewards，可验证奖励的强化学习）**：奖励只看最终答案对不对，用规则判定，不训练奖励模型。
- **RULER-HQA**：把 HotpotQA 的「金段落」（含答案的那几段）埋进大量同类维基干扰段落里，长度随干扰条目数可调。本文的训练数据和这项测试用**同一套合成方法**（PDF p. 6）。
- **NIAH（Needle in a Haystack，大海捞针）**：在一大堆无关文本里藏一条关键信息，看模型能否找回。信息密度极低。

## 一句话先说清

2025 年中，长上下文有三条老路：改位置编码再继续训、换稀疏或线性注意力、外挂压缩或记忆模块。论文认为它们各卡一处（PDF p. 2）：第一条仍是 $O(n^2)$，极长时又慢又掉点；第二条通常要从头训；第三条外推不稳，还要改生成流程。它给出的成功条件是三条同时成立：能处理无限长、外推不明显掉点、解码线性复杂度（PDF p. 2）。

MemAgent 的做法是让窗口本身不再随文档变长：

![MemAgent 把任意长的文档切成 5000 token 的块，每一轮只把问题、上一轮记忆和当前块放进 8K 窗口，生成的新记忆整段替换旧记忆，最后一轮只凭问题和记忆作答；对照的长上下文模型则要一个窗口装下整篇文档。](/reports/MemAgent/workflow-window-budget.svg)

图上每一行都是一次普通的 8K 生成。行与行之间不共享 KV Cache，传下去的只有那 1024 个记忆 token。位置编码不重标、不打补丁，每个窗口里的位置都是模型原本认识的位置（PDF p. 4）。

难点于是从「窗口够不够长」挪到「每次覆盖时留什么、扔什么」。这件事没有逐步标签，只有最后答对没答对。论文把 DAPO 扩成 **Multi-Conv DAPO**：一条样本不再是一段连续回答，而是若干轮互不拼接的对话；最终答案的对错变成一个优势，**原样发回这条样本的每一轮**（PDF p. 3–4）。

## 主要矛盾：看得见不等于记得住，记得住又没法直接训

论文要破的其实是两层矛盾。

第一层在推理侧。窗口拉长之后，模型「看得见」，但未必「用得上」。Table 1 里 Qwen2.5-Instruct-14B-1M 标称 1M 窗口，在 112K 还有 50.00，到 448K 只剩 8.59，896K 为 0（PDF p. 5）。论文的评语是：窗口扩到 1M，不等于会用超长上下文里的信息（PDF p. 7）。

第二层在训练侧。现有多轮 agent RL 的常见做法，是把工具返回和模型输出**拼成一条长对话**，或者用滑动窗口截一段（论文点名 Agent-R1、Search-R1 与 GiGPO，PDF p. 2）。MemAgent 第 $k$ 轮的合法输入是「问题 + 上一轮记忆 + 第 $k$ 块」。把一百轮拼成一条序列，窗口又回到和文档一样长；用滑窗截断，又丢掉了更早的覆盖决策。

两层叠在一起：

> 复杂度要线性，记忆就不能随文档变长；策略要可学，每一轮覆盖又必须能单独拿到梯度。而奖励只在最后一轮出现。

下面两个核心设计分别对付这两半。

## 核心设计一：定长覆盖记忆，因为追加会让窗口再长回去

### 旧问题

如果记忆是追加的，读到第一百块时笔记本身就比窗口长，只是把「文档长度」换成了「笔记长度」。外挂向量库能绕开窗口，但生成流程不再是标准解码器，论文认为这会伤兼容性和并行（PDF p. 2）。

### 新设计与工作机制

记忆就是窗口里的一段普通 token，长度固定为 $M$。读完块 $c_k$，模型生成 $m_k$，整段覆盖 $m_{k-1}$（PDF p. 3）。推理分成两个模块，各用一张提示词（PDF p. 17，Table 5）：

- **读文档模块**：告诉模型「这里有一个问题、一段可能含答案的文章、以及上一轮记忆」，要求它更新记忆，**既写入有助于答题的新信息，又保留旧记忆里所有相关细节**，在 `Updated memory:` 之后生成。
- **答题模块**：文档读完后，只给问题和最后那份记忆，要求把答案放进 `\boxed{}`。

提示词里这两个要求是一对矛盾：「保留所有相关细节」和「记忆长度固定」不可能总是同时满足。RL 要学的，正是在这句指令和 1024 token 的硬上限之间怎么取舍。

论文把「留什么」直接交给奖励：记住了后来用得上的事实就得分，把宝贵的 token 花在干扰项上就不得分（PDF p. 3–4）。

附录 C 的案例把这个过程写得很具体（PDF p. 20–21）。问题是：浪漫喜剧 *Big Stone Gap* 的导演住在纽约哪里？这是两跳题。

- 第 1 轮只看到一个也在纽约的制作团队 Ghost。模型把它**预先**记下，尽管后来证明它是干扰；
- 第 2 轮没有相关条目，记忆保持不变；
- 第 3 轮同时出现影片条目和导演 Adriana Trigiani 住在 Greenwich Village，记忆立刻改写并写出答案；
- 其后各轮记忆不再变，最后用来作答。

论文的判断是：这些行为不来自注意力结构，而是被 RL 强化出来的文本生成能力（PDF p. 21）。

### 收益

窗口固定，每块的计算是常数，整篇是 $O(N)$（PDF p. 3、p. 5）。附录 B 用 verl 里 Qwen2 模型的浮点运算估计器，把基线与 MemAgent 从 8K 画到 4M（PDF p. 19，Figure 10）。读图约值：基线在 1M 约 $0.14\times 10^{19}$、2M 约 $0.55\times 10^{19}$、4M 约 $2.1\times 10^{19}$，每翻一倍涨约 4 倍；MemAgent 在 4M 约 $0.03\times 10^{19}$，贴着横轴。估计口径是：MemAgent 每轮输入「问题 + 200 token 提示 + 5000 块 + 输出」，轮数取文档长度除以 5000 向上取整（PDF p. 19–20）。

这是估计器算出的 FLOPs，不是墙钟时间。

### 代价和边界

- **有损**。1024 token 装不下就被截断。附录 F.1 的失败正是关键句被挤掉（见后文）。
- **串行**。块与块必须一轮一轮跑。512K 的评测就超过 100 轮对话（PDF p. 8）；3.5M 按 5000 一块约 700 轮（本文推算）。FLOPs 线性，延迟按轮数累加。论文没有报墙钟时间，也没报推理用了多少卡。
- **记忆是文本**。好处是能人读、能检查，附录的案例和失败分析才写得出来；代价是每一轮都要真的把记忆生成一遍，1024 个输出 token 是实打实的解码开销。

### 可迁移启发

任何「必须记住、但状态不能无限长」的流水线（长日志摘要、多文档问答、代码仓问答），先问状态能不能做成**定长、可覆盖的文本**，而不是越拉越长的对话历史。定长把计算上限写死；代价是需要一个信号告诉模型哪句该被挤出去。MemAgent 用最终答案当这个信号。

## 核心设计二：Multi-Conv DAPO，因为拼起来的轨迹会把窗口再次撑爆

### 旧问题

GRPO 和 DAPO 的默认 rollout 里，一条样本是一段连续 token 序列，优势回到这段序列的每个 token 上。MemAgent 的一条样本却是一串**上下文彼此独立**的对话：第 3 轮写进记忆的那句话，只有到最后一轮答对时才知道它值不值。

### 新设计

![常规 GRPO 里一条样本是一段完整回答，奖励和优势只回到这一段；Multi-Conv DAPO 里一条样本是若干轮互不拼接的对话，只用最后答题轮算奖励，减去组内均值后的同一个优势发回这条样本的每一轮。](/reports/MemAgent/multiconv-dapo.svg)

图上的做法落成公式是（PDF p. 4，式 1）：

$$
\hat A_{i,j,t}=R_i-\operatorname{mean}\big(\{R_i\}_{i=1}^{G}\big)
$$

$i$ 是组内第几条样本，$j$ 是这条样本的第几轮对话，$t$ 是这一轮里的第几个 token。右边只有 $R_i$：优势与 $j$、$t$ 无关，整条样本共用一个数。不除标准差，论文写明是沿用 Dr. GRPO（PDF p. 4）。

奖励由规则判等，答对为 1、否则为 0（PDF p. 5，式 3）：

$$
R(\hat y,y)=\mathbf 1_{\mathrm{is\_equiv}(y,\hat y)}
$$

### 损失在算什么

先写单个 token 的裁剪项。重要性比 $r_{i,j,t}$ 是新旧策略在这个 token 上的概率比：

$$
r_{i,j,t}(\theta)=\frac{\pi_\theta(o_{i,j,t}\mid q,\,o_{i,j,<t})}{\pi_{\theta_{\mathrm{old}}}(o_{i,j,t}\mid q,\,o_{i,j,<t})}
$$

条件里只有问题和**这一轮**已生成的前缀，没有前几轮的块。裁剪项是 PPO 式的取小：

$$
\mathcal C_{i,j,t}=\min\Big(r_{i,j,t}\hat A_{i,j,t},\ \operatorname{clip}\big(r_{i,j,t},\,1-\varepsilon_{\mathrm{low}},\,1+\varepsilon_{\mathrm{high}}\big)\hat A_{i,j,t}\Big)
$$

整个目标把所有样本、所有轮、所有 token 加起来，再除以整组的 token 总数（PDF p. 5，式 2）：

$$
J(\theta)=\mathbb E\left[\frac{1}{\sum_{i=1}^{G}\sum_{j=1}^{n_i}|o_{i,j}|}\sum_{i=1}^{G}\sum_{j=1}^{n_i}\sum_{t=1}^{|o_{i,j}|}\Big(\mathcal C_{i,j,t}-\beta D_{\mathrm{KL}}(\pi_\theta\,\|\,\pi_{\mathrm{ref}})\Big)\right]
$$

$n_i$ 是第 $i$ 条样本的轮数，各条可以不同。期望下的采样条件写成 $\pi_{\theta_{\mathrm{old}}}(\cdot\mid q,o_{i,j-1})$：第 $j$ 轮依赖上一轮的输出，因为上一轮的输出就是新记忆。依赖走记忆，不走拼接后的长上下文。这就是论文说的 loss 从 `(group, token)` 扩成 `(group, conversation, token)`（PDF p. 4）。

和 DAPO 原文比，多出来的是 conversation 这一维，以及 KL 项回来了：附录写 KL 系数 $1\times 10^{-3}$、关掉熵损失（PDF p. 17）。DAPO 在长思维链里删掉 KL；这里为什么加回来，论文没解释。**我们如何解释它**：覆盖策略若离指令模型太远，记忆格式可能先崩，后面的轮次就没有可用的状态可传。这是推测，不是论文原话。

### 伪代码和公式对不上，以公式为准

附录 Algorithm 1（PDF p. 17）与正文式 2、Figure 3 有几处不一致：

| 位置 | Algorithm 1 写的 | 式 2 / Figure 3 写的 |
|---|---|---|
| 上下文 | $h_{g,t}\leftarrow h_{g,t-1}\Vert o_{g,t}$，把历史拼回去 | 各轮上下文独立 |
| 优化范围 | 重要性比只算最后一轮 $y_g$ | 所有轮、所有 token 都进 loss |
| KL | 从奖励里减掉 $\beta d_g$ | 在 token 级 loss 里 |
| 归一化 | `GroupNorm` | 明文写不除标准差 |

照伪代码复现会复现错。

### 代价和边界

- **信用分配很粗**。同一个优势发给所有轮：答错时每一次覆盖都被罚，答对时每一次都被鼓励，不管那一轮有没有贡献。论文没有做过程奖励，也没有分析哪一轮真正写入了关键事实。
- **batch 口径变了**。rollout batch 256、组大小 16；因为每条样本有多轮对话，实际 mini-batch 不等于 256 除以 16；采样 batch 与反传 batch 之比固定为 16，属于 off-policy 训练（PDF p. 17–18）。
- **没写的超参**。$\varepsilon_{\mathrm{low}}$、$\varepsilon_{\mathrm{high}}$ 的取值，DAPO 的动态采样与超长惩罚开不开，论文都没写。

### 可迁移启发

凡是状态不能拼回一条序列的工作流（覆盖式记忆、摘要后清空上下文、子 agent 交回结论），不要硬套「工具 token 掩码 + 单轨迹 GRPO」。先问：最终奖励能不能变成一个样本级优势、再均匀发回每个独立上下文？能，就只需在现有 GRPO / DAPO 实现上加一个 conversation 维，不必动模型结构。论文也说这套算法能优化任意有可验证结果的 agent 工作流（PDF p. 3）。

## 把自回归拆成读和写：一种看法，不是新架构

标准自回归把整段文本写成 $p(x_{1:N})=\prod_{n}p(x_n\mid x_{1:n-1})$，每个 token 都以全部历史为条件，这就是平方注意力的来源（PDF p. 5）。MemAgent 把无界历史换成定长记忆，引入隐变量序列 $m_{1:K-1}$，联合概率拆成（PDF p. 5，式 4）：

$$
p(x_{1:N})=\sum_{m_{1:K-1}}\prod_{k=1}^{K}\underbrace{p(c_k\mid m_{k-1})}_{\text{读}}\ \underbrace{p(m_k\mid c_k,m_{k-1})}_{\text{写}}
$$

初值 $m_0=\varnothing$。每步条件窗口是 $C+M$，步数约 $N/C$，乘起来是 $O(N)$。Figure 4（PDF p. 4）左边画成神经图灵机式的控制器加读写头，右边画成图模型。

两层要分开：实现里没有单独的读写头，读和写都是同一个 LLM 按 Table 5 的提示词生成文本；记忆也不是向量，就是 token。块是外部输入，式中的「读」项在训练里并不被优化，真正进 RL 的是写记忆和最后答题。论文据此说 RL 目标与长文本建模「内在统一」（PDF p. 6），这是一种视角，它不证明外推无损。

## 训练 recipe：两阶段课程，窗口故意锁在 8K

基座是 Qwen2.5-7B-Instruct 与 Qwen2.5-14B-Instruct，框架是在 verl 上实现的独立上下文多轮对话（PDF p. 6）。verl 即本站 HybridFlow 一篇讲的那套框架。

| 项目 | 取值（PDF p. 6、p. 17–18） |
|---|---|
| 窗口分配 | 问题 1024 + 块 5000 + 记忆 1024 + 输出 1024，余量给对话模板，合计 8K |
| 算法 | DAPO，KL 系数 $1\times 10^{-3}$，关掉熵损失 |
| 优化器 | AdamW，恒定学习率 $1\times 10^{-6}$，前 20 步线性预热 |
| rollout | batch 256，组大小 16，采样与反传 batch 比 16 |
| 阶段切换 | Stage I 完全收敛后进 Stage II，约 400 步 |

两阶段数据（PDF p. 18）：

- **Stage I**：32,768 条合成 QA，每条约 32K token。按 RULER 的方法，把 HotpotQA 金段落埋进同一数据集采样的干扰内容里，每条约 200 篇条目、约 28K token。先从 HotpotQA 训练集取 80,000 条，滤掉 Qwen2.5-7B-Base 或 Instruct **不给任何上下文**时 Best-of-2 就全对的题（这些答案多半已在参数里，测不出记忆），约滤掉一半，取前 32,768 条。
- **Stage II**：2,560 条，最长 60K token，来自 DocQA-RL-1.6K 的困难长文 QA，再混入第一阶段数据。两者比例没写。

验证集从 HotpotQA 验证集合成 128 条；外推测试用同一管道，维基条目数从 50 到 6400，对应约 7K 到 3.5M token（PDF p. 18）。

所以「8K」是窗口，不是训练文档长度。引言和结论说「在 60K 长度上训练」（PDF p. 3、p. 10），指 Stage II 的上限。

评测用 `sub_em`：答案包含标准答案的全部要素才算对，多部分答案按命中比例给分；比对前去冠词、忽略大小写（PDF p. 18）。附录写的抽取格式是 `the answer is ANSWER.`，与提示词里的 `\boxed{}` 并不一致，论文没交代评测时用哪一个。基线的生成配置在 Table 6：128K 窗口的模型输入 120,000、输出 10,000；Qwen2.5-Instruct-1M 系列输入 990,000、输出 10,000（PDF p. 18）。

## 实验：什么被证明了，什么没有

四类评测测的是三种不同的能力，要分开读：RULER-HQA 是同分布拉长，NIAH 是低密度找针，LongBench-QA 与 LongBench-SUM 是短而密的真实阅读（PDF p. 6–7）。

### RULER-HQA：长度外推成立，但是同分布

Table 1 已在开头。必须记住这项测试和 Stage I **同一套合成方法**（PDF p. 6），只是把干扰条目从 50 堆到 6400。它证明「同分布下的长度外推」，不证明「任意长文档都能答」。3.5M 这个头条数字建立在这条测试上。

基线各有各的崩法（PDF p. 7）：DeepSeek-R1-Distill 系列掉得最快；QwenLong-L1 在自己的训练长度内还行，之后大跌；Qwen2.5-Instruct-1M 撑到 112K，896K 归零。

### RL 到底贡献了什么：只套工作流，推得动长度，推不动理解

| 设定 | RULER-HQA 7K | 112K | 896K | LongBench-QA 平均 |
|---|---:|---:|---:|---:|
| Qwen2.5-Instruct-14B | 75.00 | 44.53 | 2.34 | 42.0 |
| MemAgent-14B，不训练 | 约 64 | 约 42 | 约 24 | 约 40 |
| RL-MemAgent-14B | 80.47 | 81.25 | 75.78 | 51.0 |
| Qwen2.5-Instruct-7B | 52.34 | 32.81 | 1.56 | 34.7 |
| MemAgent-7B，不训练 | 约 59 | 约 36 | 约 37 | 约 38 |
| RL-MemAgent-7B | 81.25 | 79.69 | 74.22 | 48.2 |

「约」字各格是从 Figure 6（RULER-HQA 折线，PDF p. 8）和 Figure 7（LongBench-QA 柱状，PDF p. 8）读出的约值，其余来自 Table 1 与 Table 3（PDF p. 5–6）。

表要这样读。只套工作流、不训练，在 896K 这种窗口外的长度上，已经比把文档截断塞进窗口的指令模型强得多（约 24 与约 37 对 2.34 与 1.56）；但在短文档上反而更差，14B 在 7K 从 75.00 掉到约 64。LongBench-QA 上，不训练的 14B 平均约 40，还低于指令模型本身的 42.0；7B 只高约 3 分。论文的说法是「只有微弱甚至负向的提升」（PDF p. 8）。加上 RL 之后，两项才一起抬起来。

**我们如何解释它**：工作流解决的是「塞得下」，RL 解决的是「记得对」。前者靠结构就能拿到，后者只在训练之后出现，而且在分布一变时最明显。

### NIAH：512K 过 95%，但它是低密度找针

| 模型（NIAH 512K，%） | Level 1 | Level 2 | Level 3 | 三级平均 |
|---|---:|---:|---:|---:|
| RL-MemAgent-14B | 100.00 | 94.53 | 100.00 | 98.18 |
| RL-MemAgent-7B | 100.00 | 92.97 | 96.88 | 96.62 |
| MemAgent-32B，不训练 | 96.88 | 60.16 | 58.59 | 71.88 |
| MemAgent-14B，不训练 | 88.28 | 17.19 | 14.84 | 40.10 |
| MemAgent-7B，不训练 | 92.19 | 89.06 | 84.38 | 88.54 |
| Qwen2.5-Instruct-14B-1M | 100.00 | 86.72 | 92.97 | 93.23 |
| Qwen2.5-Instruct-7B-1M | 100.00 | 61.72 | 58.59 | 73.44 |
| QwenLong-L1-32B | 21.88 | 14.84 | 15.62 | 17.45 |

这是 Figure 5 热力图（PDF p. 7）最右一列的节选，原图还有 8K–256K 各列和其余基线。三级来自 RULER 的 `niah_single_1/2/3`：Level 1 的干草堆是重复句子、针是七位数字；Level 2 换成长文章；Level 3 的针改成 36 字符 UUID。原版 RULER 的答案前缀与工作流不兼容，被去掉了（PDF p. 18–19）。

正文「512K 上损失不到 5%」（PDF p. 8）对应的是这张平均图：14B 从 8K 的 99.74 到 98.18，7B 从 100.00 到 96.62。它不是 3.5M QA 的跌幅，也不是整个 RULER 套件。

一处值得单独看：不训练时，7B 的 88.54 远高于 14B 的 40.10 和 32B 的 71.88。更大的模型套上覆盖工作流并不更稳，RL 之后 14B 才反超。论文没有讨论这个倒置。

### LongBench-QA：比 32B 推理模型高一点，不是全面领先

Table 3（PDF p. 6）平均分：RL-MemAgent-14B 51.0，QwenLong-L1-32B 50.7，DS-Distill-Qwen-32B 49.0，RL-MemAgent-7B 48.2。14B 只比 32B 长推理模型高 0.3 分；2Wiki 上 MemAgent-14B 的 79.0 低于 DS-Distill-Qwen-32B 与 DS-Distill-Qwen-14B 的 83.5；Qasper 上 7B 的 29.0 反而高于 14B 的 26.0。

论文据此说这组任务考的是「更深的理解而不只是检索」，并认为 RL 学到的记忆能力可以泛化（PDF p. 7）。泛化存在，幅度远没有 RULER-HQA 那么戏剧性。

### LongBench-SUM：训练信号全是 QA，摘要也能涨一点

Table 2（PDF p. 6）用 GovReport 与 QMSum，报 ROUGE-1/2/L 的**召回率**，不是常见的 F1。论文说 RL-MemAgent「几乎在所有指标上 SOTA」（PDF p. 8）。逐格看：14B 在两个数据集的 ROUGE-1、ROUGE-L 与平均上都是第一；两个数据集的 ROUGE-2 第一都是 7B（12.37 与 14.41）；7B 的 GovReport ROUGE-1 是 30.28，低于 Qwen2.5-Instruct-7B 的 30.91。

幅度不大：GovReport 平均从 Qwen2.5-Instruct-14B 的 19.04 到 21.80。这组实验的作用是说明学到的不完全是 HotpotQA 的答题格式。

### 记忆长度：1024 是折中

默认 1024 记忆 + 5000 块，是为了在 8192 以内取一个合理压缩比，依据是初步验证（PDF p. 8）。Figure 8（PDF p. 9）的 NIAH 上，256 到 4096 的差别都不大，512K 平均最低的 14B-m256 也有 93.75。Figure 9（PDF p. 9）的 LongBench 平均上，两条线都在 1024 处最高，256 最低。

附录 D.1 把「记忆 + 块」总长固定、线性改记忆大小（PDF p. 22，Table 8–9）：NIAH 各档都在 94–100 之间；LongBench-QA 上 14B 仍是 `m1024-c5000` 的 51.0 最高，`m4096-c1928` 只有 48.5。更长记忆、更短块，意味着轮数更多、覆盖更频繁，并不自动更好。

读 Figure 9 要小心：它在 1024 处的 HQA、MuSiQue 与平均（14B 读图约 70.5、47.6、47.5）低于 Table 3 同一配置的 73.0、52.0、51.0，而 2Wiki、NQA、Qasper 三项与 Table 3 一致。两者可能不是同一次评测，论文没有说明。

### 位置探针：没有灾难性的位置偏好

论文把两组关键信息放在文档的不同相对位置（PDF p. 9–10，Table 4）：首尾 $(0\%,100\%)$ 最考验「前面记的会不会被覆盖掉」，中间 $(40\%,60\%)$ 最考验「中间迷失」。表中数字是相对随机打乱的差值。

五种设置的平均差值，14B 在 $-0.11$ 到 $+2.79$ 之间，7B 在 $+0.56$ 到 $+2.35$ 之间，没有哪一种崩掉。论文的假说是端到端优化会逼模型追踪关键信息（PDF p. 9）。探针支持「没有系统性的位置偏好」，不支持「覆盖从不丢信息」，附录 F 就是反例。

表里有一处笔误：14B 随机行的平均写成 75.78，与 Table 1 的 896K 分数相同；对 7K–448K 七列求平均应约为 80.91（本文算）。7B 随机行的 79.58 正是七列均值。差值行不受影响。

### 和 RAG、Mem0 比：检索基线不弱

附录 D.2 拉来 Mem0 与多组 RAG（PDF p. 22–23）。Mem0 用 GPT-5.1 加 `text-embedding-3-large`，按 5000 token 切块建记忆、检索 top 30；RAG 同样用这个嵌入模型，扫了多种块长与 top-$K$。

Table 10（RULER-HQA，每个维基条目一块）上，Qwen2.5-14B 加 RAG、$K=8$，7K 为 78.12，3.5M 仍有 64.84，已远强于所有整篇塞进窗口的基线；RL-MemAgent-14B 是 80.47 与 71.09。检索在「金段落埋在同类维基里」的设定下本来就强，差距主要在极长处拉开。

Table 11（LongBench-QA，定长切块）的平均列有一处计算错误：RAG 各行的 AVG 都等于五项之和除以 6，而 MemAgent 行是除以 5（本文逐行验算）。按五项平均重算，14B 加 RAG 最好一组（块 2048、$K=8$）是 47.3，不是表中的 39.42；7B 最好一组（块 1024、$K=6$）是 36.7，不是 30.58。所以 14B 上端到端记忆相对 RAG 的真实优势约 3.7 分，远没有表面上的 11.6 分；7B 上仍有约 11.5 分。

Mem0 的逐长度分数没有印进任何表里，论文只写 MemAgent 胜过这些方法（PDF p. 22）。

## 失败模式：覆盖会丢，多跳会看走眼，先入为主改不回来

附录 F 给了三条失败轨迹（PDF p. 24–29）。它们比主表更能说明覆盖记忆的边界。

**信息被挤掉。** 问 Sachin Warrier 做软件工程师的那家公司总部在哪，答案是孟买。模型早期记了大量无关公司（第 60 轮）；第 289 轮看到 TCS 总部在孟买并记下，第 290 轮却把它追加在记忆末尾，因空间不够被截断；第 317 轮它主动做了一次摘要腾地方，记忆里却留下了「总部在 Faridabad」这样的错误残留；第 433 轮看到 Warrier 在 TCS 的科钦分部工作过，于是用错误的总部作答（PDF p. 24–26）。这不是没看到，是定长覆盖的物理限制：写得下，下一轮未必留得住。

**缺了前提，关键信息没被认出来。** 问 *The Hard Easy* 那一集客串演员的弟弟是谁，答案是 Bill Murray。第 143 轮已经出现 Brian Doyle-Murray 是 Bill Murray 的哥哥，但模型还没见过这一集的条目，判为无关没存；第 215 轮看到客串名单时，记忆里只剩赛车手 Truex 兄弟的「弟弟」（PDF p. 27）。多跳题里，第一跳在第二跳出现之前看起来就像干扰项。附录 C 里预存 Ghost 的行为只是有时发生，没有保证。

**首因偏差。** 问 Brown State Fishing Lake 所在的 country 有多少居民。英语 country 既可指国家也可指乡郡，答案是 Brown County 的 9,984。模型第 1 轮就认定问的是美国；第 617 轮把美国人口约 3.27 亿写进记忆；第 728 轮已经记下 Brown County 人口 9,984，仍回答美国人口（PDF p. 28–29）。早期写进记忆的判断，会变成后面各轮都沿用的信念。

三条合起来，把「近乎无损外推」的适用范围画了出来：低密度找针几乎不触发它们；同分布长 QA 触发得少；真正的多跳、歧义和超长干扰堆叠，仍会在覆盖的缝里失败。

## 限制、边界，以及论文没写的

论文写清了训练框架、两阶段数据、默认 8K 切分、主实验和失败案例。下面这些没写，或自相矛盾：

- **没写的**：$\varepsilon_{\mathrm{low}}$ 与 $\varepsilon_{\mathrm{high}}$；动态采样与超长惩罚是否沿用 DAPO；GPU 数、墙钟时间与训练成本；推理延迟；Stage II 中两类数据的比例；评测到底解析 `\boxed{}` 还是 `the answer is`；Mem0 的具体分数；QA、摘要与 NIAH 之外的任务。
- **正文内部不一致**：摘要「不到 10%」、引言「without performance drop」与 Table 1 实际约 9.4 个百分点；Algorithm 1 与式 2 在拼接、优化范围、KL 位置和归一化四处不一致；Table 4 的 14B 平均误贴；Table 11 的 RAG 平均除错了数；Figure 9 与 Table 3 在三项上对不上；Table 3 的模型名写成 MemAgent，未加 RL 前缀，但数字对得上 RL 版本。
- **口径边界**：3.5M 是同一套合成题堆干扰条目；512K 的 95% 是低密度找针；LongBench-QA 相对 32B 推理模型只多 0.3 分。

## 可迁移启发

1. **先问状态要不要增长。** 任务允许有损时，定长覆盖比拉长窗口便宜：计算上限写死，位置外推和 KV 压缩都可以先不碰。代价是信息会被挤出，要准备好附录 F.1 那种截断。
2. **奖励要能回到每一次覆盖。** 中间没有「好记忆」的标签，就用最终对错当所有轮共用的优势。前提是最终对错和中间记忆质量足够相关；低密度检索最符合，多跳密文本弱一些，开放生成没有可验证结果时这条路先断。
3. **独立上下文是训练接口问题。** 推理时本来就是一轮一轮跑，难的是让 RL 系统承认「一条样本 = 一袋互不拼接的对话」。任何会重置上下文的 agent 都会碰到同一个接口。
4. **先上工作流，再决定训不训。** 不训练的覆盖工作流在超长 RULER-HQA 上已经大幅好于截断，在 LongBench-QA 上却几乎没用。先用工作流测一遍，比一上来就训几百步便宜；但分布越像训练合成数据，工作流的红利越容易被高估。
5. **评测口径决定头条数字。** 同分布拉长、低密度找针、短密阅读是三种能力。自己做长上下文系统时三类都要各看一眼，还要自己验算表里的平均。

和同一条线上的几篇放在一起记：DAPO 一篇修的是单轮 RL 的默认陷阱；ReTool 一篇让 rollout 里能插入真实代码执行；MemAgent 让 rollout 里每一轮的上下文彼此独立、只靠一段可覆盖的文本相连。三者都不改基座的注意力。

## 关键词回看

- **覆盖式记忆**：定长的普通 token，每读一块整段替换，不追加。
- **独立上下文多轮对话**：一条样本拆成多轮生成，每轮输入不能由拼接前序得到，状态只经记忆传递。
- **Multi-Conv DAPO**：DAPO 的 token 级裁剪损失加一个 conversation 维；优势来自最终答案，发回所有轮次。
- **RLVR**：只用规则可验证的最终结果当奖励。
- **Dr. GRPO 式优势**：只减组内均值，不除标准差。
- **RULER-HQA**：金段落埋进同类维基干扰；3.5M 头条数字的来源，与训练同分布。
- **NIAH 三级**：数字针配重复句子、数字针配长文章、UUID 针配长文章；512K 的 95% 指三级平均。
- **sub_em**：答案包含标准答案全部要素才算对，多部分按比例给分。
- **两阶段课程**：Stage I 32K 合成 QA 约 400 步，Stage II 60K 困难长文 QA。
