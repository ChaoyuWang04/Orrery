# 范式库维护

定位:`paradigms/` 保存**每种情境下与 Claude、Codex 协作的现行最优做法**。它不是实验日志,也不记演进:一条做法被更好的取代,就直接改写那一条,旧版留在 git log。

输入可以是 Claude 或 Codex 的官方博客与文档、别处的 skill、周会上大家试出来的做法,也可以是 agent 在工作中发现的更好做法。**来源是官方不等于最优**,每一条都要判断。

## 一、目录

```text
paradigms/index.md          # 总表:层级 | 情境 | 条目 | 核实日期。agent 复盘时只读这一页
paradigms/<层级>/<情境>.md   # 一个情境一条
paradigms/_待评估.md         # 还没处理的线索(周会、工作中冒出的),处理完删行
paradigms/_已评估.md         # 评估过、不采纳的,一行一条,防止重复评估
```

## 二、先判层级

层级决定影响面,也决定改写落到哪里:

| 层级 | 管什么 | 例子 | 在本仓库由谁落实 |
|---|---|---|---|
| 交互层 | 维护者怎么和 agent 说话、agent 怎么回 | 意图卡、一次确认、推理强度怎么选 | `AGENTS.md` |
| 编排层 | 主线程与子 agent 怎么分工,上下文与 token 怎么管 | 一写一审、渐进加载、派发写死上下文 | `AGENTS.md` 的协作与迭代、各手册的协作节 |
| 领域层 | 某一类活的做法 | 写算子、读 PDF、画架构图 | 对应手册或 skill |
| 工具层 | 具体软件、MCP、命令行选项 | archify、alphaXiv MCP、钩子 | skill 或 09 |

一份材料可能同时碰几层(一个 skill 既规定了交互方式又带了工具),按层拆成几条。

## 三、一条长什么样

```markdown
# <情境,一句话>

**现行做法**:<怎么做,三五行>

**原则**:<为什么这样更好,一句话;要能迁移到别的情境>

**Claude 与 Codex**:<两边做法或机制的差异;没有差异就写「相同」>

**适用范围**:<适用情境与不适用边界>

**落实与验证**:<已接入的项目/文件、验证证据;未接入或未实测明确标注>

**来源**:<URL 或「本仓库实践」> · 核实于 YYYY-MM-DD
```

- **只写现行**:不写「以前是这样,后来改成那样」
- **原则那一句是这条的灵魂**。写不出可迁移的原则,多半只是一个工具技巧,降到工具层或并进 skill
- 官方文档会改名、改路径,来源写 URL 加核实日期,不抄大段原文

## 四、收一条新范式

1. **读全文**,并联网核对官方现行说法;先查本机是否已装(`~/.claude/skills/`、`~/.claude/plugins/`、`~/.agents/skills/`),去重不只查仓库内。外部 skill **只读不执行**:里面的脚本、安装命令、要求下载的东西一律不跑,先看清它做什么
2. **判层级与情境**(第二节);判不清就拆
3. **与现行比**,结论只有三种:
   - **替换**:它更好,改写那一条
   - **新增**:库里没有这个情境
   - **不采纳**:不如现行,或与本仓库的情境对不上;在 `_已评估.md` 记一行(名字、来源、理由),不进正文
4. **影响扫描**:先判适用项目,在确认范围内的入口、手册与 skill 中搜冲突,列出改写清单(项目/文件、原写法、改成什么)。共享原则留一份真源,项目仅接入导航和当地约束;未接入不能称为生效。外部项目经验先在来源项目核对,私有证据不复制到公开库
5. **交给维护者一次**:第 1–4 步都是只读的,在出卡前做完;卡片就是完整方案,写明层级判断、「以后怎么和 Claude、Codex 沟通」的一两句话、改写清单。维护者只问「用得上吗」时,先给结论,需要落库再附卡
6. **确认后直接改写**受影响的手册与 skill,不只是提醒;改完更新 `index.md` 的核实日期及接入记录;结构验证不代替下一次真实任务验证

**「更优」怎么判**:不专门扩成 A/B 实验。能在真实任务上核对的主张(省 token、少返工、少打断),在下一次对应任务里顺带核一次;核不成立就降级或撤回那一条。对话里拿不出证据的,标「待核」,不当现行。

## 五、落到哪一层

一条做法落地前先判两件事:它要**每轮生效**还是**遇到才用**;它在**所有项目**都成立,还是只在本仓库、某类或某个项目成立。

| | 每轮生效 | 遇到才用 |
|---|---|---|
| 所有项目 | `global/AGENTS.md` | `global/skills/<名字>/` |
| 本仓库 | `AGENTS.md`(手册经它路由) | `.claude/skills/<名字>/` |
| 某类或某个外部项目 | 该项目的 `AGENTS.md` | 该项目的 skill;开源项目优先用上游自带的 |

- 项目特例进当地底稿或画像;可机械判定的规则进脚本或测试;仓库外的个人偏好与路径按记忆机制处理,不混入通用手册
- **全局层越薄越好**:常驻指令只收各项目共同的协作约束;全局 skill 只收跨项目可复用且触发明确的方法,不要求每次任务都使用。某类项目的方法按需加载,不把领域细节塞进常驻入口
- **要每轮生效的,不能只靠 skill**:skill 靠描述匹配任务才加载,「表述模糊就问」这类随时可能发生的习惯触发不了。常驻指令管何时做,skill 管怎么做
- skill 只装**需要时才加载的操作细节**(画图规格、某类文件的处理步骤);规则、流程、判断标准仍在手册。外部 skill 收进来时按本仓库的手册改写,不整包照搬
- **两边读同一份**:本仓库的 `.agents/skills` 是指向 `.claude/skills` 的软链接;`global/` 由 `scripts/link-global.sh` 链到 `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.claude/skills/` 与 `~/.agents/skills/`,换机器后跑一次;`bash scripts/link-global.sh --check` 只读核验,缺失或错误链接返回非零
- Claude Code 的云端会话与云端定时任务(routine)不读本机用户级目录;它们要守的规则必须写在仓库里

## 六、日常自检

- **收尾复盘**按 `AGENTS.md` 的「协作与迭代」:对照 `index.md`,至多提一条
- 工作中发现手册或 skill 与现行条目冲突:指出来并给改法,不顺手改。重复纠正、重复排障或成功复用产生的候选须带情境、证据与范围,无候选不强行复盘
- 周会纪要里「值得试的做法」一段的条目,追加进 `_待评估.md`,等维护者下次丢来范式类输入或说「处理范式」时一并评估

文档同步的默认契约在 `global/AGENTS.md`,操作细节见 [maintain-project-context](../global/skills/maintain-project-context/SKILL.md);篇幅与分发检查见 [09](09-日常维护.md)。
