# 维护项目上下文

让下一次工作读到足够且当前的信息。沿用项目现有文档职责,不新建平行台账;文档更新授权不扩大到部署、清理或其他仓库。

## 定位写入位置

先读项目入口和与任务有关的权威文档,检查 Git 状态及目标段落;并发修改前重读。只调查本次变化影响的内容。

| 信息 | 落点与动作 |
|---|---|
| 进度、阻塞与下一步 | 改写现有任务队列,只留未完成部分;完成证据进入原有任务记录 |
| 现行结论、操作或边界变化 | 替换权威手册或决策中的旧说法,保留必要理由和证据链接 |
| 命令、版本、指标、失败与恢复过程 | 写进已有实验记录或发布回执;缺少承载位置且确需追溯时才建记录 |
| 可复用的方法 | 优先改已有流程;具体命令留项目,可迁移原则提为候选 |
| 对话复述、无影响的成功操作 | 不落长期文档;没有实质变化时无需制造 diff |

历史记录保留当时语境,纠错注明依据;不能把历史改得仿佛一直正确。科学判据、原始数据口径、恢复条件与失败证据不得因压缩而丢失。

## 定点更新与验收

1. 写最小的完整变化:结论、必要前提/边界、证据入口。重复事实改为指向唯一权威位置;被取代内容同批更新。
2. 检查 diff:每段是否改变下次行动,是否重复、过时或缺证据,是否仍足够执行。保留无关修改;不要因文件变长就归档或删除材料。
3. 运行项目要求的验证;有上下文检查器时查看提示。篇幅与重复提示须人工判断,不换措辞或挤长行来躲检查。
4. 简短报告改了哪个权威位置、还有什么未核实。无需每次附文档清单或复盘长文。

## 经验候选

只有重复纠正、重复排障或成功复用出现时才检查是否值得提炼,至多 1 条:情境、可迁移做法、证据、适用范围。已授权的项目内经验更新直接完成;共享规则变更超出范围时只提建议。

先在来源项目核对,再向共享范式层提交候选。宿主地址、权限和一次性补丁不升级为通用规则;私有证据不能复制到公开库。后续真实任务核不成立就修正或撤回;没有测量不声称节省了 token。
